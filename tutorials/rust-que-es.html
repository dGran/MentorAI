¿Qué es Rust y para qué proyectos?

Por qué existe Rust, qué problema resuelve que C++ no pudo, para qué proyectos encaja (y para cuáles no), y una tabla comparativa honesta con Go y PHP.

El origen: memoria sin garbage collector

En los años 2000, Mozilla tenía un problema: Firefox estaba escrito en C++ y los bugs de memoria (use-after-free, buffer overflows, data races) consumían una fracción desproporcionada del tiempo de ingeniería. El GC de Java resolvía esos bugs pero introducía pausas inaceptables para un navegador.

Graydon Hoare empezó Rust en 2006 con una hipótesis: se puede tener seguridad de memoria sin GC si el compilador verifica la propiedad y el ciclo de vida de cada valor. Mozilla adoptó el proyecto, y en 2015 Rust llegó a su primera versión estable.

Dato clave: Los componentes de Firefox reescritos en Rust (CSS layout, renderizado MP4) eliminaron clases enteras de vulnerabilidades CVE que afectaban a las versiones en C++.

Qué garantiza Rust

Rust ofrece tres garantías verificadas en tiempo de compilación, sin coste en runtime:

  • Sin use-after-free: el compilador rastrea quién "posee" cada valor y lo destruye exactamente cuando ya nadie lo usa.
  • Sin data races: como mucho un escritor O muchos lectores simultáneos, nunca los dos a la vez. El tipo garantiza esto, no el programador.
  • Sin null pointer dereferences: no existe null. Cualquier valor opcional es Option<T> y el compilador exige que lo trates.

El precio es una curva de aprendizaje real. El compilador rechaza código válido en todos los demás lenguajes porque aplica reglas que esos lenguajes no tienen. La frustración inicial es casi universal; la claridad que viene después también.

Para qué proyectos es ideal

  • Sistemas y kernel: drivers, sistemas de archivos, OS (Linux ya acepta Rust). Rendimiento de C, seguridad que C no tiene.
  • WebAssembly: Rust compila a WASM mejor que ningún otro lenguaje. Figma, Cloudflare Workers y npm usan Rust aquí.
  • CLI de alto rendimiento: ripgrep, fd, bat están escritos en Rust y son entre 2× y 10× más rápidos que sus equivalentes en C/Go.
  • Servicios backend con latencia crítica: cuando P99 importa más que velocidad de desarrollo. Discord migró algunos servicios de Go a Rust por las pausas del GC.
  • Herramientas de build y tooling: el compilador de JavaScript SWC, el bundler Turbopack y Biome están en Rust.
  • Blockchain y criptografía: Solana, NEAR y gran parte del ecosistema Web3 eligen Rust.

Para qué no encaja (o no todavía)

  • APIs CRUD estándar: donde PHP o Go te dan el mismo resultado 5× más rápido de desarrollar.
  • Scripting y automatización: Python o bash ganan aquí sin discusión.
  • Proyectos donde el tiempo al mercado manda: el ownership tarda semanas en "hacer clic". Si tienes que entregar en tres semanas, no es el momento.
  • Equipos sin tiempo de adopción: Rust requiere inversión de formación que no todos los equipos pueden permitirse ahora.
Regla práctica: elige Rust cuando el rendimiento, la seguridad de memoria o el control fino sean requisitos reales, no aspiraciones. Para el resto, Go o PHP son mejores elecciones pragmáticas.

Go y Rust no compiten directamente: Go optimiza el tiempo de los desarrolladores, Rust optimiza el tiempo de la máquina. Para un backend developer de PHP, Go es el siguiente paso natural; Rust es el paso después, cuando ya dominas Go o cuando el proyecto lo exige.

Resumen

  • Rust nació para resolver bugs de memoria en C++ sin sacrificar rendimiento ni introducir GC.
  • Sus garantías (sin use-after-free, sin data races, sin null) son verificadas por el compilador, no por el programador.
  • Encaja bien en sistemas, CLI de alto rendimiento, WASM, y servicios con latencia crítica.
  • No es la elección obvia para CRUD estándar o cuando el tiempo al mercado es prioritario.
  • Frente a Go: Go optimiza al desarrollador, Rust optimiza a la máquina. Son herramientas distintas para contextos distintos.
