El entorno de Claude Code: carpetas, comandos y atajos

Rules, skills, subagentes, hooks y servidores MCP acaban siendo ficheros en carpetas concretas, y la sesión se maneja con comandos que empiezan por barra. Esta lección es el mapa de referencia: dónde va cada cosa, qué se comparte con el equipo y qué comando usar en cada momento.

Claude Code organiza su configuración en dos niveles: usuario (~/.claude/, para todos tus proyectos) y proyecto (.claude/ dentro del repo, compartido con el equipo). Saber qué va en cada uno evita las dos trampas típicas: imponer tus preferencias al equipo y dejar fuera de Git lo que todos necesitan.

Nivel proyecto #

texto · estructura de un proyecto 
mi-proyecto/
├── CLAUDE.md                 # instrucciones del proyecto (o .claude/CLAUDE.md)
├── CLAUDE.local.md           # tus instrucciones personales, fuera de Git
├── AGENTS.md                 # estándar multi-harness; Claude lo lee si no hay CLAUDE.md
├── .mcp.json                 # servidores MCP compartidos con el equipo
├── src/
│   └── Pedidos/
│       └── CLAUDE.md         # reglas de esa carpeta, se cargan al trabajar en ella
└── .claude/
    ├── settings.json         # permisos, hooks, configuración compartida
    ├── settings.local.json   # tu configuración personal, fuera de Git
    ├── rules/                # reglas modulares, opcionalmente con paths
    │   ├── arquitectura.md
    │   ├── controllers.md
    │   └── testing.md
    ├── skills/               # skills del proyecto
    │   └── nueva-migracion/
    │       ├── SKILL.md
    │       ├── scripts/
    │       └── references/
    ├── agents/               # definiciones de subagentes
    │   └── qa.md
    └── commands/             # comandos personalizados (/nombre)

Nivel usuario #

texto · ~/.claude/ 
~/.claude/
├── CLAUDE.md                 # tus instrucciones globales (estilo, principios)
├── settings.json             # tu configuración global
├── rules/                    # tus reglas globales
├── skills/                   # tus skills personales (p. ej. commits)
├── agents/                   # tus subagentes personales
└── commands/                 # tus comandos personales

Los servidores MCP a nivel de usuario se guardan en ~/.claude.json, fuera de la carpeta.

Qué va en Git y qué no #

Archivo¿A Git?Para qué
CLAUDE.md, .claude/rules/SíConvenciones del equipo
.claude/skills/, .claude/agents/, .claude/commands/SíProcedimientos y agentes compartidos
.claude/settings.json, .mcp.jsonSíPermisos y MCP comunes (sin secretos)
CLAUDE.local.md, .claude/settings.local.jsonNoPreferencias personales
Credenciales y tokensNuncaVan en variables de entorno o en la configuración de usuario

AGENTS.md y el estándar multi-harness #

  • AGENTS.md es un archivo de instrucciones estándar que leen varios harnesses (Codex, Cursor, Copilot y otros). Equivale al CLAUDE.md.
  • Claude Code: desde la versión 2.1.277 (septiembre de 2026), si una carpeta no tiene CLAUDE.md, lee AGENTS.md. Se puede cambiar en /config. Si existen los dos, manda CLAUDE.md.
  • Para compartir un repo entre harnesses: poner las instrucciones en AGENTS.md y no crear CLAUDE.md; o, si quieres añadir cosas solo para Claude, un CLAUDE.md cuya primera línea sea @AGENTS.md (import) más lo específico.
  • .agents/skills/: hay una carpeta propuesta como estándar común para skills, pero Claude Code no la soporta oficialmente; la comunidad lo tiene pedido. Por ahora las skills de Claude van en .claude/skills/. El formato SKILL.md sí es estándar, así que la misma skill funciona copiada o enlazada en ambas rutas.
  • Las rules modulares (.claude/rules/) y los subagentes (.claude/agents/) son específicos de Claude Code; otros harnesses tienen sus equivalentes con otro formato.

Cómo se instala un método que sirve a varias herramientas a la vez sin duplicar ficheros, en instalar sin pisar.

La estructura cambia entre versiones

Contrástala con la documentación oficial de la versión que uses. El soporte de AGENTS.md se contrastó con la cobertura del lanzamiento de la 2.1.277.

Comandos de Claude Code #

Los comandos se escriben con / en la sesión. La lista cambia entre versiones: /help muestra siempre la actual, y al escribir / aparece un autocompletado con todos los disponibles, incluidos los tuyos.

Comprueba con /help

Los comandos y atajos de esta lección se recogieron sin la documentación de la versión que tengas instalada delante, y cambian entre versiones. /help es la fuente de verdad.

Comandos personalizados #

Tus propios comandos son archivos Markdown en .claude/commands/ (proyecto) o ~/.claude/commands/ (usuario). El nombre del archivo es el comando: review-pr.md se invoca con /review-pr. El contenido es el prompt; $ARGUMENTS recoge lo que escribas detrás.

markdown · .claude/commands/traspaso.md 
---
description: Escribe la nota de traspaso de la tarea actual
---

Escribe en docs/handoff.md el estado de la tarea: objetivo, hecho, pendiente,
decisiones con su motivo, archivos clave y siguiente paso. $ARGUMENTS

Comando vs. skill: el comando lo lanzas tú explícitamente; la skill la elige el modelo según la descripción. Las versiones recientes de Claude Code tienden a unificarlos (una skill también puede invocarse como comando). Qué debe llevar esa nota de traspaso, en modelos, esfuerzo y coste.

Cuándo aplicarlo #

Úsalo cuando…

  • Montas la configuración de un proyecto: decide qué va a Git y qué se queda en .local
  • Compartes el repo con gente que usa otros harnesses: AGENTS.md y un CLAUDE.md que lo importa
  • Repites el mismo prompt a menudo: conviértelo en un comando propio

No lo uses cuando…

  • Quieres guardar un secreto: ni settings.json ni .mcp.json son sitio para credenciales
  • Te aprendes la lista de comandos de memoria: cambia entre versiones, /help manda

Resumen #

Lo que te llevas

  • Dos niveles: usuario (~/.claude/) para lo tuyo y proyecto (.claude/) para lo del equipo; los .local se quedan fuera de Git y los secretos nunca entran.
  • AGENTS.md es el estándar entre harnesses; Claude Code lo lee si no hay CLAUDE.md, y un CLAUDE.md puede importarlo con @AGENTS.md.
  • /context, /compact, /clear y /rewind gestionan la sesión; /model, /cost y /usage, el coste.
  • Un comando propio es un Markdown en .claude/commands/ que lanzas tú; una skill la elige el modelo.
