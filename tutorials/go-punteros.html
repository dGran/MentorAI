Punteros en Go: & y * sin miedo

PHP pasa objetos por referencia automáticamente. Go pasa todo por valor: strings, ints, structs. Los punteros son la forma explícita de compartir datos sin copiarlos. Sin aritmética de punteros: no pueden apuntar a direcciones arbitrarias.

Go pasa todo por valor

Esta es la diferencia fundamental con PHP: en Go, cuando pasas un valor a una función, se crea una copia. Siempre. Para cualquier tipo.

func duplicar(n int) {
    n = n * 2   // modifica la copia local, no el original
}

x := 5
duplicar(x)
fmt.Println(x)   // 5: no cambió

Lo mismo con structs:

type Contador struct {
    Valor int
}

func incrementar(c Contador) {
    c.Valor++   // modifica la copia, no el original
}

c := Contador{Valor: 0}
incrementar(c)
fmt.Println(c.Valor)   // 0: no cambió

Qué es un puntero

Un puntero es una variable que almacena la dirección de memoria de otro valor. En lugar de copiar el valor, copias la dirección. Ambas variables apuntan al mismo dato en memoria.

Variable x
valor: 5
dirección: 0xC000
→
Puntero p
valor: 0xC000
(dirección de x)

Cuando modificas el valor a través del puntero, modificas el dato original porque ambos apuntan a la misma dirección.

Los operadores & y *

x := 5

p := &x          // &: "dame la dirección de x". p es un *int (puntero a int)
fmt.Println(p)   // 0xc000018068 (la dirección de memoria)
fmt.Println(*p)  // 5: *: "dame el valor al que apunta p" (dereferenciar)

*p = 10          // modificar el valor a través del puntero
fmt.Println(x)   // 10: x cambió porque p apunta a x

Con structs es igual, pero Go tiene un atajo: no necesitas derreferenciar el puntero para acceder a los campos:

type Producto struct {
    Nombre string
    Precio float64
}

p := &Producto{Nombre: "Mesa", Precio: 299.99}   // p es *Producto

// Las dos formas son equivalentes:
(*p).Nombre = "Silla"   // derreferenciando explícitamente
p.Nombre = "Silla"      // Go aplica la derreferencia automáticamente

Ahora la función incrementar que fallaba antes, corregida con puntero:

func incrementar(c *Contador) {
    c.Valor++   // modifica el struct original a través del puntero
}

c := Contador{Valor: 0}
incrementar(&c)           // pasamos la dirección de c
fmt.Println(c.Valor)      // 1: ahora sí cambió

Comparación con PHP

En PHP, los objetos se pasan como "handles" (referencias encubiertas): cuando pasas un objeto a una función, ambas variables apuntan al mismo objeto. Esto se parece al comportamiento de los punteros en Go, pero no es idéntico.

PHP: objetos son handles implícitos

function actualizar(Producto $p): void {
    $p->precio = 99.99;
    // $p apunta al mismo objeto: el cambio afecta fuera
}

$prod = new Producto("Mesa", 299.99);
actualizar($prod);
echo $prod->precio;  // 99.99

Go: necesitas el puntero explícito

func actualizar(p *Producto) {
    p.Precio = 99.99   // a través del puntero
}

prod := Producto{Nombre: "Mesa", Precio: 299.99}
actualizar(&prod)
fmt.Println(prod.Precio)   // 99.99

La diferencia es que en Go la decisión de compartir o copiar es explícita. Ves el & y sabes que esa función puede modificar el dato. En PHP no hay esa señal visual.

El puntero nil

Un puntero no inicializado tiene el valor nil: apunta a ningún sitio. Derreferenciar un puntero nil es un error en tiempo de ejecución (panic).

var p *Producto   // p es nil

fmt.Println(p)    // <nil>
fmt.Println(*p)   // PANIC: runtime error: invalid memory address or nil pointer dereference

La comprobación antes de usar un puntero que puede ser nil:

func procesarProducto(p *Producto) {
    if p == nil {
        return
    }

    fmt.Println(p.Nombre)
}

Cuándo usar punteros

SituaciónRecomendación
Función que necesita modificar un structPointer receiver / pasar puntero
Struct grande (decenas de campos)Puntero para evitar copias costosas
Campo opcional que puede no existir*Tipo (nil = ausente)
Struct pequeño, función que solo leeValue (copia): más simple y seguro
Tipos básicos (int, string, bool)Value casi siempre; puntero solo si necesitas modificarlo
Go no tiene aritmética de punteros. No puedes hacer p + 1 para avanzar al siguiente elemento de un array como en C. Los punteros de Go solo pueden apuntar a variables existentes. Esto elimina toda una clase de vulnerabilidades de seguridad.

Resumen

  • Go pasa todo por valor: strings, ints, structs. Cada argumento recibe una copia del dato.
  • &x devuelve la dirección de x (un puntero); *p devuelve el valor al que apunta p (derreferencia).
  • Para acceder a campos de un struct a través de un puntero, Go aplica la derreferencia automáticamente: p.Campo equivale a (*p).Campo.
  • Un puntero no inicializado vale nil. Derreferenciar nil provoca un panic.
  • Usa punteros cuando necesites modificar el dato original, o cuando el struct es grande y copiar sería costoso.
  • No hay aritmética de punteros: los punteros de Go son seguros por diseño.
