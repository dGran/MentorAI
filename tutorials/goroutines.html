Goroutines: concurrencia ligera

PHP es principalmente single-threaded: una petición, un hilo, ejecución secuencial. Go nació para lo contrario: lanzar miles de tareas concurrentes es tan natural como llamar a una función. La palabra clave es go.

Qué es una goroutine

Una goroutine es una función que Go ejecuta de forma concurrente con el resto del programa. No es un thread del sistema operativo: es una unidad gestionada por el runtime de Go, mucho más ligera.

Un thread del OS ocupa entre 1 y 8 MB de memoria. Una goroutine empieza con 2 KB y crece dinámicamente según lo que necesite. Puedes tener cientos de miles de goroutines activas en el mismo proceso sin problemas.

La palabra clave go

Para lanzar una goroutine, antepones go a cualquier llamada de función:

func saludar(nombre string) {
    fmt.Println("Hola,", nombre)
}

go saludar("Ana")   // lanza saludar en una goroutine nueva
go saludar("Luis")  // otra goroutine, concurrente con la anterior

// La función principal continúa aquí sin esperar

El problema con este código: si main termina antes que las goroutines, el proceso muere y las goroutines no completan su ejecución. Necesitas un mecanismo para esperar.

func main() {
    go saludar("Ana")
    go saludar("Luis")

    // sin nada más, main termina y las goroutines mueren con él
    // fmt.Println nunca llega a ejecutarse
}

Las goroutines también se lanzan con funciones anónimas, lo que es muy común en la práctica:

for i := 0; i < 5; i++ {
    i := i   // copia local: importante para capturar el valor correcto en el closure
    go func() {
        fmt.Println("goroutine", i)
    }()
}
El i := i es crítico. Sin él, el closure captura la variable del bucle (no su valor), y cuando la goroutine ejecuta, i ya puede haber cambiado. Es uno de los errores más comunes al empezar con goroutines.

Esperar goroutines: WaitGroup

sync.WaitGroup es el mecanismo básico para esperar a que un grupo de goroutines termine:

import "sync"

func procesarLotes(ids []int) {
    var wg sync.WaitGroup

    for _, id := range ids {
        wg.Add(1)   // incrementa el contador antes de lanzar la goroutine
        id := id    // captura local

        go func() {
            defer wg.Done()   // decrementa cuando la goroutine termina

            procesar(id)
        }()
    }

    wg.Wait()   // bloquea hasta que el contador llega a 0
    fmt.Println("todos los lotes procesados")
}

Tres reglas del WaitGroup:

  • Add(1) siempre antes de lanzar la goroutine. Si se llama dentro de la goroutine, puede haber una race condition entre Add y Wait.
  • Done() siempre con defer, para garantizar que se llama aunque la goroutine haga un return anticipado o entre en pánico.
  • No reusar un WaitGroup que tiene goroutines activas.

Race conditions

Cuando múltiples goroutines acceden a la misma variable y al menos una escribe, hay una race condition: el resultado depende del orden de ejecución, que no está garantizado.

// BUGGY: race condition
contador := 0
var wg sync.WaitGroup

for i := 0; i < 1000; i++ {
    wg.Add(1)
    go func() {
        defer wg.Done()
        contador++   // lectura + incremento + escritura: no atómico
    }()
}

wg.Wait()
fmt.Println(contador)   // puede ser cualquier número menor que 1000

Go tiene un detector de race conditions integrado. Compila y ejecuta con -race:

go run -race main.go
go test -race ./...

La solución con sync.Mutex (se desarrolla en la siguiente lección):

var mu sync.Mutex
contador := 0

for i := 0; i < 1000; i++ {
    wg.Add(1)
    go func() {
        defer wg.Done()
        mu.Lock()
        contador++
        mu.Unlock()
    }()
}

O con sync/atomic para operaciones simples:

import "sync/atomic"

var contador int64

for i := 0; i < 1000; i++ {
    wg.Add(1)
    go func() {
        defer wg.Done()
        atomic.AddInt64(&contador, 1)   // atómico: seguro sin mutex
    }()
}

Patrón worker pool

Lanzar una goroutine por cada tarea puede saturar los recursos si hay millones de tareas. El patrón worker pool limita la concurrencia a N goroutines activas:

func procesarConWorkers(ids []int, numWorkers int) {
    trabajos := make(chan int, len(ids))
    var wg sync.WaitGroup

    // Lanzar N workers
    for range numWorkers {
        wg.Add(1)
        go func() {
            defer wg.Done()

            for id := range trabajos {   // el channel se cierra cuando no hay más
                procesarID(id)
            }
        }()
    }

    // Enviar trabajos al channel
    for _, id := range ids {
        trabajos <- id
    }

    close(trabajos)   // señala a los workers que no hay más trabajo
    wg.Wait()
}

Resumen

  • Una goroutine es una función lanzada con go f(). El runtime de Go multiplexa miles de goroutines sobre un pequeño número de threads del OS.
  • Una goroutine pesa ~2 KB frente a 1-8 MB de un thread. Crear cientos de miles es normal en Go.
  • Usa sync.WaitGroup para esperar a que un grupo de goroutines termine. Add(1) antes de lanzar; defer Done() dentro.
  • Las race conditions ocurren cuando múltiples goroutines acceden a la misma variable con al menos una escritura. Detecta con go run -race.
  • El patrón worker pool limita la concurrencia a N goroutines activas usando un channel como cola de trabajo.
