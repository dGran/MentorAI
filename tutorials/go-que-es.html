Por qué Go: fortalezas y casos de uso

Go compila a un binario único, tiene concurrencia nativa y se lee en un día. No es otro lenguaje más: resuelve problemas específicos mejor que cualquier alternativa. Antes de escribir una línea de código, hay que entender qué lo hace diferente.

De dónde viene Go

Go lo crearon en Google en 2007 tres ingenieros que estaban hartos de esperar a que compilasen los programas en C++ y de la complejidad acumulada del lenguaje. Robert Griesemer, Rob Pike y Ken Thompson (el mismo que creó Unix y C) se pusieron un objetivo inusual: un lenguaje tan rápido de compilar que la compilación se note como instantánea, tan simple que la especificación completa quepa en una tarde de lectura, y con concurrencia de primera clase porque Google necesitaba gestionar millones de conexiones simultáneas.

Go 1.0 salió en 2012 con una promesa de compatibilidad: el código escrito para Go 1.0 compila con cualquier versión posterior. Esa promesa se ha mantenido. En 2024 ya va por la 1.23.

Las fortalezas del lenguaje

Compila a un binario único y estático

Go produce un ejecutable que no necesita runtime externo. No hay que instalar Go en el servidor. No hay que preocuparse por la versión de Python/Ruby/Node. No hay que subir dependencias: todo va dentro del binario.

Desplegar PHP

apt install php8.3-fpm
apt install php8.3-pdo php8.3-mbstring ...
composer install --no-dev
systemctl reload php8.3-fpm

Desplegar Go

GOOS=linux GOARCH=amd64 go build -o servicio .
scp servicio servidor:/usr/local/bin/
systemctl restart servicio

En Docker, esto se traduce en imágenes de producción que pueden pesar menos de 10 MB partiendo de FROM scratch (una imagen vacía). Sin runtime, sin capas extra.

Concurrencia nativa con goroutines

Una goroutine es como un hilo, pero gestionado por el runtime de Go, no por el sistema operativo. Arrancar un hilo del SO cuesta del orden de un megabyte de pila y milisegundos de tiempo. Una goroutine empieza con 2 KB y se lanza en microsegundos. Puedes tener miles sin que el sistema se resienta.

Para lanzar código concurrente basta con la palabra clave go:

func main() {
    go procesarPedido(123)   // se ejecuta concurrentemente, sin bloquear
    go enviarEmail("cliente@ejemplo.com")

    // el programa continúa aquí mientras ambas goroutines corren
    time.Sleep(time.Second)
}

Comparado con PHP, que arranca un proceso nuevo por cada petición HTTP y comparte nada entre ellos, Go puede manejar decenas de miles de conexiones simultáneas en un solo proceso. La diferencia es de órdenes de magnitud.

Compilación casi instantánea

Un proyecto mediano de Go compila en segundos. Uno grande, en menos de un minuto. Esto no es un detalle menor: ciclos rápidos de compilación son ciclos rápidos de desarrollo. Go consiguió esto prohibiendo las dependencias circulares entre paquetes y simplificando el árbol de compilación.

Tipado estático con inferencia

Go es estrictamente tipado: el compilador sabe el tipo de cada variable en tiempo de compilación y detecta errores antes de ejecutar. Pero la inferencia de tipos (:=) evita la verbosidad de Java:

// tipado explícito (también válido)
var nombre string = "Ana"

// inferido: el compilador deduce que es string
nombre := "Ana"

// el compilador detecta esto en compilación, no en producción
nombre = 42  // error: cannot use 42 (type int) as type string

Garbage collection con baja latencia

Go tiene GC como PHP, pero el compilador de Go 1.5 en adelante lo tiene ajustado para pausas por debajo de 1 ms. No tienes que gestionar memoria manualmente, pero tampoco sufres las pausas de GC que afectan a lenguajes JVM en servicios de baja latencia.

Especificación mínima y legibilidad forzada

Go tiene exactamente 25 palabras reservadas. La especificación completa tiene unas 100 páginas. No hay clases, no hay herencia, no hay excepciones, no hay sobrecarga de funciones, no hay anotaciones/decoradores. Lo que parece una limitación es una decisión: todo el código Go escrito por cualquier persona tiene el mismo estilo porque gofmt lo formatea automáticamente y el compilador rechaza código que no sigue ciertas convenciones (variables no usadas = error, imports no usados = error).

Go vs PHP: dos modelos de ejecución

Venir de PHP a Go implica cambiar el modelo mental sobre cómo vive un programa.

PHP con PHP-FPM

  • Un proceso por petición HTTP
  • Estado completamente aislado: variables, conexiones, todo se destruye al acabar
  • El framework arranca en cada petición (autoloader, DI container...)
  • No hay estado compartido entre peticiones → no hay condiciones de carrera
  • Escalar = más procesos FPM o más servidores

Go

  • Un proceso maneja todas las peticiones concurrentemente
  • El estado vive en la memoria del proceso entre peticiones
  • El servidor arranca una vez: conexiones a BD, cachés y configuración persisten
  • El estado compartido requiere sincronización (Mutex, channels)
  • Escalar = más instancias del binario detrás de un load balancer

Ninguno de los dos modelos es mejor en absoluto. PHP-FPM es más sencillo de razonar (cada petición es un mundo aislado). Go es más eficiente cuando el coste de arranque del proceso o el número de conexiones simultáneas es un problema.

Para qué proyectos es ideal

  • Servicios de red y APIs de alta concurrencia — servidores que manejan miles de conexiones simultáneas. La stdlib de Go incluye un servidor HTTP de producción en el paquete net/http.
  • CLIs y herramientas de sistema — compilas un binario y lo distribuyes. Sin instalar nada. kubectl, terraform, hugo y decenas de herramientas del ecosistema cloud están escritas en Go.
  • Infraestructura y plataformas — Docker, Kubernetes, Prometheus, Grafana, Loki, etcd, CockroachDB, Consul, Vault... toda la capa de infraestructura cloud nativa está en Go. No es casualidad.
  • Microservicios con equipos grandes — la simplicidad forzada del lenguaje hace que el código de un equipo sea legible por otro. El compilador rechaza código que no compila limpio.
  • Proxies, gateways y middleware de red — Caddy, Traefik, Envoy (parcialmente) están escritos en Go. La concurrencia y el rendimiento de red son su punto fuerte.
¿PHP entonces para qué? Para aplicaciones web con mucha lógica de negocio, formularios, CMS, e-commerce, APIs CRUD estándar. El ecosistema (Laravel, Symfony, Doctrine) es maduro y productivo. Go brilla cuando el cuello de botella es la concurrencia o el despliegue, no la lógica de negocio.

Cuándo NO elegir Go

  • Dominio con jerarquías de tipos ricas — Go no tiene herencia. Si tu modelo de negocio se beneficia de jerarquías OOP complejas, PHP o Java son más cómodos.
  • Control máximo de memoria o latencia sub-microsegundo — Go tiene GC. Para sistemas embebidos, drivers o código donde cada byte importa, Rust es la alternativa (sin GC, sin runtime).
  • Prototipado muy rápido — Go es explícito y verboso comparado con Python o PHP. Para explorar ideas rápido, lenguajes dinámicos ganan.
  • Ecosistema de librerías muy específico — machine learning (Python), móvil (Swift/Kotlin), juegos (C++). Go no tiene el ecosistema de nicho que otros lenguajes llevan décadas construyendo.

Go vs Rust: la pregunta inevitable

Si buscas salir del mundo interpretado, Go y Rust son las dos opciones más mencionadas. Son complementarios más que competidores:

DimensiónGoRust
Modelo de memoriaGC (automático)Ownership (sin GC, sin runtime)
Curva de aprendizajeSemanas para ser productivoMeses para dominar el borrow checker
RendimientoExcelente (comparável a Java/C#)Comparable a C/C++
ConcurrenciaGoroutines + channels (fácil)Fearless concurrency (garantizada por el compilador)
Punto fuerteServicios de red, CLIs, infra cloudSistemas, embedded, WebAssembly, máximo rendimiento
Casos realesDocker, Kubernetes, TerraformFirefox, ripgrep, Tokio, herramientas JS modernas

La regla práctica: si necesitas escribir un servicio, una API o una herramienta y quieres salir de PHP, empieza por Go. Si en algún momento el GC se convierte en un problema real (latencia de sub-milisegundo, memoria estrechamente controlada), entonces Rust es el siguiente paso.

Este curso termina donde empieza Rust. La lección go-a-produccion cierra el ciclo completo. Cuando llegues, tendrás criterio propio para decidir si quieres profundizar en Rust o quedarte en Go.

Resumen

  • Go compila a un binario estático único sin runtime externo: el despliegue más simple que existe.
  • Las goroutines permiten concurrencia masiva a un coste mínimo: miles de conexiones simultáneas en un solo proceso.
  • La compilación es casi instantánea. La especificación del lenguaje cabe en una tarde de lectura.
  • PHP y Go no compiten: PHP brilla en lógica de negocio web; Go en servicios de red, CLIs e infraestructura.
  • El ecosistema cloud nativo (Docker, Kubernetes, Prometheus) está escrito en Go.
  • Go tiene GC. Para control máximo de memoria sin GC, Rust es la alternativa.
