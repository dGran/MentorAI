Structs #

Los structs en Rust son la forma principal de agrupar datos relacionados, equivalente a las clases de PHP pero sin herencia. Un struct solo define datos; el comportamiento se añade con impl.

rust 
struct Producto {
    nombre: String,
    precio: f64,
    stock: u32,
}

fn main() {
    let producto = Producto {
        nombre: String::from("Teclado mecánico"),
        precio: 89.99,
        stock: 15,
    };

    println!("{} — {:.2}€", producto.nombre, producto.precio);
}

La struct update syntax crea una nueva instancia copiando los campos no especificados de otra:

rust 
let producto_sin_stock = Producto {
    stock: 0,
    ..producto // copia nombre y precio de producto
};

Los tuple structs son structs con campos posicionales en lugar de nombrados, útiles para crear tipos distintos de tipos primitivos:

rust 
struct Metros(f64);
struct Kilogramos(f64);

fn calcular_imc(peso: Kilogramos, altura: Metros) -> f64 {
    peso.0 / (altura.0 * altura.0)
}

// El compilador rechaza pasar Metros donde se espera Kilogramos
let imc = calcular_imc(Kilogramos(75.0), Metros(1.78));

Los unit structs no tienen campos. Se usan para implementar traits sobre un tipo vacío:

rust 
struct Marcador;

Métodos con impl #

El comportamiento de un struct se define en un bloque impl. Hay tres formas de declarar el primer parámetro según el acceso al dato:

rust 
impl Producto {
    pub fn new(nombre: &str, precio: f64) -> Self {
        Producto {
            nombre: nombre.to_string(),
            precio,
            stock: 0,
        }
    }

    pub fn precio_con_iva(&self) -> f64 {
        self.precio * 1.21
    }

    pub fn aplicar_descuento(&mut self, porcentaje: f64) {
        self.precio *= 1.0 - porcentaje / 100.0;
    }

    pub fn consumir(self) -> String {
        self.nombre
    }
}

fn main() {
    let mut prod = Producto::new("Ratón", 29.99);
    println!("{:.2}€ con IVA", prod.precio_con_iva());
    prod.aplicar_descuento(10.0);
    println!("{:.2}€ con descuento", prod.precio);
}
  • &self: préstamo inmutable. El más común. Solo lee el dato.
  • &mut self: préstamo mutable. Modifica el struct en su lugar.
  • self: toma ownership. El struct se consume y ya no es válido después de la llamada.
  • Métodos asociados (sin self): funcionan como métodos estáticos o constructores. Producto::new() es el patrón de constructor en Rust.

Enums con datos #

Los enums de Rust van mucho más allá de los enums de PHP: cada variante puede llevar datos distintos. Esto se llama algebraic data type y es la forma de modelar valores que pueden ser de varios tipos posibles.

rust 
enum Forma {
    Circulo(f64),
    Rectangulo(f64, f64),
    Triangulo { base: f64, altura: f64 },
}

fn area(forma: &Forma) -> f64 {
    match forma {
        Forma::Circulo(radio) => std::f64::consts::PI * radio * radio,
        Forma::Rectangulo(ancho, alto) => ancho * alto,
        Forma::Triangulo { base, altura } => base * altura / 2.0,
    }
}

fn main() {
    let formas = vec![
        Forma::Circulo(5.0),
        Forma::Rectangulo(4.0, 6.0),
        Forma::Triangulo { base: 3.0, altura: 8.0 },
    ];

    for forma in &formas {
        println!("Área: {:.2}", area(forma));
    }
}

La potencia está en que el compilador sabe en cada match qué datos lleva cada variante, y los extrae con tipo correcto. No hay casting ni instanceof.

También puedes añadir métodos a los enums con impl, igual que con los structs.

Option<T>: sin null #

Rust no tiene null. Un valor que puede estar presente o ausente se modela con Option<T>, que es un enum de la stdlib:

rust 
enum Option<T> {
    Some(T),
    None,
}

Cuando una función puede no encontrar un valor, retorna Option:

rust 
fn buscar_usuario(id: u32) -> Option<String> {
    if id == 1 {
        Some(String::from("Ana"))
    } else {
        None
    }
}

fn main() {
    match buscar_usuario(1) {
        Some(nombre) => println!("Usuario: {}", nombre),
        None => println!("No encontrado"),
    }

    if let Some(nombre) = buscar_usuario(2) {
        println!("Usuario: {}", nombre);
    } else {
        println!("No encontrado");
    }
}

Métodos útiles de Option:

  • .unwrap(): extrae el valor o entra en panic si es None. Solo en tests o cuando es imposible que sea None.
  • .expect("mensaje"): como unwrap pero con mensaje de error descriptivo.
  • .unwrap_or(valor_por_defecto): extrae el valor o usa el default.
  • .map(|x| ...): transforma el valor dentro del Some sin tocar el None.
  • .and_then(|x| ...): encadena operaciones que retornan Option (flatMap).

Comparación con PHP: en PHP, cualquier función puede retornar null sin que el tipo lo declare. En Rust, si el tipo de retorno es String, es imposible que sea null. Si puede ser null, el tipo debe ser Option<String> y el compilador exige que lo trates.

Result<T, E>: errores como valores #

Result<T, E> es el equivalente de Option para operaciones que pueden fallar con información de error:

rust 
enum Result<T, E> {
    Ok(T),
    Err(E),
}
rust 
use std::fs;
use std::io;

fn leer_config(ruta: &str) -> Result<String, io::Error> {
    fs::read_to_string(ruta)
}

fn main() {
    match leer_config("config.toml") {
        Ok(contenido) => println!("Config: {}", contenido),
        Err(error) => eprintln!("Error al leer config: {}", error),
    }
}

El operador ? propaga el error automáticamente: si el Result es Err, retorna ese error de la función actual. Si es Ok, extrae el valor:

rust 
fn procesar_config(ruta: &str) -> Result<(), io::Error> {
    let contenido = fs::read_to_string(ruta)?; // propaga si Err
    println!("Procesando {} bytes", contenido.len());
    Ok(())
}

unwrap() en producción: llamar a .unwrap() en un Result en código de producción es como dejar una excepción sin capturar en PHP. Si el Result es Err, el programa entra en panic y se detiene. Usa ? para propagar o match para manejar.

Resumen #

Lo que te llevas

  • Los structs agrupan datos con campos nombrados; los tuple structs crean tipos distintos de primitivos; los unit structs son marcadores sin datos.
  • El bloque impl añade comportamiento al struct: &self para leer, &mut self para mutar, self para consumir, y métodos asociados sin self para constructores.
  • Los enums pueden llevar datos distintos en cada variante (algebraic data types); el match los desestructura con tipo correcto sin casting.
  • Option<T> reemplaza a null: el compilador exige tratar explícitamente los casos Some y None, eliminando los null pointer errors.
  • Result<T, E> modela operaciones fallibles; el operador ? propaga el error de forma concisa; unwrap() solo se usa en tests.
