Paquetes y módulos: la unidad de organización

En Go el código se organiza en paquetes y los proyectos en módulos. go.mod y go.sum son el composer.json y el composer.lock de Go: declaran dependencias y fijan las versiones exactas que se usan.

Qué es un paquete

Un paquete en Go es un directorio con ficheros .go que comparten la misma declaración package. El nombre del paquete suele coincidir con el nombre del directorio, aunque no es obligatorio.

La stdlib de Go está organizada en paquetes: fmt para formateo, net/http para HTTP, os para el sistema operativo, strings para manipulación de cadenas. Cada uno es un directorio en la instalación de Go.

// fichero: matematicas/suma.go
package matematicas    // nombre del paquete

func Suma(a, b int) int {
    return a + b
}

func sumaInterna(a, b int) int {   // minúscula: solo visible dentro del paquete
    return a + b
}

// fichero: main.go
package main

import (
    "fmt"
    "mi-proyecto/matematicas"
)

func main() {
    resultado := matematicas.Suma(3, 4)    // mayúscula: accesible
    fmt.Println(resultado)                  // 7
}

Visibilidad: mayúscula vs minúscula

Go no tiene public, private ni protected. La regla es una sola: mayúscula inicial = exportado (visible desde fuera del paquete); minúscula inicial = no exportado (privado al paquete).

PHP

class Calculadora {
    public function sumar(int $a, int $b): int {
        return $a + $b;
    }

    private function log(): void {}
}

Go

// en el paquete calculadora
func Sumar(a, b int) int {    // exportada
    return a + b
}

func logear() {               // no exportada
}

La regla aplica a funciones, tipos, variables, constantes y campos de struct. Si el nombre empieza con mayúscula, es parte de la API pública del paquete.

Módulos: go.mod y go.sum

Un módulo es la unidad de distribución de Go: un árbol de paquetes con un fichero go.mod en la raíz. El módulo tiene un nombre (su ruta de importación) y declara sus dependencias.

// go.mod
module github.com/usuario/mi-servicio

go 1.23

require (
    github.com/gin-gonic/gin v1.10.0
    github.com/lib/pq v1.10.9
)

PHP (composer.json)

{
  "name": "usuario/mi-servicio",
  "require": {
    "laravel/framework": "^11.0",
    "doctrine/orm": "^3.0"
  }
}

Go (go.mod)

module github.com/usuario/mi-servicio

go 1.23

require (
    github.com/gin-gonic/gin v1.10.0
    github.com/jmoiron/sqlx v1.3.5
)

go.sum fija los checksums criptográficos de cada dependencia y sus dependencias transitivas. Es el equivalente al composer.lock: garantiza que todos en el equipo (y el CI) usan exactamente los mismos binarios. Nunca se edita a mano.

Imports y alias

Los imports usan la ruta completa del paquete pero se usan por el nombre corto final:

import (
    "fmt"                           // uso: fmt.Println
    "net/http"                      // uso: http.Get
    "github.com/gin-gonic/gin"      // uso: gin.New
)

Cuando dos paquetes tienen el mismo nombre final, se usa un alias:

import (
    pgx "github.com/jackc/pgx/v5"          // alias: pgx
    stdlib "github.com/jackc/pgx/v5/stdlib" // alias: stdlib
)

El import con guión bajo descarta el paquete pero ejecuta su función init() — útil para registrar drivers de base de datos:

import (
    "database/sql"
    _ "github.com/lib/pq"    // registra el driver postgres, no se usa directamente
)

Gestionar dependencias

# Añadir una dependencia
go get github.com/gin-gonic/gin@v1.10.0

# Actualizar a la última versión compatible
go get github.com/gin-gonic/gin@latest

# Eliminar dependencias no usadas / añadir las que faltan
go mod tidy

# Ver el árbol de dependencias
go mod graph

# Descargar todas las dependencias al caché local
go mod download
go mod tidy es el equivalente a composer install + composer dump-autoload. Ejecútalo antes de cada commit para que go.mod y go.sum estén sincronizados.

El directorio internal

Go tiene un mecanismo de encapsulamiento a nivel de módulo: el directorio internal/. El compilador impide importar paquetes de internal/ desde fuera del módulo al que pertenecen. No es una convención: es una regla del compilador.

mi-servicio/
├── cmd/
│   └── server/
│       └── main.go        # puede importar internal/
├── internal/
│   ├── auth/              # solo importable desde mi-servicio
│   └── db/                # solo importable desde mi-servicio
└── pkg/
    └── utils/             # importable desde cualquier módulo externo

La convención es: internal/ para código privado del módulo; pkg/ para código que quieres ofrecer a otros módulos.

Resumen

  • Un paquete = un directorio de ficheros .go con la misma declaración package.
  • Visibilidad: mayúscula inicial = exportado; minúscula inicial = privado al paquete. Sin public/private.
  • go.mod declara el módulo y sus dependencias directas; go.sum fija los checksums. Nunca editar go.sum a mano.
  • go get añade dependencias; go mod tidy las sincroniza. Equivale a composer require y composer install.
  • El directorio internal/ es código privado del módulo: el compilador impide importarlo desde fuera.
