Linux: paquetes, compresión y cron

Instalar software con apt, descomprimir archives con tar, y programar tareas automáticas con crontab. Tres herramientas de administración que usarás cada semana.

Gestión de paquetes: apt#

En Ubuntu/Debian el gestor de paquetes es apt (Advanced Package Tool). Descarga, instala y actualiza software desde repositorios mantenidos por la distribución.

bash · apt esencial
apt update                      # actualiza el índice de paquetes disponibles
apt upgrade                     # actualiza los paquetes instalados
apt full-upgrade                # actualiza incluyendo cambios de dependencias

apt install nginx               # instala nginx
apt install php8.2 php8.2-fpm php8.2-mbstring   # instala varios
apt install -y nginx            # -y responde sí automáticamente (scripts)
apt remove nginx                # desinstala (conserva configs)
apt purge nginx                 # desinstala + borra ficheros de configuración
apt autoremove                  # elimina dependencias ya no necesarias

apt search "nombre o descripción"   # buscar paquetes
apt show nginx                      # información detallada de un paquete
apt list --installed                # paquetes instalados
apt list --upgradable               # paquetes con actualización disponible

apt update antes de instalar, siempre

Si no actualizas el índice, apt puede intentar descargar versiones antiguas o que ya no existen en los repositorios. El flujo correcto es siempre apt update && apt install paquete. En Dockerfiles se combina en un solo RUN para evitar que la caché de capas use un índice viejo.

bash · repositorios externos (PPAs)
# Añadir un repositorio externo (ejemplo: Ondrej para PHP en Ubuntu):
apt install -y software-properties-common
add-apt-repository ppa:ondrej/php
apt update
apt install php8.3

# Ver repositorios configurados:
cat /etc/apt/sources.list
ls /etc/apt/sources.list.d/

El nivel más bajo: dpkg#

dpkg es la herramienta de bajo nivel que gestiona paquetes .deb individualmente. apt se apoya en ella y gestiona las dependencias automáticamente; dpkg no lo hace.

bash
dpkg -i paquete.deb             # instalar un .deb descargado
dpkg -r nombre-paquete          # desinstalar
dpkg -l                         # listar todos los paquetes instalados
dpkg -l | grep nginx            # buscar en los instalados
dpkg -L nginx                   # ficheros que instaló el paquete nginx
dpkg -S /usr/sbin/nginx         # qué paquete instaló ese fichero
dpkg --get-selections           # lista de paquetes con su estado

Compresión: tar y gzip#

tar (Tape Archive) agrupa ficheros en un solo archivo; los algoritmos de compresión (gzip, bzip2, xz) reducen su tamaño. La combinación .tar.gz (tarball) es el estándar de facto en Linux.

bash · tar: crear y extraer
# Crear:
tar -czf backup.tar.gz directorio/     # c=crear, z=gzip, f=fichero
tar -cjf backup.tar.bz2 directorio/   # j=bzip2 (mejor ratio, más lento)
tar -cJf backup.tar.xz directorio/    # J=xz (mejor ratio aún)
tar -czf backup.tar.gz fichero1 fichero2 directorio/   # múltiples orígenes

# Extraer:
tar -xzf backup.tar.gz              # x=extraer, z=gzip, f=fichero
tar -xzf backup.tar.gz -C /destino/ # extrae en un directorio específico
tar -xzf backup.tar.gz fichero.txt  # extrae solo un fichero del archivo

# Ver contenido sin extraer:
tar -tzf backup.tar.gz              # lista los ficheros

# Regla mnemotécnica: czf = Crear Zipped File; xzf = eXtraer Zipped File
bash · gzip y otros
gzip fichero.log            # comprime y reemplaza por fichero.log.gz
gzip -k fichero.log         # -k conserva el original
gunzip fichero.log.gz        # descomprime
zcat fichero.log.gz          # lee sin descomprimir (útil para grep)
zcat fichero.log.gz | grep "error"

zip y unzip#

bash
zip -r backup.zip directorio/    # -r recursivo
zip -r backup.zip *.php *.env    # múltiples patrones
unzip backup.zip                 # extrae en el directorio actual
unzip backup.zip -d /destino/    # extrae en directorio específico
unzip -l backup.zip              # lista el contenido sin extraer
unzip -p backup.zip fichero.txt  # muestra el contenido de un fichero por stdout

Tareas programadas: cron#

cron es el demonio que ejecuta comandos en horarios definidos. Cada usuario tiene su propia tabla de tareas (crontab).

bash · sintaxis crontab
# Formato: minuto hora dia_mes mes dia_semana comando
# *=cualquiera, */n=cada n, valores separados por coma, rangos con -

# Minuto (0-59)
#   │ Hora (0-23)
#   │   │ Día del mes (1-31)
#   │   │   │ Mes (1-12)
#   │   │   │   │ Día de semana (0=dom, 1=lun... 6=sáb)
#   │   │   │   │   │ Comando
#   *   *   *   *   *   /ruta/al/script.sh

0   2   *   *   *   /usr/local/bin/backup.sh    # a las 2:00 todos los días
*/15 *  *   *   *   /usr/local/bin/check.sh     # cada 15 minutos
0   0   *   *   0   /usr/local/bin/weekly.sh    # domingos a medianoche
0   9   1   *   *   /usr/local/bin/monthly.sh   # el 1 de cada mes a las 9h
30  23  *   *  1-5  /usr/local/bin/work.sh      # lunes-viernes a las 23:30
bash · gestionar crontab
crontab -e              # editar el crontab del usuario actual
crontab -l              # listar las tareas actuales
crontab -r              # borrar TODAS las tareas (cuidado)
crontab -u david -l     # ver el crontab de otro usuario (como root)

# Tareas del sistema (requieren root):
ls /etc/cron.d/          # tareas de paquetes del sistema
ls /etc/cron.daily/      # scripts que se ejecutan diariamente
ls /etc/cron.weekly/     # semanalmente
ls /etc/cron.monthly/    # mensualmente

# Log de ejecuciones:
grep CRON /var/log/syslog | tail -20
journalctl -u cron | tail -20

Cron no hereda el PATH de tu shell

Los scripts de cron se ejecutan con un entorno mínimo. php, composer o git pueden no estar en el PATH de cron aunque sí estén en el tuyo. Solución: usa rutas absolutas (/usr/bin/php) o añade PATH=/usr/local/bin:/usr/bin:/bin al inicio del crontab.

bash · crontab con salida controlada
# Redirigir stdout y stderr a un log:
0 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1

# Silenciar todo (si no hay log del demonio):
0 2 * * * /usr/local/bin/backup.sh > /dev/null 2>&1

# Variables de entorno en crontab:
PATH=/usr/local/bin:/usr/bin:/bin
MAILTO=admin@midominio.com      # cron enviará emails con la salida si hay errores
0 2 * * * /usr/local/bin/backup.sh

Cuándo aplicarlo#

Úsalo cuando…

  • Servidor bare-metal o VM con servicios nativos del OS: gestiona con systemd
  • Necesitas diagnosticar fallos de arranque, hardware o servicios que mueren silenciosamente: revisa con journalctl
  • Tareas programadas del sistema sin contenedores: usa cron

No lo uses cuando…

  • Entorno containerizado: no gestiones servicios con systemd dentro del contenedor, usa el proceso principal de Docker
  • El servicio necesita portabilidad entre entornos: prefiere Docker en lugar de instalarlo como servicio del OS

Resumen#

Lo que te llevas

  • Siempre apt update antes de apt install. apt purge borra también los ficheros de configuración; apt remove los conserva.
  • dpkg -L paquete lista los ficheros instalados por ese paquete. dpkg -S /ruta/fichero dice qué paquete lo instaló.
  • tar -czf backup.tar.gz dir/ crea; tar -xzf backup.tar.gz extrae. Mnemotécnica: c=crear, x=extraer, z=gzip, f=fichero.
  • La sintaxis de crontab es min hora dia mes diasemana comando. * = cualquier valor; */15 = cada 15.
  • Cron no hereda el PATH del shell: usa rutas absolutas o define PATH= al inicio del crontab. Redirige la salida a un log para poder depurar.
