Testing: tests, benchmarks y cobertura

Go incluye testing en la stdlib. go test ejecuta tests, mide cobertura y corre benchmarks sin instalar nada. No hay assertions library obligatoria: el compilador y el paquete testing son suficientes.

Estructura de un test

En Go, los tests van en ficheros con sufijo _test.go, en el mismo paquete que el código que prueban. La función de test recibe *testing.T:

// fichero: matematicas/suma_test.go
package matematicas

import "testing"

func TestSuma(t *testing.T) {
    resultado := Suma(3, 4)

    if resultado != 7 {
        t.Errorf("Suma(3, 4) = %d, se esperaba 7", resultado)
    }
}

Los métodos más habituales de *testing.T:

t.Errorf("mensaje: %v", valor)    // marca el test como fallido y continúa
t.Fatalf("mensaje: %v", valor)    // marca el test como fallido y para
t.Logf("info: %v", valor)         // log visible con -v
t.Skip("razón")                   // omite el test
t.Parallel()                      // ejecuta el test en paralelo con otros

go test y sus flags

# Ejecutar todos los tests del módulo
go test ./...

# Con output detallado (ver nombres de tests que pasan)
go test -v ./...

# Un paquete específico
go test ./matematicas

# Cobertura de código
go test -cover ./...
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out   # abre el informe en el navegador

# Ejecutar solo tests que coinciden con el patrón
go test -run TestSuma ./...

# Con race detector
go test -race ./...

# Timeout (por defecto 10 minutos)
go test -timeout 30s ./...

Table-driven tests

El patrón dominante en Go: una tabla de casos de prueba que se itera en un único test. Evita duplicación y hace trivial añadir casos:

func TestSuma(t *testing.T) {
    casos := []struct {
        nombre    string
        a, b      int
        esperado  int
    }{
        {"positivos", 3, 4, 7},
        {"negativos", -1, -2, -3},
        {"mixto", -1, 5, 4},
        {"cero", 0, 0, 0},
    }

    for _, tc := range casos {
        t.Run(tc.nombre, func(t *testing.T) {
            t.Parallel()   // cada subtest en paralelo

            resultado := Suma(tc.a, tc.b)

            if resultado != tc.esperado {
                t.Errorf("Suma(%d, %d) = %d, se esperaba %d",
                    tc.a, tc.b, resultado, tc.esperado)
            }
        })
    }
}

t.Run crea un subtest con nombre, lo que hace más legibles los errores: --- FAIL: TestSuma/negativos.

Interfaces para tests: sin mocks

Go favorece un enfoque diferente al de PHP para los tests: en lugar de mocks que simulan dependencias completas, defines interfaces pequeñas e implementas versiones fake directamente. Así evitas librerías de mocking y mantienes los tests compilables:

type EnviadorEmail interface {
    Enviar(dest, asunto, cuerpo string) error
}

type ServicioRegistro struct {
    emails EnviadorEmail
}

func (s *ServicioRegistro) Registrar(usuario string) error {
    // ... lógica de registro
    return s.emails.Enviar(usuario, "Bienvenido", "Tu cuenta está lista")
}

// Fake para tests: implementa la interfaz, captura las llamadas
type fakeEmailer struct {
    enviados []string
}

func (f *fakeEmailer) Enviar(dest, asunto, cuerpo string) error {
    f.enviados = append(f.enviados, dest)
    return nil
}

func TestRegistrar(t *testing.T) {
    emailer := &fakeEmailer{}
    svc := &ServicioRegistro{emails: emailer}

    if err := svc.Registrar("ana@ejemplo.com"); err != nil {
        t.Fatalf("error inesperado: %v", err)
    }

    if len(emailer.enviados) != 1 {
        t.Errorf("se esperaba 1 email, se enviaron %d", len(emailer.enviados))
    }
}

httptest: tests de handlers HTTP

El paquete net/http/httptest permite testear handlers HTTP sin levantar un servidor real:

import (
    "net/http"
    "net/http/httptest"
    "testing"
)

func TestListarProductos(t *testing.T) {
    req := httptest.NewRequest(http.MethodGet, "/productos", nil)
    w := httptest.NewRecorder()

    listarProductos(w, req)   // llamamos al handler directamente

    resp := w.Result()

    if resp.StatusCode != http.StatusOK {
        t.Errorf("status = %d, se esperaba 200", resp.StatusCode)
    }

    if ct := resp.Header.Get("Content-Type"); ct != "application/json" {
        t.Errorf("Content-Type = %q, se esperaba application/json", ct)
    }
}

Benchmarks

Los benchmarks siguen la misma convención: fichero _test.go, función con prefijo Benchmark que recibe *testing.B:

func BenchmarkSuma(b *testing.B) {
    for i := 0; i < b.N; i++ {   // b.N lo ajusta el framework automáticamente
        Suma(3, 4)
    }
}

# Ejecutar benchmarks (no se ejecutan con go test normal)
go test -bench=. ./...

# Con memoria
go test -bench=. -benchmem ./...

# Salida: ns/op, B/op, allocs/op
# BenchmarkSuma-8   1000000000   0.3 ns/op   0 B/op   0 allocs/op

Resumen

  • Tests en ficheros _test.go. Función TestNombre(t *testing.T). t.Errorf falla y continúa; t.Fatalf falla y para.
  • Table-driven tests con t.Run: el patrón dominante en Go. Añadir un caso es añadir una línea a la tabla.
  • En lugar de mocks pesados, define interfaces pequeñas e implementa fakes directamente. Compilados, sin magia de runtime.
  • httptest.NewRequest y httptest.NewRecorder permiten testear handlers HTTP sin servidor.
  • Benchmarks con BenchmarkNombre(b *testing.B) y go test -bench=.. El framework ajusta b.N automáticamente.
  • go test -race ./... detecta race conditions. go test -cover ./... mide cobertura. Ambos deben pasar en CI.
