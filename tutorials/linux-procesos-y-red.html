Linux: procesos, SSH y red

Gestión de procesos#

Cada programa en ejecución es un proceso con su propio identificador (PID). Linux te da herramientas para listarlos, inspeccionarlos y terminarlos.

bash · ps y top
ps aux                          # todos los procesos del sistema
ps aux | grep nginx             # filtrar por nombre
ps aux | grep "^www-data"       # procesos del usuario www-data
ps -p 1234                      # información de un PID concreto
ps --forest                     # árbol de procesos (muestra hijos)

top                             # vista dinámica en tiempo real (q para salir)
top -u david                    # procesos solo del usuario david
top -p 1234,5678                # monitorizar PIDs concretos

htop                            # versión mejorada de top (instalar: apt install htop)

pgrep nginx                     # devuelve los PIDs de procesos que se llaman nginx
pgrep -u www-data php           # PIDs del proceso php del usuario www-data
pstree                          # árbol de procesos en ASCII
bash · señales y kill
kill 1234               # SIGTERM (15): pide al proceso que termine ordenadamente
kill -9 1234            # SIGKILL: lo mata inmediatamente, sin que pueda limpiarse
kill -HUP 1234          # SIGHUP: recarga la configuración (nginx, php-fpm...)
kill -STOP 1234         # pausa el proceso
kill -CONT 1234         # reanuda un proceso pausado

pkill nginx             # kill por nombre (equivale a kill $(pgrep nginx))
pkill -u david          # mata todos los procesos del usuario david
pkill -HUP php-fpm      # recarga php-fpm por nombre

# Regla: siempre intenta SIGTERM primero; SIGKILL solo si el proceso no responde.

Procesos en segundo plano#

bash
comando &                   # lanza en segundo plano; imprime el PID
jobs                        # lista procesos en segundo plano de esta shell
fg %1                       # trae al primer plano el job 1
bg %1                       # reanuda en segundo plano el job 1
Ctrl+Z                      # pausa el proceso actual y lo pone en jobs

# nohup: sobrevive al cierre de la sesión
nohup python3 servidor.py &                     # ignora SIGHUP
nohup python3 servidor.py > servidor.log 2>&1 &  # con log

SSH y autenticación por clave#

SSH (Secure Shell) cifra la conexión entre tu máquina y el servidor. Con claves asimétricas eliminas las contraseñas: tu clave privada nunca sale de tu máquina.

bash · generar y distribuir claves
# Generar un par de claves (ed25519 es el estándar moderno):
ssh-keygen -t ed25519 -C "david@mi-maquina"
# Guarda ~/.ssh/id_ed25519 (privada) y ~/.ssh/id_ed25519.pub (pública)

# Copiar la clave pública al servidor:
ssh-copy-id usuario@servidor.com
# Equivalente manual: añade el contenido de id_ed25519.pub a ~/.ssh/authorized_keys en el servidor

# Conectar:
ssh usuario@servidor.com
ssh -p 2222 usuario@servidor.com          # puerto no estándar
ssh -i ~/.ssh/otra_clave usuario@servidor.com  # clave específica
bash · ~/.ssh/config
# ~/.ssh/config — aliases para no recordar IPs ni usuarios:
Host produccion
    HostName 192.168.1.100
    User deploy
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

Host staging
    HostName staging.miempresa.com
    User david
    ForwardAgent yes    # reenvía tu agente SSH al servidor remoto

# Con esta config:
ssh produccion          # equivale a: ssh -p 2222 -i ~/.ssh/id_ed25519 deploy@192.168.1.100

Permisos del directorio .ssh

SSH rechaza las claves si los permisos son demasiado permisivos. El directorio ~/.ssh debe ser 700 y los ficheros de clave privada 600. Si SSH se niega a usar una clave, ese es el primer sitio donde mirar.

bash · permisos correctos
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub
chmod 600 ~/.ssh/authorized_keys
chmod 600 ~/.ssh/config

Transferir ficheros: scp y rsync#

bash · scp
scp fichero.txt usuario@servidor:/destino/      # subir
scp -r directorio/ usuario@servidor:/destino/  # subir directorio
scp usuario@servidor:/remoto/fichero.txt ./    # descargar
scp -P 2222 fichero.txt usuario@servidor:/destino/  # puerto no estándar
bash · rsync
# rsync es más potente: solo transfiere lo que ha cambiado
rsync -avz directorio/ usuario@servidor:/destino/
# -a = archive (preserva permisos, timestamps, symlinks)
# -v = verbose
# -z = comprime durante la transferencia

rsync -avz --delete directorio/ usuario@servidor:/destino/
# --delete: elimina en destino los ficheros que ya no existen en origen

rsync -avz --exclude="*.log" --exclude=".git/" src/ servidor:/var/www/
# excluir patrones

rsync -avz -e "ssh -p 2222" directorio/ usuario@servidor:/destino/
# SSH con puerto no estándar

# Dry run: ver qué haría sin ejecutar nada
rsync -avz --dry-run directorio/ usuario@servidor:/destino/

Diagnóstico de red#

bash · puertos y conexiones
# ss: herramienta moderna para ver sockets (reemplaza a netstat)
ss -tlnp              # TCP (-t), en escucha (-l), numérico (-n), con proceso (-p)
ss -tlnp | grep :80   # ver quién escucha en el puerto 80
ss -tunp              # también UDP
ss -s                 # resumen de estadísticas

# lsof: qué proceso tiene abierto un fichero o socket
lsof -i :80           # proceso que usa el puerto 80
lsof -i :80 -i :443   # varios puertos
lsof -p 1234          # ficheros abiertos por el PID 1234
lsof -u www-data      # ficheros del usuario www-data
bash · curl y wget
# curl: cliente HTTP desde la terminal
curl https://api.miservicio.com/health    # GET básico
curl -I https://ejemplo.com              # solo cabeceras (HEAD)
curl -s https://api.github.com/users/php | python3 -m json.tool  # JSON bonito
curl -X POST https://api/endpoint \
     -H "Content-Type: application/json" \
     -H "Authorization: Bearer TOKEN" \
     -d '{"nombre":"david"}'             # POST con JSON
curl -o archivo.zip https://ejemplo.com/archivo.zip  # descargar con nombre
curl -v https://ejemplo.com             # verbose: muestra cabeceras y handshake
curl -w "%{http_code} %{time_total}s\n" -o /dev/null -s https://ejemplo.com  # código y tiempo

# wget: descargador; mejor que curl para ficheros grandes
wget https://ejemplo.com/archivo.tar.gz
wget -q --show-progress https://ejemplo.com/archivo.tar.gz  # barra de progreso
wget -c https://ejemplo.com/archivo.tar.gz  # continuar descarga interrumpida
bash · diagnóstico básico
ping -c 4 8.8.8.8              # comprobar conectividad (4 paquetes)
traceroute 8.8.8.8             # ruta que sigue el paquete
nslookup dominio.com           # resolver DNS
dig dominio.com                # resolución DNS detallada
dig dominio.com MX             # registros de correo
ip addr                        # interfaces de red e IPs
ip route                       # tabla de rutas

Logs del sistema: journalctl#

journalctl accede al journal de systemd, el registro centralizado de todos los servicios del sistema.

bash
journalctl                              # todos los logs (paginado)
journalctl -u nginx                     # logs del servicio nginx
journalctl -u nginx -f                  # -f = seguir en tiempo real (como tail -f)
journalctl -u nginx --since "1 hour ago"
journalctl -u nginx --since "2024-01-15 10:00" --until "2024-01-15 11:00"
journalctl -u nginx -n 100              # últimas 100 líneas
journalctl -u nginx -p err              # solo errores
journalctl -u nginx -p err..crit        # entre niveles de prioridad
journalctl --disk-usage                 # cuánto espacio ocupa el journal
journalctl --vacuum-time=30d            # borrar logs de más de 30 días

# Para servicios que no usan systemd:
tail -f /var/log/nginx/error.log
tail -f /var/log/nginx/access.log | grep " 5[0-9][0-9] "   # solo errores 5xx

Cuándo aplicarlo#

Úsalo cuando…

  • Snapshot rápido del estado de los procesos: ps aux o top
  • Monitorización interactiva y cómoda: htop o btop
  • Verificar que tu servicio escucha en el puerto correcto o detectar conexiones inesperadas: ss -tlnp

No lo uses cuando…

  • No uses netstat en sistemas modernos: está deprecado, ss es más rápido y completo
  • No ignores procesos zombie o picos de CPU sostenidos: son síntomas de problemas reales que necesitan diagnóstico

Resumen#

Lo que te llevas

  • ps aux | grep nombre para encontrar un proceso; kill PID para terminarlo. SIGTERM primero, SIGKILL solo si no responde.
  • SSH con clave ed25519 es más seguro que con contraseña. ssh-copy-id copia tu clave al servidor. ~/.ssh/config guarda alias para no recordar IPs ni usuarios.
  • rsync -avz --delete es la herramienta de sincronización: solo transfiere cambios. --dry-run para ver qué haría antes de ejecutar.
  • ss -tlnp muestra qué proceso escucha en cada puerto. curl -v y curl -w para depurar peticiones HTTP.
  • journalctl -u servicio -f para seguir los logs de un servicio en tiempo real. -p err filtra solo errores.
