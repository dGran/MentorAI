Tipos y variables en Rust

let e inmutabilidad por defecto, tipos escalares, inferencia de tipos, const, shadowing y por qué Rust prefiere la explicitez.

En PHP una variable es una caja donde cabe cualquier cosa en cualquier momento, y alguna vez habrás descubierto en producción que $total era un string. Rust le da la vuelta: cada valor tiene un tipo fijo conocido al compilar y no cambia salvo que lo pidas. Parece burocracia hasta que cuentas cuántos bugs de PHP desaparecen antes de ejecutar nada.

let e inmutabilidad por defecto #

En PHP, cualquier variable es mutable por defecto: puedes reasignarla en cualquier momento. En Rust, ocurre lo contrario: las variables declaradas con let son inmutables por defecto.

rust 
fn main() {
    let x = 5;
    x = 6; // error[E0384]: cannot assign twice to immutable variable `x`
}

Para hacer una variable mutable, debes declararlo explícitamente con let mut:

rust 
fn main() {
    let mut contador = 0;
    contador += 1;
    println!("{}", contador); // 1
}

Esta decisión no es caprichosa. La inmutabilidad por defecto hace que el código sea más predecible: cuando ves let x = 5, sabes que x nunca cambia. Si alguien quiere mutarlo, tiene que declararlo, lo que es una señal de intención explícita.

Comparación con PHP: en PHP, $x = 5; $x = 6; es perfectamente válido y no hay forma idiomática de declarar que $x no debe cambiar. En Rust, la inmutabilidad es la posición por defecto y la mutabilidad requiere declaración explícita.

Tipos escalares #

Rust es tipado estático: el tipo de cada variable se conoce en compilación. Los tipos escalares básicos:

TipoTamañoRango aproximado
i8/i16/i32/i64/i1281-16 bytesEnteros con signo
u8/u16/u32/u64/u1281-16 bytesEnteros sin signo
isize/usizeDepende de la plataformaTamaño del puntero
f32/f644/8 bytesComa flotante IEEE 754
bool1 bytetrue / false
char4 bytesUn codepoint Unicode completo

El tipo por defecto para enteros es i32 y para flotantes f64. Usa usize para índices de arrays y longitudes de colecciones.

El overflow aritmético tiene comportamiento distinto según el modo de compilación. En debug, un overflow provoca un panic (error en runtime). En release, hace wraparound silencioso (igual que en C). Si necesitas aritmética con overflow controlado en cualquier modo, usa los métodos explícitos:

rust 
let resultado = 255u8.wrapping_add(1); // 0, sin panic
let resultado = 255u8.saturating_add(1); // 255, satura en el máximo
let resultado = 255u8.checked_add(1); // None, retorna Option

El casting entre tipos numéricos se hace con as:

rust 
let x: i32 = 1000;
let y = x as u8; // 232, trunca sin error
let z = x as f64; // 1000.0

El cast con as trunca silenciosamente si el valor no cabe. Para conversiones seguras, usa TryFrom/TryInto que retornan Result.

Inferencia de tipos #

Rust infiere el tipo de una variable a partir del contexto. En la mayoría de casos, no necesitas anotarlo:

rust 
let x = 5;        // inferido: i32
let y = 3.14;     // inferido: f64
let activo = true; // inferido: bool
let letra = 'á';  // inferido: char

let numeros = vec![1, 2, 3]; // inferido: Vec<i32>

La inferencia funciona hacia adelante y hacia atrás en el bloque. Si más adelante usas la variable en un contexto que requiere un tipo concreto, el compilador lo usa para inferir el tipo inicial:

rust 
let mut coleccion = Vec::new(); // tipo desconocido por ahora
coleccion.push(42u64);         // ahora el compilador sabe: Vec<u64>

Cuando la inferencia no es posible, el compilador te pide que lo anotes explícitamente:

rust 
let coleccion: Vec<i32> = Vec::new(); // anotación necesaria aquí

Cuándo anotar el tipo explícitamente aunque el compilador pueda inferirlo:

  • Cuando el tipo tiene implicaciones de seguridad (un u32 vs i32 en un campo de edad).
  • Cuando la inferencia depende de un context lejano y hace el código menos legible.
  • En APIs públicas: los parámetros y retornos de funciones públicas siempre deben ser explícitos.

const y static #

Además de let, Rust tiene const y static para valores globales:

rust 
const MAX_CONEXIONES: u32 = 1000;
static PREFIJO_LOG: &str = "APP";

fn main() {
    println!("Máximo: {}", MAX_CONEXIONES);
    println!("Prefijo: {}", PREFIJO_LOG);
}

Las diferencias entre ambos son importantes:

conststatic
Tipo requeridoSíSí
Valor en memoriaSe inlínea en compilación (no tiene dirección de memoria fija)Tiene dirección de memoria fija durante toda la ejecución
Puede ser mutableNoSí, con static mut (unsafe)
Convención de nombreSCREAMING_SNAKE_CASESCREAMING_SNAKE_CASE

Usa const para valores conocidos en compilación que se usan en múltiples lugares. Usa static cuando necesites que el valor tenga una dirección de memoria fija (por ejemplo, para referencias 'static).

Shadowing #

Rust permite redeclarar una variable con el mismo nombre usando let. Esto se llama shadowing y es diferente de mut:

rust 
fn main() {
    let x = 5;
    let x = x + 1;   // x ahora es 6, shadowing del anterior x
    let x = x * 2;   // x ahora es 12

    println!("{}", x); // 12
}

La diferencia clave con mut: el shadowing permite cambiar el tipo de la variable, algo que mut no permite:

rust 
let espacios = "   ";      // &str
let espacios = espacios.len(); // usize, mismo nombre, tipo diferente

// Esto NO compila con mut:
let mut espacios = "   ";
espacios = espacios.len(); // error: tipos incompatibles

El shadowing es útil para transformar un valor paso a paso sin inventar nombres intermedios (espacios_str, espacios_len). La variable anterior queda inaccesible dentro del nuevo scope.

String vs &str #

La distinción entre String y &str confunde a casi todos los que llegan a Rust desde PHP. En PHP, una cadena es siempre mutable y su gestión de memoria es transparente. En Rust, existen dos tipos de cadena con propiedades muy distintas:

String&str
AlmacenamientoHeap (memoria dinámica)Puede ser stack, heap o código estático
MutabilidadMutable si es mutInmutable (es una referencia)
PropiedadEl dueño puede modificarla y soltarlaPrestada: apunta a un String o a un literal
CreaciónString::from("hola") o "hola".to_string()"hola" (literal) o &mi_string
rust 
let saludo: &str = "hola mundo";        // literal, vive en el binario
let nombre: String = String::from("Rust"); // heap, podemos crecer/mutar

let combinado = format!("{}, {}!", saludo, nombre); // String nuevo
println!("{}", combinado);

La regla práctica: usa &str en los parámetros de funciones cuando solo necesitas leer la cadena, y String cuando necesitas poseerla, modificarla o retornarla desde una función.

rust 
fn saludar(nombre: &str) -> String {
    format!("Hola, {}!", nombre)
}

Pasar &str en lugar de String como parámetro hace la función más flexible: acepta tanto &str literales como referencias a String existentes.

Errores típicos con tipos y variables

let mut por reflejo. Es la costumbre de PHP, pero quita la garantía de que el valor no cambia. El compilador avisa de los mut innecesarios: hazle caso.

Recibir &String en los parámetros. Obliga a quien llama a tener un String; con &str la función acepta literales y referencias a String por igual. Clippy lo señala.

Tratar un String como un array de caracteres. texto[0] no compila, porque en UTF-8 un carácter puede ocupar varios bytes, y len() cuenta bytes: "camión".len() es 7, como strlen en PHP. Para caracteres, .chars().count(), el equivalente a mb_strlen.

Convertir con as datos que vienen de fuera. Con let valor: i32 = 300;, valor as u8 da 44 sin avisar. Para entradas de usuario o de una API, u8::try_from(valor) devuelve un Result que te obliga a tratar el caso que no cabe.

Si dudas, empieza por lo más restrictivo (let, &str) y deja que el compilador te pida más: añadir un mut cuando hace falta cuesta un segundo; descubrir quién muta algo que no debía cuesta una tarde.

Resumen #

Lo que te llevas

  • Las variables son inmutables por defecto en Rust; la mutabilidad requiere let mut explícito.
  • Los tipos numéricos son explícitos: i32, u64, f64; el overflow en debug provoca panic, en release hace wraparound.
  • La inferencia de tipos cubre la mayoría de casos; las APIs públicas y situaciones ambiguas requieren anotación explícita.
  • const se inlínea en compilación; static tiene dirección de memoria fija durante toda la ejecución.
  • El shadowing permite redeclarar con let y cambiar el tipo; mut no permite cambiar el tipo.
  • String es un valor en heap que el dueño puede modificar; &str es una referencia inmutable a una cadena, más eficiente como parámetro de función.
