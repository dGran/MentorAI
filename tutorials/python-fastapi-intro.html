Qué es FastAPI y cuándo elegirlo

FastAPI es un framework web para construir APIs en Python. Su propuesta central es usar las anotaciones de tipo de Python directamente para validar las peticiones entrantes, serializar las respuestas y generar documentación interactiva, todo sin configuración adicional.

Internamente se apoya en dos librerías: Pydantic para la validación de datos y Starlette para la capa HTTP/ASGI. Es async-first: los handlers se definen con async def y el servidor (uvicorn) los ejecuta en un event loop, lo que permite manejar miles de conexiones concurrentes sin bloquear.

¿FastAPI, Flask o Django? Elige FastAPI cuando construyes una API pura, necesitas validación automática de input/output, quieres docs sin esfuerzo y el equipo ya conoce anotaciones de tipo. Elige Flask cuando el proyecto es pequeño, el equipo ya lo domina o necesitas flexibilidad máxima sin opiniones del framework. Elige Django cuando necesitas ORM, panel de administración, sistema de autenticación integrado y el ecosistema completo desde el primer día — su REST framework (DRF) añade soporte de API encima, pero es más verboso que FastAPI para ese caso de uso.
FastAPI Flask Django + DRF
Modelo de ejecución ASGI / async WSGI / sync WSGI / sync (ASGI opcional)
Validación automática Sí (Pydantic) No (manual o extensión) Sí (Serializers de DRF)
Docs interactivas Sí (sin config) No No (requiere Swagger UI manual)
ORM incluido No No Sí (Django ORM)
Panel de administración No No Sí

Tu primer endpoint

El entorno más reproducible es Docker. Estructura mínima del proyecto:

mi-api/
├── Dockerfile
├── requirements.txt
└── main.py

requirements.txt:

fastapi>=0.111.0
uvicorn[standard]>=0.29.0

Dockerfile:

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000", "--reload"]

main.py:

from fastapi import FastAPI

app = FastAPI(title="Mi API", version="1.0.0")


@app.get("/")
async def raiz() -> dict[str, str]:
    return {"mensaje": "Hola desde FastAPI"}

Para levantar el contenedor:

docker build -t mi-api .
docker run -p 8000:8000 -v $(pwd):/app mi-api

Con --reload, uvicorn detecta cambios en el código y recarga el servidor automáticamente. El volumen -v $(pwd):/app monta el directorio local dentro del contenedor para que los cambios sean instantáneos sin rebuilds.

Abre http://localhost:8000 y verás la respuesta JSON. Abre http://localhost:8000/docs y verás la documentación interactiva generada automáticamente.

Path params, query params y body

Path params. Los parámetros entre llaves en la ruta se convierten en parámetros del handler. FastAPI los convierte al tipo anotado y devuelve un 422 si la conversión falla:

from fastapi import FastAPI

app = FastAPI()


@app.get("/usuarios/{usuario_id}")
async def obtener_usuario(usuario_id: int) -> dict:
    return {"id": usuario_id, "nombre": "Ana"}


@app.get("/articulos/{slug}")
async def obtener_articulo(slug: str) -> dict:
    return {"slug": slug}

Query params. Los parámetros de función que no están en la ruta son automáticamente query params. Usa Query para añadir validaciones y valores por defecto:

from fastapi import FastAPI, Query

app = FastAPI()


@app.get("/articulos")
async def listar_articulos(
    pagina: int = Query(default=1, ge=1),
    tamanyo: int = Query(default=10, ge=1, le=100),
    categoria: str | None = Query(default=None),
) -> dict:
    return {
        "pagina": pagina,
        "tamanyo": tamanyo,
        "categoria": categoria,
    }

Una llamada a GET /articulos?pagina=2&tamanyo=20&categoria=python llega al handler con los valores ya convertidos a sus tipos. Si pagina=0, FastAPI rechaza la petición con un 422 detallado porque viola ge=1.

Request body. Un parámetro de tipo Pydantic BaseModel indica que el dato viene en el cuerpo de la petición como JSON. FastAPI valida la estructura y los tipos:

from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class CrearPedidoRequest(BaseModel):
    producto_id: int
    cantidad: int = Field(ge=1, le=1000)
    notas: str | None = None


@app.post("/pedidos", status_code=201)
async def crear_pedido(datos: CrearPedidoRequest) -> dict:
    return {
        "producto_id": datos.producto_id,
        "cantidad": datos.cantidad,
        "estado": "pendiente",
    }

Si el body enviado tiene cantidad: -5, FastAPI rechaza con 422 antes de llegar al handler. El modelo Pydantic documenta el schema esperado en las docs automáticas.

Response model con Pydantic

El response_model cumple dos funciones: documenta el schema de la respuesta en las docs automáticas y filtra los campos, asegurando que nunca se expone más de lo declarado aunque el handler devuelva un objeto más rico:

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class UsuarioInterno(BaseModel):
    id: int
    nombre: str
    email: str
    password_hash: str


class UsuarioPublico(BaseModel):
    id: int
    nombre: str
    email: str


USUARIOS: dict[int, UsuarioInterno] = {
    1: UsuarioInterno(
        id=1,
        nombre="Ana",
        email="ana@example.com",
        password_hash="$2b$12$abc123",
    )
}


@app.get("/usuarios/{usuario_id}", response_model=UsuarioPublico)
async def obtener_usuario(usuario_id: int) -> UsuarioInterno:
    return USUARIOS[usuario_id]

El handler devuelve un UsuarioInterno que incluye password_hash. FastAPI lo serializa contra UsuarioPublico y descarta el campo sensible. En el JSON de respuesta nunca aparece password_hash.

Para excluir campos opcionales cuando son None, usa response_model_exclude_none=True:

@app.get("/articulos/{slug}", response_model=ArticuloResponse, response_model_exclude_none=True)
async def obtener_articulo(slug: str) -> ArticuloResponse:
    pass
Pydantic v2 y model_config. FastAPI moderno usa Pydantic v2. Para que un modelo acepte objetos ORM (atributos en lugar de diccionario), añade model_config = ConfigDict(from_attributes=True) en la clase del modelo de respuesta.

Docs automáticas: Swagger y ReDoc

FastAPI genera dos interfaces de documentación sin ninguna configuración adicional:

  • /docs — Swagger UI. Permite explorar y ejecutar los endpoints directamente desde el navegador.
  • /redoc — ReDoc. Interfaz más limpia, ideal para compartir como documentación de referencia.

La documentación se enriquece con metadatos en la instancia de la app y en los decoradores de ruta:

from fastapi import FastAPI

app = FastAPI(
    title="API de Pedidos",
    description="Gestión de pedidos del sistema de e-commerce.",
    version="2.0.0",
    docs_url="/docs",
    redoc_url="/redoc",
)


@app.get(
    "/pedidos/{pedido_id}",
    summary="Obtener pedido por ID",
    description="Devuelve los datos completos de un pedido, incluyendo sus líneas.",
    response_description="Datos del pedido",
    tags=["pedidos"],
)
async def obtener_pedido(pedido_id: int) -> dict:
    return {"id": pedido_id}

Los tags agrupan los endpoints en secciones en la UI. El summary es la primera línea visible en el listado de rutas. La description admite Markdown.

Para desactivar las docs en producción (o cambiar su URL) pasa docs_url=None o redoc_url=None al construir la app. En entornos donde la API es interna y quieres evitar exponer el schema, es habitual desactivar ambas en producción y mantenerlas solo en local y staging.

import os
from fastapi import FastAPI

IS_PRODUCTION = os.getenv("ENVIRONMENT") == "production"

app = FastAPI(
    title="API de Pedidos",
    docs_url=None if IS_PRODUCTION else "/docs",
    redoc_url=None if IS_PRODUCTION else "/redoc",
)

Resumen

  • FastAPI usa las anotaciones de tipo de Python para validar requests, serializar responses y generar docs — todo del mismo código fuente, sin duplicar esquemas.
  • Pydantic valida el body automáticamente: si llega un campo con tipo incorrecto o fuera de rango, FastAPI devuelve un 422 con detalle del error sin que el handler llegue a ejecutarse.
  • response_model actúa como filtro de salida: solo los campos del modelo definido salen en la respuesta, aunque el handler devuelva un objeto más rico con datos sensibles.
  • Las docs en /docs (Swagger UI) y /redoc (ReDoc) se generan automáticamente a partir del código; summary, description y tags las enriquecen sin configuración externa.
  • FastAPI es async-first: usa async def para handlers que hacen I/O (BD, llamadas HTTP); def normal para handlers puramente síncronos o que llaman a código bloqueante.
  • Para APIs puras con validación automática y docs sin fricción, FastAPI es la opción más productiva; elige Django cuando necesites ORM, admin y el ecosistema completo desde el primer día.
