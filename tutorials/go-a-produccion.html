Go a producción: build, Docker y observabilidad

El superpower de Go en producción: un binario estático sin dependencias externas. Desplegarlo es copiar un fichero. La imagen Docker resultante puede ser de 10 MB con FROM scratch. Añade healthcheck, logging estructurado y métricas, y tienes un servicio listo.

Compilar para producción

Go compila a un binario estático: todas las dependencias se incrustan en él. No necesita runtime instalado, ni vendor, ni intérprete.

# Build básico para el OS actual
go build -o bin/servidor ./cmd/servidor

# Build para Linux desde Mac (cross-compilation)
GOOS=linux GOARCH=amd64 go build -o bin/servidor-linux ./cmd/servidor

# Build de producción: sin debug info, sin stack frames del linker
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
    go build -ldflags="-s -w" -o bin/servidor ./cmd/servidor

-s -w elimina la tabla de símbolos y la información de debug. El binario resultante es más pequeño (típicamente un 30% menos). CGO_ENABLED=0 desactiva CGo para garantizar el binario estático puro.

Incrustar la versión en el binario con ldflags:

VERSION=$(git describe --tags --always)
go build -ldflags="-s -w -X main.version=${VERSION}" ./cmd/servidor

// en main.go
var version = "dev"   // sobreescrito en build por ldflags

func main() {
    fmt.Println("versión:", version)
}

Dockerfile multistage

El patrón estándar para Go: compilar en una imagen con Go instalado, copiar solo el binario a una imagen mínima:

# Dockerfile
FROM golang:1.23-alpine AS builder

WORKDIR /app

# Copiar go.mod y go.sum primero (aprovecha la caché de Docker)
COPY go.mod go.sum ./
RUN go mod download

COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o servidor ./cmd/servidor


# Imagen final: solo el binario
FROM scratch

# Para hacer peticiones HTTPS: incluir certificados CA
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/

COPY --from=builder /app/servidor /servidor

EXPOSE 8080

ENTRYPOINT ["/servidor"]

Con FROM scratch la imagen tiene solo el binario y los certificados. Resultado típico: 10-15 MB frente a 500+ MB de una imagen PHP.

PHP en Docker

FROM php:8.3-fpm-alpine
# instalar extensiones, composer, dependencias...
# imagen final: ~200-500 MB
# necesita php-fpm + nginx

Go en Docker

FROM scratch
COPY servidor /servidor
# imagen final: ~10-15 MB
# el binario es el servidor

Configuración con variables de entorno

El patrón 12-factor: toda la configuración llega por variables de entorno. Sin ficheros de config que difieren entre entornos:

type Config struct {
    Puerto    string
    DatabaseURL string
    LogLevel  string
    Debug     bool
}

func cargarConfig() Config {
    return Config{
        Puerto:      getenv("PORT", "8080"),
        DatabaseURL: requireEnv("DATABASE_URL"),
        LogLevel:    getenv("LOG_LEVEL", "info"),
        Debug:       os.Getenv("DEBUG") == "true",
    }
}

func getenv(clave, porDefecto string) string {
    if v := os.Getenv(clave); v != "" {
        return v
    }
    return porDefecto
}

func requireEnv(clave string) string {
    v := os.Getenv(clave)

    if v == "" {
        log.Fatalf("variable de entorno requerida no definida: %s", clave)
    }

    return v
}

Logging estructurado

Go 1.21 introdujo log/slog: logging estructurado en JSON, listo para ingestarse en cualquier sistema de observabilidad:

import "log/slog"

func main() {
    // En producción: JSON para ingestar en Loki, Datadog, etc.
    logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
        Level: slog.LevelInfo,
    }))

    slog.SetDefault(logger)

    // Logs con campos estructurados
    slog.Info("servidor arrancado", "puerto", "8080")
    slog.Error("error de base de datos", "error", err, "query", sql)
    slog.Warn("latencia alta", "duracion_ms", 1500, "endpoint", "/api/productos")
}

Salida JSON:

{"time":"2026-07-05T10:30:00Z","level":"INFO","msg":"servidor arrancado","puerto":"8080"}
{"time":"2026-07-05T10:30:01Z","level":"ERROR","msg":"error de base de datos","error":"connection refused","query":"SELECT * FROM productos"}

Healthcheck y métricas

Dos endpoints que todo servicio en producción debe tener:

func registrarEndpointsSistema(mux *http.ServeMux, db *sql.DB) {
    // Healthcheck: para el orquestador (Kubernetes, Fly.io, etc.)
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        if err := db.PingContext(r.Context()); err != nil {
            http.Error(w, `{"status":"unhealthy"}`, http.StatusServiceUnavailable)
            return
        }
        w.Header().Set("Content-Type", "application/json")
        w.Write([]byte(`{"status":"ok"}`))
    })

    // Readiness: el servicio está listo para recibir tráfico
    mux.HandleFunc("GET /ready", func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("ok"))
    })

    // Métricas en formato Prometheus (con la lib expvar o pprof)
    mux.Handle("GET /metrics", expvar.Handler())
}

Para métricas más avanzadas, la librería estándar de facto es github.com/prometheus/client_golang. Pero para empezar, el paquete expvar de la stdlib expone variables en JSON sin dependencias.

Apagado graceful

func main() {
    cfg := cargarConfig()

    mux := http.NewServeMux()
    registrarRutas(mux)
    registrarEndpointsSistema(mux, db)

    servidor := &http.Server{
        Addr:         ":" + cfg.Puerto,
        Handler:      logger(mux),
        ReadTimeout:  5 * time.Second,
        WriteTimeout: 10 * time.Second,
        IdleTimeout:  120 * time.Second,
    }

    // Capturar señales del OS
    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
    defer stop()

    go func() {
        slog.Info("servidor arrancado", "puerto", cfg.Puerto)

        if err := servidor.ListenAndServe(); !errors.Is(err, http.ErrServerClosed) {
            slog.Error("servidor caído inesperadamente", "error", err)
            os.Exit(1)
        }
    }()

    <-ctx.Done()
    slog.Info("apagando servidor...")

    shutdownCtx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    if err := servidor.Shutdown(shutdownCtx); err != nil {
        slog.Error("error en el apagado", "error", err)
        os.Exit(1)
    }

    slog.Info("servidor apagado correctamente")
}

Resumen

  • CGO_ENABLED=0 go build -ldflags="-s -w" produce un binario estático sin dependencias externas, listo para copiar a cualquier servidor.
  • Dockerfile multistage: compila en golang:alpine, copia solo el binario a FROM scratch. Imagen final de ~10-15 MB.
  • Toda la configuración por variables de entorno (12-factor). Usa log.Fatalf para las requeridas si no están presentes.
  • log/slog (Go 1.21+) para logging estructurado en JSON. Campos con slog.Info("msg", "key", value).
  • Expón siempre /health (comprueba dependencias) y /ready (el proceso está vivo). Configura ReadTimeout, WriteTimeout e IdleTimeout.
  • signal.NotifyContext + server.Shutdown para apagado graceful: las peticiones activas terminan antes de matar el proceso.
