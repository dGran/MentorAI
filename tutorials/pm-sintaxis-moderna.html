Sintaxis moderna: match, argumentos con nombre y callables

Un switch que trata un null como un cero, una llamada con tres booleanos seguidos que nadie sabe leer, un 'trim' entre comillas que el IDE no puede seguir. PHP 8 trajo sintaxis que cierra esos huecos; lo que importa es saber qué te compra cada pieza y qué te cuesta.

Cada construcción de esta lección elimina una clase concreta de fallo o de ruido, y cada una tiene un caso en el que conviene no usarla. Partimos de donde acaban Tipos de clases en PHP y el tipado estricto.

Código que dice menos de lo que hace #

Mucho PHP heredado funciona, pero esconde la intención. Tres síntomas habituales:

  • Un switch compara con ==: un valor que no esperabas cae en un caso que no le toca, o en el default, sin que nada avise.
  • createUser('ana@example.com', false, true, true) obliga a abrir la firma para saber qué es cada true.
  • array_map('trim', $lines) pasa una función como texto: el motor solo comprueba que existe cuando la llama, y un renombrado automático no la sigue.

El porqué es el mismo en los tres casos: el lenguaje no podía expresar la intención, así que vivía en la cabeza de quien escribió el código. La sintaxis moderna la mueve al código, donde la comprueban el motor y PHPStan.

match frente a switch #

switch es una sentencia: ejecuta ramas, compara con == y, si olvidas un break, sigue con el caso siguiente. match (PHP 8.0) es una expresión: devuelve un valor, compara con ===, no tiene caída entre brazos y, si ningún brazo encaja, lanza UnhandledMatchError.

Con un descuento que aún no se ha calculado, switch da por bueno el primer caso:

php · antes: switch 
<?php

declare(strict_types=1);

$percentage = null;

switch ($percentage) {
    case 0:
        $label = 'Sin descuento';
        break;
    case 10:
        $label = 'Cliente habitual';
        break;
    default:
        $label = 'Promoción';
}

echo $label, PHP_EOL;

Imprime «Sin descuento», porque null == 0 es cierto. El dato que faltaba se ha convertido en un dato válido y nadie se ha enterado. La versión con match:

php · después: match 
<?php

declare(strict_types=1);

function discountLabel(?int $percentage): string
{
    return match ($percentage) {
        0 => 'Sin descuento',
        10 => 'Cliente habitual',
        20, 30 => 'Promoción',
    };
}

echo discountLabel(10), PHP_EOL;

try {
    echo discountLabel(null), PHP_EOL;
} catch (UnhandledMatchError $exception) {
    echo $exception->getMessage(), PHP_EOL;
}

La primera llamada imprime «Cliente habitual»; la segunda lanza la excepción, que en PHP 8.5 dice Unhandled match case of type null. El fallo sale donde nace, no tres pantallas después. Para rangos, match (true) con una condición en cada brazo.

No pongas default por reflejo

Un default convierte el error ruidoso en un valor silencioso, justo lo que match venía a evitar. Ponlo solo cuando de verdad exista un «todo lo demás». Con enums es aún más claro: sin default, el análisis estático puede avisarte de que falta un caso cuando añades uno nuevo.

Argumentos con nombre y su precio #

Desde PHP 8.0 puedes pasar un argumento por el nombre de su parámetro. Ganas dos cosas: la llamada se explica sola y te saltas opcionales sin repetir sus valores por defecto.

php · argumentos con nombre 
<?php

declare(strict_types=1);

function createUser(
    string $email,
    bool $isAdmin = false,
    bool $shouldSendWelcome = true,
    bool $isVerified = false,
): string {
    return sprintf('%s admin=%d welcome=%d verified=%d', $email, $isAdmin, $shouldSendWelcome, $isVerified);
}

echo createUser('ana@example.com', false, true, true), PHP_EOL;
echo createUser('ana@example.com', isVerified: true), PHP_EOL;

Las dos llamadas hacen lo mismo; solo la segunda se entiende sin abrir la función. Reglas: los posicionales van primero (uno detrás de un nombrado es un error de compilación) y un nombre que no existe lanza Error: Unknown named parameter $x al ejecutar.

El nombre del parámetro ya es API

Antes de PHP 8, renombrar $limit a $max era un cambio interno. Ahora cualquier llamante puede haber escrito limit: 10, así que el renombrado rompe su código. Y la herencia lo agrava: si una clase hija cambia el nombre, PHP no protesta al declararla; falla la llamada que use el nombre del padre.

php · renombrar en la clase hija 
<?php

declare(strict_types=1);

class ReportExporter
{
    public function export(int $limit): string
    {
        return "Exportando {$limit} filas";
    }
}

final class CsvReportExporter extends ReportExporter
{
    public function export(int $max): string
    {
        return "CSV con {$max} filas";
    }
}

function runExport(ReportExporter $exporter): string
{
    return $exporter->export(limit: 100);
}

echo runExport(new ReportExporter()), PHP_EOL;

try {
    echo runExport(new CsvReportExporter()), PHP_EOL;
} catch (Error $exception) {
    echo $exception->getMessage(), PHP_EOL;
}

La segunda llamada imprime Unknown named parameter $limit. runExport cumple el contrato del padre y aun así falla con la hija.

En una librería pública, renombrar es un cambio incompatible

Si publicas un paquete, los nombres de los parámetros públicos entran en tu contrato de versionado semántico: cambiarlos pide versión mayor. En código interno el IDE encuentra los llamantes, pero al sobrescribir un método conserva el nombre.

Callables de primera clase #

Antes, para pasar una función se usaban 'trim', [$this, 'normalize'] o Closure::fromCallable(). Los dos primeros son callables por convención: un texto y un array que solo se comprueban al llamarlos. PHP 8.1 añadió trim(...): los tres puntos literales crean un Closure en ese punto, y si la función o el método no existe, falla ahí mismo con Call to undefined function, no más tarde dentro de array_map.

php · antes y después 
<?php

declare(strict_types=1);

final class TagNormalizer
{
    public function normalize(string $tag): string
    {
        return strtolower(trim($tag));
    }

    public function normalizeAllTheOldWay(array $tags): array
    {
        return array_map([$this, 'normalize'], $tags);
    }

    public function normalizeAll(array $tags): array
    {
        return array_map($this->normalize(...), $tags);
    }
}

$normalizer = new TagNormalizer();
$tags = [' PHP ', 'Rector', ' phpstan'];

var_dump($normalizer->normalizeAllTheOldWay($tags) === $normalizer->normalizeAll($tags));
var_dump(strlen(...) instanceof Closure);
echo implode(',', $normalizer->normalizeAll($tags)), PHP_EOL;

Para un IDE o para PHPStan, $this->normalize(...) es una referencia real al método: la siguen al renombrar y comprueban sus tipos. Dos límites: no se combina con nullsafe ($user?->name(...) no compila) ni con new (new Foo(...) tampoco).

El operador nullsafe #

?-> (PHP 8.0) evalúa el lado izquierdo y, si es null, corta la cadena entera y devuelve null. Sustituye la escalera de if ($x !== null) cuando un dato es opcional de verdad.

php · nullsafe 
<?php

declare(strict_types=1);

final class Address
{
    public function __construct(public readonly string $city) {}
}

final class Customer
{
    public function __construct(private readonly ?Address $address) {}

    public function address(): ?Address
    {
        return $this->address;
    }
}

function shippingCity(?Customer $customer): string
{
    return $customer?->address()?->city ?? 'Sin dirección';
}

echo shippingCity(new Customer(new Address('Valencia'))), PHP_EOL;
echo shippingCity(new Customer(null)), PHP_EOL;
echo shippingCity(null), PHP_EOL;

Ojo con el «entera»: en $a?->b()->c(), si $a es null no se llama a nada más; pero si b() devuelve null, ->c() sí falla, porque esa flecha no es nullsafe. Tampoco sirve para escribir: $a?->b = 1 no compila.

Spread con claves de texto #

El operador ... desempaqueta un array. Desde PHP 8.1 también acepta claves de texto dentro de un array literal, con la semántica de array_merge: si una clave se repite, gana la última; las numéricas se renumeran. En una llamada, cada clave de texto se convierte en un argumento con nombre.

php · spread 
<?php

declare(strict_types=1);

$defaults = ['timeout' => 5, 'retries' => 3];
$overrides = ['timeout' => 10];

$options = [...$defaults, ...$overrides];
var_dump($options);

function connect(string $host, int $timeout = 5, int $retries = 3): string
{
    return "{$host} timeout={$timeout} retries={$retries}";
}

echo connect('db.local', ...$overrides), PHP_EOL;

try {
    echo connect('db.local', ...['timeout' => 10, 'verbose' => 1]), PHP_EOL;
} catch (Error $exception) {
    echo $exception->getMessage(), PHP_EOL;
}

La última llamada lanza Unknown named parameter $verbose. Es el mismo coste de antes con otra cara: un array de configuración desempaquetado en una llamada queda atado a los nombres de los parámetros.

Funciones flecha: captura por valor #

fn ($x) => expresión tiene una sola expresión, devuelve su valor y captura sola las variables del ámbito exterior, sin use. Lo importante es cómo las captura: por valor y en el momento de crearse. No puede modificar la variable de fuera y no ve cambios posteriores.

php · captura por valor 
<?php

declare(strict_types=1);

$amounts = [10, 20, 30];
$taxRate = 0.21;
$withTax = fn (float $price): float => round($price * (1 + $taxRate), 2);
$taxRate = 0.10;

echo $withTax(100.0), PHP_EOL;

$total = 0;
array_map(fn (int $amount): int => $total += $amount, $amounts);
echo $total, PHP_EOL;

$total = 0;
array_walk($amounts, function (int $amount) use (&$total): void {
    $total += $amount;
});
echo $total, PHP_EOL;

echo array_sum($amounts), PHP_EOL;

Imprime 121, 0, 60 y 60. La flecha usó el 21 % que había al crearla, y su $total += ... sumó sobre una copia. Para acumular, una función normal con use (&$total) funciona, pero casi siempre hay algo mejor: array_sum o array_reduce, que no dependen de estado de fuera.

new en inicializadores #

Desde PHP 8.1, new se admite en valores por defecto de parámetros, argumentos de attributes, variables estáticas y constantes globales. En propiedades y constantes de clase sigue sin estar permitido: PHP responde New expressions are not supported in this context.

El uso que más rinde es una dependencia opcional con un valor por defecto que no hace nada, sin el clásico ?Logger $logger = null seguido de $logger ?? new NullLogger():

php · antes y después 
<?php

declare(strict_types=1);

interface Logger
{
    public function info(string $message): void;
}

final class NullLogger implements Logger
{
    public function info(string $message): void {}
}

final class EchoLogger implements Logger
{
    public function info(string $message): void
    {
        echo $message, PHP_EOL;
    }
}

final class LegacyImporter
{
    private Logger $logger;

    public function __construct(?Logger $logger = null)
    {
        $this->logger = $logger ?? new NullLogger();
    }

    public function import(): void
    {
        $this->logger->info('Importación antigua');
    }
}

final class Importer
{
    public function __construct(private readonly Logger $logger = new NullLogger()) {}

    public function import(): void
    {
        $this->logger->info('Importación terminada');
    }
}

(new LegacyImporter())->import();
(new Importer())->import();
(new Importer(new EchoLogger()))->import();

Solo la última línea imprime algo. La propiedad deja de ser anulable y desaparece una rama. Sigue siendo inyección de dependencias: el valor por defecto solo cubre a quien no pasa nada, y un contenedor que conozca Logger seguirá inyectando el real.

El operador pipe de PHP 8.5 #

PHP 8.5 añade |>: pasa el valor de la izquierda como único argumento al callable de la derecha. Con los callables de primera clase, las llamadas anidadas, que se leen de dentro afuera, pasan a leerse en orden.

php · solo PHP 8.5 
<?php

declare(strict_types=1);

$title = '  Sintaxis Moderna en PHP  ';

$nested = str_replace(' ', '-', strtolower(trim($title)));

$piped = $title
    |> trim(...)
    |> strtolower(...)
    |> (fn (string $text): string => str_replace(' ', '-', $text));

var_dump($nested === $piped);
echo $piped, PHP_EOL;

Una función flecha a la derecha de |> va entre paréntesis; sin ellos PHP 8.5 da un error de compilación. Si tu proyecto aún soporta PHP 8.4, el operador es un error de sintaxis allí: espera a que la versión mínima de tu composer.json sea 8.5.

Errores típicos #

Lo que se cuela en las revisiones

  • Desempaquetar la petición en un constructor. new Filter(...$request->query->all()) deja que el cliente elija qué parámetros rellenar y cuáles hacen saltar un Error. Mapea los campos a mano.
  • Un default en cada match. Reproduce el silencio del switch.
  • Encadenar ?-> sobre datos obligatorios. Si el pedido siempre tiene cliente, un null ahí es un fallo que conviene ver, no un caso que tapar.
  • Acumular dentro de una función flecha. Suma sobre una copia y el resultado se pierde sin aviso.
  • Renombrar un parámetro al sobrescribir un método. Rompe a quien llame con el nombre del padre.

Cómo comprobarlo #

Casi todos estos fallos saltan al compilar o en la primera ejecución: basta un lint contra tu versión mínima y los tests de siempre.

bash · terminal 
php -v
php -l src/Importer.php
find src -name '*.php' -print0 | xargs -0 -n1 php -l

Si desarrollas con PHP 8.5 pero soportas 8.4, pasa el lint con un 8.4 en tu pipeline de CI: tu máquina no detecta un |> colado. Lo que el lint no ve, como un argumento con nombre que no existe, lo ve el análisis estático; lo tratamos en PHPStan. Y para migrar switch o Closure::fromCallable en bloque, Rector lo hace por ti.

Cuándo aplicarlo #

Úsalo cuando…

  • match: cada caso produce un valor y un caso desconocido es un error
  • Argumentos con nombre: hay booleanos u opcionales que quieres saltar
  • f(...): pasas una función o un método como callback
  • ?->: el dato es opcional por diseño
  • new por defecto: la dependencia tiene un sustituto que no hace nada

Mejor no cuando…

  • Cada rama ejecuta varias sentencias con efectos: un switch o una tabla de handlers se leen mejor
  • Llamas a una librería que no promete estabilidad en los nombres de parámetros
  • La función flecha necesita modificar estado exterior
  • El null indica un fallo que debería verse
  • Tu versión mínima es anterior a la de la sintaxis

La alternativa sencilla

Si una función pide tres booleanos con nombre para leerse, quizá el problema es la firma: un enum o un objeto de opciones dice lo mismo sin atar a nadie a los nombres de los parámetros. La sintaxis moderna aclara el diseño, no lo sustituye.

Resumen #

Lo que te llevas

  • match compara con ===, devuelve un valor y lanza UnhandledMatchError si nada encaja. No lo silencies con un default por reflejo.
  • Con argumentos con nombre, el nombre del parámetro es parte de la API: renombrarlo, también en una clase hija, rompe llamantes.
  • trim(...) y $this->metodo(...) crean un Closure que el IDE y PHPStan siguen; los callables en texto no.
  • ?-> corta toda la cadena si encuentra null; resérvalo para datos opcionales de verdad.
  • Las funciones flecha capturan por valor al crearse: no acumulan ni ven cambios posteriores.
  • new en un valor por defecto elimina el parámetro anulable de las dependencias opcionales; |> solo existe desde PHP 8.5.
