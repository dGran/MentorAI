Serde: el framework de serialización

Serde es el framework de serialización y deserialización de Rust. Soporta JSON, TOML, YAML, MessagePack, Bincode y decenas de formatos más, todos con la misma API. Es la crate más descargada del ecosistema Rust.

use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug)]
struct Producto {
    id: u32,
    nombre: String,
    precio: f64,
    disponible: bool,
}

fn main() {
    let producto = Producto {
        id: 1,
        nombre: "Teclado mecánico".to_string(),
        precio: 89.99,
        disponible: true,
    };

    let json = serde_json::to_string(&producto).unwrap();
    println!("{}", json);
    // {"id":1,"nombre":"Teclado mecánico","precio":89.99,"disponible":true}

    let producto2: Producto = serde_json::from_str(&json).unwrap();
    println!("{:?}", producto2);
}

El #[derive(Serialize, Deserialize)] genera el código de serialización en compilación. No hay reflexión en runtime como en PHP: el compilador genera código especializado para cada tipo, con el rendimiento resultante.

Para JSON dinámico (cuando no conoces la estructura), usa serde_json::Value:

use serde_json::{json, Value};

fn main() {
    let valor: Value = json!({
        "nombre": "Rust",
        "version": 2021,
        "features": ["seguro", "rápido", "concurrente"]
    });

    println!("{}", valor["nombre"]); // Rust
    println!("{}", valor["version"].as_u64().unwrap()); // 2021
}

Atributos de Serde

Serde tiene un sistema de atributos para personalizar la serialización sin código adicional, equivalente a las anotaciones del Symfony Serializer:

use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize)]
struct UsuarioApi {
    #[serde(rename = "userId")]
    id: u32,

    #[serde(rename = "fullName")]
    nombre_completo: String,

    #[serde(skip_serializing_if = "Option::is_none")]
    email: Option<String>,

    #[serde(default)]
    activo: bool,

    #[serde(skip)]
    password_hash: String,
}
  • #[serde(rename = "nombre")]: nombre distinto en JSON. Útil para APIs que usan camelCase mientras el código Rust usa snake_case.
  • #[serde(skip_serializing_if = "Option::is_none")]: omite el campo en el JSON cuando es None, en lugar de serializar null.
  • #[serde(default)]: usa el valor por defecto del tipo si el campo no está en el JSON de entrada.
  • #[serde(skip)]: excluye el campo de la serialización y deserialización completamente.

Para renombrar todos los campos automáticamente de snake_case a camelCase:

#[derive(Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
struct PerfilUsuario {
    nombre_usuario: String, // serializa como "nombreUsuario"
    fecha_creacion: String, // serializa como "fechaCreacion"
}

sqlx: queries async tipadas

sqlx es la librería de acceso a base de datos más usada en Rust async. A diferencia de un ORM como Doctrine, sqlx trabaja con SQL directamente. Su característica diferencial: verifica las queries contra el esquema de la base de datos en tiempo de compilación.

use sqlx::postgres::PgPoolOptions;
use sqlx::PgPool;

#[derive(sqlx::FromRow, Debug)]
struct Usuario {
    id: i32,
    nombre: String,
    email: String,
    activo: bool,
}

async fn crear_pool() -> PgPool {
    PgPoolOptions::new()
        .max_connections(10)
        .connect("postgres://usuario:password@localhost/mi_bd")
        .await
        .expect("No se pudo conectar a la base de datos")
}

El trait sqlx::FromRow permite que sqlx mapee las filas de un resultado al struct automáticamente. Los nombres de los campos del struct deben coincidir con los alias de la columna en la query (o usar #[sqlx(rename = "nombre")]).

Cargo.toml:

[dependencies]
sqlx = { version = "0.7", features = ["postgres", "runtime-tokio-rustls", "macros"] }

sqlx::query_as! y fetch

sqlx ofrece dos formas de ejecutar queries:

Sin verificación de compilación (más flexible):

async fn obtener_usuarios(pool: &PgPool) -> Result<Vec<Usuario>, sqlx::Error> {
    sqlx::query_as::<_, Usuario>("SELECT id, nombre, email, activo FROM usuarios")
        .fetch_all(pool)
        .await
}

Con verificación de compilación (la macro query_as! necesita DATABASE_URL en el entorno al compilar):

async fn obtener_usuario(pool: &PgPool, id: i32) -> Result<Option<Usuario>, sqlx::Error> {
    sqlx::query_as!(
        Usuario,
        "SELECT id, nombre, email, activo FROM usuarios WHERE id = $1",
        id
    )
    .fetch_optional(pool)
    .await
}

async fn crear_usuario(pool: &PgPool, nombre: &str, email: &str) -> Result<i32, sqlx::Error> {
    let resultado = sqlx::query!(
        "INSERT INTO usuarios (nombre, email) VALUES ($1, $2) RETURNING id",
        nombre,
        email
    )
    .fetch_one(pool)
    .await?;

    Ok(resultado.id)
}

Los métodos de fetch:

  • .fetch_one(pool): exactamente una fila o error.
  • .fetch_optional(pool): cero o una fila (Option<T>).
  • .fetch_all(pool): todas las filas (Vec<T>).
  • .execute(pool): ejecuta sin retornar filas (INSERT, UPDATE, DELETE).

Transacciones

async fn transferir(
    pool: &PgPool,
    origen_id: i32,
    destino_id: i32,
    cantidad: f64,
) -> Result<(), sqlx::Error> {
    let mut transaccion = pool.begin().await?;

    sqlx::query!(
        "UPDATE cuentas SET saldo = saldo - $1 WHERE id = $2",
        cantidad,
        origen_id
    )
    .execute(&mut *transaccion)
    .await?;

    sqlx::query!(
        "UPDATE cuentas SET saldo = saldo + $1 WHERE id = $2",
        cantidad,
        destino_id
    )
    .execute(&mut *transaccion)
    .await?;

    transaccion.commit().await?;

    Ok(())
}

La transacción se revierte automáticamente si se hace drop de ella sin llamar a .commit(). Si alguna de las queries falla y el operador ? hace un early return, la transacción sale de scope y se hace rollback automático. Este es el patrón RAII aplicado a transacciones de base de datos.

Patrón Repository en Rust

El patrón Repository separa la lógica de acceso a datos del resto del dominio. En Rust, se implementa con un trait que define el contrato y una implementación concreta sobre el pool:

use async_trait::async_trait;
use std::sync::Arc;

#[async_trait]
pub trait UsuarioRepository: Send + Sync {
    async fn buscar_por_id(&self, id: i32) -> Result<Option<Usuario>, sqlx::Error>;
    async fn buscar_todos(&self) -> Result<Vec<Usuario>, sqlx::Error>;
    async fn guardar(&self, nombre: &str, email: &str) -> Result<i32, sqlx::Error>;
}

pub struct SqlxUsuarioRepository {
    pool: PgPool,
}

impl SqlxUsuarioRepository {
    pub fn new(pool: PgPool) -> Self {
        Self { pool }
    }
}

#[async_trait]
impl UsuarioRepository for SqlxUsuarioRepository {
    async fn buscar_por_id(&self, id: i32) -> Result<Option<Usuario>, sqlx::Error> {
        sqlx::query_as::<_, Usuario>(
            "SELECT id, nombre, email, activo FROM usuarios WHERE id = $1"
        )
        .bind(id)
        .fetch_optional(&self.pool)
        .await
    }

    async fn buscar_todos(&self) -> Result<Vec<Usuario>, sqlx::Error> {
        sqlx::query_as::<_, Usuario>("SELECT id, nombre, email, activo FROM usuarios")
            .fetch_all(&self.pool)
            .await
    }

    async fn guardar(&self, nombre: &str, email: &str) -> Result<i32, sqlx::Error> {
        let row = sqlx::query!("INSERT INTO usuarios (nombre, email) VALUES ($1, $2) RETURNING id", nombre, email)
            .fetch_one(&self.pool)
            .await?;
        Ok(row.id)
    }
}

struct AppState {
    usuarios: Arc<dyn UsuarioRepository>,
}

La crate async_trait es necesaria porque los traits con métodos async no son directamente estables en Rust todavía. Añade el boilerplate de Box<dyn Future> automáticamente.

Para tests: el trait UsuarioRepository permite crear una implementación fake en memoria para tests unitarios, sin tocar la base de datos. Esto es el equivalente a mockear el repositorio en PHP.

Resumen

  • Serde genera código de serialización en compilación con #[derive(Serialize, Deserialize)]. Soporta docenas de formatos con la misma API.
  • Los atributos #[serde(...)] personalizan la serialización por campo: rename, skip, default, skip_serializing_if. Equivalentes a las anotaciones del Symfony Serializer.
  • sqlx ejecuta queries SQL async con el pool de conexiones. La macro query_as! verifica la query contra el esquema de BD en compilación.
  • Las transacciones usan RAII: si la transacción sale de scope sin commit, se hace rollback automático. El operador ? en early return garantiza esto.
  • El patrón Repository en Rust usa un trait con #[async_trait] para definir el contrato y una implementación concreta sobre PgPool. El trait permite implementaciones fake para tests.
