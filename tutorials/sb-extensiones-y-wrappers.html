Extensiones, wrappers, GraphQL y Vault

Supabase es Postgres, y Postgres tiene un ecosistema de extensiones enorme. Algunas cambian lo que puedes hacer sin salir de SQL: preguntar a Stripe con un select, guardar claves cifradas, exponer una API GraphQL o buscar con faltas de ortografía. Esta lección recorre las que más rendimiento dan.

Ya usaste pg_net, pg_cron, pgmq y pgvector en lecciones anteriores. Aquí van las piezas restantes que completan el mapa: extensiones de búsqueda y rendimiento, GraphQL, Vault y los wrappers que convierten servicios externos en tablas.

Extensiones que se ganan su sitio #

Se activan en Database → Extensions (o con create extension ... with schema extensions en una migración). Más allá de las ya vistas, estas aparecen a menudo:

ExtensiónQué resuelveEjemplo
pg_trgmSimilitud de texto por trigramas: búsqueda tolerante a errataswhere title % 'recta' encuentra «receta»
unaccentQuitar tildes al compararBuscar «camion» y encontrar «camión»
postgisGeometría y geografía: distancias, áreas, cercaníaNotas a menos de 5 km de un punto
pg_jsonschemaValidar un jsonb contra un JSON Schema en un checkQue la configuración de una libreta tenga la forma correcta
index_advisorSugerir índices para una consulta concretaVer abajo
hypopgÍndices hipotéticos: ver si el planificador los usaría sin crearlosLo usa index_advisor
pg_stat_statementsEstadísticas de cada consultaLa base de los informes de rendimiento
pgauditRegistro de auditoría de lo que se ejecutaRequisitos de cumplimiento normativo
sql · búsqueda con erratas en títulos 
create extension if not exists pg_trgm with schema extensions;

create index on public.notes using gin (title extensions.gin_trgm_ops);

select id, title
from public.notes
where title operator(extensions.%) 'recta de pan'
order by extensions.similarity(title, 'recta de pan') desc
limit 10;
sql · qué índice le falta a esta consulta 
select * from extensions.index_advisor(
  'select id, title from public.notes where notebook_id = 42 order by created_at desc'
);

index_advisor devuelve el create index recomendado y el coste estimado antes y después. Es una sugerencia del planificador, no una orden: comprueba con explain analyze que la consulta real mejora, como cuenta Índices en la práctica.

GraphQL con pg_graphql #

Además de REST, Supabase puede exponer tu esquema como GraphQL con la extensión pg_graphql, en https://<ref>.supabase.co/graphql/v1. Igual que PostgREST, lo genera leyendo tablas, relaciones y funciones, y respeta los permisos y RLS de Postgres.

bash · una consulta GraphQL con curl 
curl "https://abcdefghijklmnop.supabase.co/graphql/v1" \
  -H "apikey: sb_publishable_xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"query": "{ notesCollection(first: 10) { edges { node { id title } } } }"}'

Si en tu proyecto no está activa, se activa con create extension pg_graphql. ¿Cuándo usarla en lugar de la Data API? Si tu frontend ya está construido sobre un cliente GraphQL (Apollo, urql, Relay) o necesita su sistema de tipos y paginación por conexiones. Si no, la Data API REST hace lo mismo con menos piezas; REST, RPC y GraphQL compara los tres estilos.

Vault: secretos dentro de la base de datos #

Hay secretos que la propia base de datos necesita: la clave con la que Cron llama a una función, la API key de un wrapper. Escribirlos en el texto de una función o de una tarea los deja en claro en el esquema, en los backups y en los logs. Vault los guarda cifrados:

sql · guardar y leer un secreto 
select vault.create_secret('re_xxxxxxxx', 'resend_api_key', 'Clave de Resend para emails');

select decrypted_secret from vault.decrypted_secrets where name = 'resend_api_key';

Los secretos se guardan cifrados en vault.secrets; la clave de cifrado no está en la base de datos, así que un volcado no los expone. La vista vault.decrypted_secrets los descifra al leerla y solo pueden consultarla roles privilegiados: nunca la expongas por la API ni la uses desde funciones security definer que pueda llamar cualquiera.

Foreign Data Wrappers: servicios externos como tablas #

Un Foreign Data Wrapper (FDW) hace que una fuente externa parezca una tabla de Postgres: haces select y el wrapper traduce la consulta a llamadas a la API de turno. Supabase mantiene Wrappers, una colección de FDW para Stripe, Firebase, S3, BigQuery, ClickHouse, Airtable, Notion y otros.

sql · los clientes de Stripe, consultables con SQL 
create extension if not exists wrappers with schema extensions;

create foreign data wrapper stripe_wrapper
  handler stripe_fdw_handler
  validator stripe_fdw_validator;

create server stripe_server
  foreign data wrapper stripe_wrapper
  options (api_key_id '<id del secreto en Vault>');

create schema if not exists stripe;

import foreign schema stripe from server stripe_server into stripe;

select id, email, created from stripe.customers limit 10;

La clave de Stripe va en Vault y el servidor la referencia por su id. A partir de ahí puedes cruzar datos externos con los tuyos: tus usuarios con sus suscripciones en Stripe en un solo join.

Dos trampas de los wrappers

Cada consulta es una llamada a la API externa: latencia, límites de peticiones del proveedor y, en algunos, coste. Para datos que se consultan a menudo, cópialos a una vista materializada que una tarea de Cron refresca. Y las tablas externas no tienen RLS: nunca pongas el esquema del wrapper entre los esquemas expuestos por la API, o cualquiera con la clave publicable leería tus clientes de Stripe. Déjalo en un esquema privado y accede desde funciones o desde el servidor.

Automatizar el proyecto: API de gestión y MCP #

Todo lo que haces en el panel (crear proyectos, cambiar ajustes, ver logs, ejecutar SQL) está también en la Management API, una API HTTP autenticada con un token personal o de organización. La CLI la usa por debajo, y te sirve para scripts de aprovisionamiento o para crear un proyecto por cliente en una app multiinquilino.

Supabase ofrece además un servidor MCP que deja a un agente de IA (Claude Code, Cursor y otros) consultar el esquema, ejecutar SQL, leer logs y crear migraciones de tu proyecto. Es muy útil para desarrollar, y peligroso si se conecta donde no debe. Si no has usado MCP, MCP en Claude Code explica cómo funciona.

Un agente con acceso a producción

Un agente que puede ejecutar SQL en tu base de datos de producción puede borrar datos por un malentendido, y lee contenido de tus tablas que podría contener instrucciones maliciosas escritas por un usuario. Conecta el servidor MCP a un proyecto de desarrollo, en modo solo lectura cuando no necesites escribir, y limitado a un único proyecto.

Resumen #

Lo que te llevas

  • pg_trgm busca con erratas, index_advisor sugiere índices y pg_jsonschema valida jsonb: extensiones que se activan en el esquema extensions.
  • pg_graphql expone el esquema como GraphQL en /graphql/v1 respetando RLS; solo compensa si tu frontend ya vive en GraphQL.
  • Vault guarda secretos cifrados que la base de datos necesita, legibles solo por roles privilegiados.
  • Los Wrappers convierten Stripe, S3 o BigQuery en tablas: cada consulta es una llamada externa y no tienen RLS, así que van en un esquema privado.
  • La Management API automatiza lo que haces en el panel; el servidor MCP da acceso a agentes de IA, siempre contra desarrollo y en solo lectura.
