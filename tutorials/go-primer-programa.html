Estructura de un fichero Go

Todo fichero Go empieza igual: declaración de paquete, imports y código. No hay opciones, no hay variantes.

package main   // 1. a qué paquete pertenece este fichero

import "fmt"   // 2. qué paquetes usa

func main() {  // 3. el punto de entrada del programa
    fmt.Println("Hola, mundo")
}

Tres reglas que el compilador impone sin negociación:

  1. Todos los imports deben usarse. Si importas "fmt" y no usas ninguna de sus funciones, el programa no compila. No es un warning: es un error.
  2. Todas las variables declaradas deben usarse. Misma regla. Declarar y no usar es un error de compilación.
  3. El punto de entrada es siempre func main() en el paquete main. Sin excepciones.

Estas restricciones son deliberadas: eliminan ruido del código antes de que llegue a revisión.

Hola, mundo

Crea el módulo y el primer fichero dentro del contenedor:

docker compose run --rm app bash

# dentro del contenedor:
mkdir /tmp/hola && cd /tmp/hola
go mod init hola               # crea go.mod con module hola

cat > main.go <<'EOF'
package main

import "fmt"

func main() {
    fmt.Println("Hola, mundo")
    fmt.Printf("2 + 2 = %d\n", 2+2)
}
EOF

go mod init crea el fichero go.mod, que es la declaración del módulo (equivale a composer.json pero más simple). El argumento es el nombre del módulo.

go run vs go build

go run

go run main.go
# Hola, mundo
# 2 + 2 = 4

Compila en memoria y ejecuta directamente. No deja ningún fichero en disco. Ideal para desarrollo y pruebas rápidas.

go build

go build -o hola .
./hola
# Hola, mundo
# 2 + 2 = 4

Compila y genera un binario ejecutable. El -o hola fija el nombre de salida. El . compila el paquete del directorio actual.

Para desarrollo, go run es más cómodo. Para producción, siempre go build: el binario resultante no necesita Go instalado para ejecutarse.

El compilador es tu aliado

Prueba a romper el programa a propósito para ver cómo responde el compilador:

package main

import (
    "fmt"
    "os"   // importado pero no usado
)

func main() {
    x := 42   // declarado pero no usado
    fmt.Println("hola")
}
go run main.go
# ./main.go:5:2: "os" imported and not used
# ./main.go:9:2: x declared and not used

El compilador da el fichero, la línea y el mensaje exacto. No hay que adivinar nada. Esta precisión es una de las razones por las que el código Go en equipos grandes sigue siendo manejable: los errores se detectan antes de ejecutar.

go fmt y go vet

go fmt formatea el código según el estilo oficial. No tiene opciones porque no las necesita: hay un único estilo.

go fmt ./...        # formatea todos los ficheros del módulo
go vet ./...        # detecta errores comunes que no son de compilación

go vet detecta errores que el compilador no puede: llamadas a Printf con el tipo de argumento incorrecto, variables de bucle capturadas en goroutines incorrectamente, comparaciones con nil que nunca son verdad.

package main

import "fmt"

func main() {
    // Printf espera string con %s, recibe int: vet lo detecta
    fmt.Printf("%s\n", 42)
}
go vet main.go
# ./main.go:7:2: fmt.Printf format %s has arg 42 of wrong type int
En el día a día, el editor ejecuta go fmt al guardar y go vet en tiempo real. Solo necesitas ejecutarlos manualmente si trabajas fuera del editor o en CI.

Leer argumentos

Un programa un poco más útil: leer el nombre desde la línea de comandos.

package main

import (
    "fmt"
    "os"
)

func main() {
    if len(os.Args) < 2 {
        fmt.Println("Uso: hola <nombre>")
        os.Exit(1)
    }

    nombre := os.Args[1]
    fmt.Printf("Hola, %s!\n", nombre)
}
go run main.go Ana
# Hola, Ana!

go run main.go
# Uso: hola <nombre>

os.Args es un slice de strings. El índice 0 es siempre el nombre del programa; los argumentos empiezan en 1. len() devuelve la longitud del slice.

Un servidor HTTP en 10 líneas

La stdlib de Go incluye un servidor HTTP completo en el paquete net/http. Sin instalar nada extra:

package main

import (
    "fmt"
    "net/http"
)

func main() {
    http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintf(w, "Hola desde Go! Ruta: %s\n", r.URL.Path)
    })

    fmt.Println("Servidor en http://localhost:8080")
    http.ListenAndServe(":8080", nil)
}
go run main.go
# Servidor en http://localhost:8080

# En otra terminal:
curl http://localhost:8080/
# Hola desde Go! Ruta: /

curl http://localhost:8080/api/usuarios
# Hola desde Go! Ruta: /api/usuarios

Este servidor maneja concurrencia automáticamente: cada petición HTTP se atiende en su propia goroutine. Sin configuración, sin dependencias.

¿Cuánto código equivalente en PHP? En PHP necesitas nginx o apache configurado, PHP-FPM, un index.php y un router. El servidor HTTP de la stdlib de Go hace todo eso en 10 líneas. Esa es una de las fortalezas que se mencionaba en la lección anterior.

Resumen

  • Todo fichero Go declara su paquete, sus imports y el código. No hay variaciones en la estructura.
  • El compilador rechaza imports no usados y variables no usadas: cero ruido de partida.
  • go run compila y ejecuta sin dejar ficheros; go build genera el binario de producción.
  • go fmt formatea el código sin opciones; go vet detecta errores sutiles que el compilador no ve.
  • La stdlib incluye un servidor HTTP de producción: concurrencia automática, sin dependencias externas.
