Tipos y variables en Go

Go es estrictamente tipado: el compilador conoce el tipo de cada variable antes de ejecutar. Pero la inferencia con := hace que el código sea cómodo de escribir. Y el zero value elimina la clase entera de bugs del "usé una variable sin inicializar".

Tipos básicos

Go tiene un sistema de tipos más explícito que PHP. No hay un tipo numérico genérico: hay enteros con signo de distintos tamaños, enteros sin signo y flotantes:

TipoTamañoRango / Descripción
int32 o 64 bits*El tipo entero por defecto
int8/16/32/64fijoEnteros con signo de tamaño fijo
uint/uint8/16/32/64fijoEnteros sin signo
float32/float6432/64 bitsfloat64 es el por defecto
bool1 bytetrue o false
stringvariableSecuencia de bytes UTF-8 inmutable
byte1 byteAlias de uint8
rune4 bytesAlias de int32; un carácter Unicode

* int es 32 bits en plataformas de 32 bits y 64 bits en plataformas de 64 bits. En la práctica casi siempre es 64 bits.

var y :=

Hay dos formas de declarar variables. La diferencia no es de rendimiento sino de contexto:

// var: declaración explícita del tipo
var nombre string = "Ana"
var edad int = 30
var activo bool = true

// var sin valor inicial: usa el zero value del tipo
var contador int      // = 0
var mensaje string    // = ""
var encontrado bool   // = false

// := inferencia de tipo (solo dentro de funciones)
nombre := "Ana"       // string inferido
edad := 30            // int inferido
precio := 9.99        // float64 inferido

:= solo puede usarse dentro de funciones. Para variables a nivel de paquete (fuera de funciones), hay que usar var.

PHP (tipado dinámico)

$valor = 42;          // int
$valor = "hola";      // ahora string, sin error
$valor = true;        // ahora bool, sin error

Go (tipado estático)

valor := 42            // int
valor = "hola"         // error: cannot use "hola" (string) as int
valor = true           // error: cannot use true (bool) as int

El zero value: nunca null

En Go, toda variable declarada sin valor inicial tiene un zero value según su tipo. No existe el null como valor por defecto para tipos básicos. Esto elimina toda una clase de bugs del tipo "variable no inicializada".

var i int       // 0
var f float64   // 0.0
var b bool      // false
var s string    // "" (cadena vacía, no null)

// El zero value de un struct inicializa todos sus campos
type Punto struct {
    X, Y float64
}
var p Punto   // p.X == 0.0, p.Y == 0.0
¿Entonces no hay null en Go? Sí lo hay, pero solo para tipos que son inherentemente referencias: punteros, slices, maps, channels, funciones e interfaces. Para un string o un int, el zero value es "" y 0, nunca nil.

Conversiones explícitas

Go no hace conversiones implícitas entre tipos numéricos. Ni siquiera entre int y int64. Todas las conversiones son explícitas:

var i int = 42
var f float64 = float64(i)   // conversión explícita
var u uint = uint(f)          // otra conversión explícita

// Esto no compila:
var x int = 10
var y float64 = x            // error: cannot use x (int) as float64

La razón: las conversiones implícitas en C y C++ son fuente histórica de bugs sutiles. Go las prohíbe para que los datos que cambian de tipo sean siempre visibles en el código.

// Conversión string ↔ bytes
s := "hola"
b := []byte(s)              // []byte{104, 111, 108, 97}
s2 := string(b)             // "hola"

// Rune ↔ string
r := rune('ñ')              // 241 (el code point Unicode)
s3 := string(r)             // "ñ"

Constantes e iota

Las constantes en Go se evalúan en tiempo de compilación y no tienen tipo hasta que se usan (son "untyped" por defecto), lo que les da más flexibilidad que las constantes de PHP:

const Pi = 3.14159          // untyped: se adapta al contexto
const Nombre = "MentorAI"   // untyped string

const (
    StatusOK    = 200
    StatusError = 500
)

iota es un contador que se resetea a 0 en cada bloque const y se incrementa en 1 por cada constante. Ideal para enumeraciones:

type Nivel int

const (
    Principiante Nivel = iota   // 0
    Intermedio                   // 1
    Avanzado                     // 2
)

type DiaSemana int

const (
    Lunes DiaSemana = iota + 1  // 1
    Martes                        // 2
    Miercoles                     // 3
    Jueves                        // 4
    Viernes                       // 5
)

Strings en Go

Los strings en Go son inmutables y contienen bytes UTF-8. La distinción entre bytes y caracteres (runes) es explícita:

s := "hola, 世界"

fmt.Println(len(s))           // 13: número de BYTES, no de caracteres
fmt.Println(len([]rune(s)))   // 9: número de CARACTERES Unicode

// Iterar sobre bytes (puede partir caracteres multibyte)
for i, b := range []byte(s) {
    fmt.Printf("[%d]=%d ", i, b)
}

// Iterar sobre runes (caracteres Unicode completos)
for i, r := range s {
    fmt.Printf("[%d]=%c ", i, r)   // 世 ocupa bytes 7, 8, 9
}

// Concatenar (crea un nuevo string; para muchas concatenaciones, usar strings.Builder)
saludo := "Hola" + ", " + "mundo"
El paquete strings tiene todo lo que PHP tiene como funciones nativas: strings.Contains, strings.HasPrefix, strings.ToUpper, strings.TrimSpace, strings.Split, strings.Join...

Resumen

  • Go tiene tipos numéricos explícitos: int, float64, bool, string. El compilador los conoce todos en tiempo de compilación.
  • var nombre tipo = valor para declaraciones explícitas; nombre := valor para inferencia dentro de funciones.
  • Toda variable tiene un zero value según su tipo: 0, "", false. No hay null para tipos básicos.
  • Las conversiones entre tipos son siempre explícitas: float64(i), string(b). Nada implícito.
  • iota en un bloque const genera enumeraciones incrementales sin repetir valores a mano.
