Tipos y variables en Python

Tipado dinámico vs estático, tipos built-in (int, float, str, bool, None), listas, tuplas, diccionarios y sets. Mutabilidad e inmutabilidad.

En PHP aprendiste a desconfiar de las comparaciones y de las conversiones silenciosas. En Python esas sorpresas desaparecen, pero aparecen otras: listas que cambian «solas» porque dos nombres apuntan al mismo objeto, o diccionarios que rechazan una lista como clave. Casi todas salen de una sola idea: la variable es una etiqueta y el tipo vive en el objeto.

Tipado dinámico y fuerte #

En Python, la variable no tiene tipo, el objeto sí. Una variable es solo un nombre que apunta a un objeto. Ese objeto tiene un tipo fijo; la variable puede apuntar a objetos de tipos distintos a lo largo del tiempo:

python 
x = 42
print(type(x))  # <class 'int'>

x = "hola"
print(type(x))  # <class 'str'>

x = [1, 2, 3]
print(type(x))  # <class 'list'>

Lo anterior no significa que Python no tenga tipos; significa que los tipos viven en los objetos, no en las variables. El tipado es fuerte: no hay coerciones implícitas entre tipos incompatibles.

python 
1 + "2"
# TypeError: unsupported operand type(s) for +: 'int' and 'str'

int("42") + 1   # 43  — conversión explícita
str(42) + "px"  # "42px"  — conversión explícita

En PHP, 1 + "2" devuelve 3 silenciosamente. En Go, el compilador rechazaría la operación en tiempo de compilación. En Python, el error aparece en runtime pero es explícito: TypeError con un mensaje claro. Cada modelo tiene sus ventajas; Python elige la seguridad sobre la conveniencia implícita.

Escalares: int, float, str, bool, None #

python 
n = 2 ** 100
print(n)  # 1267650600228229401496703205376 — precisión arbitraria, sin overflow

precio = 9.99
resultado = 0.1 + 0.2
print(resultado)  # 0.30000000000000004 — IEEE 754 double, igual que en todo lenguaje

activo = True
print(type(activo))  # <class 'bool'>
print(isinstance(activo, int))  # True — bool es subclase de int
print(True + True)  # 2

nombre = "Python"
print(nombre[0])    # 'P'
print(nombre[-1])   # 'n'  — índice negativo desde el final
print(nombre[1:4])  # 'yth'  — slicing
print(len(nombre))  # 6
print(nombre.upper())  # 'PYTHON'

vacio = None
print(type(vacio))  # <class 'NoneType'>
print(vacio is None)  # True — siempre comparar None con is, no ==

int de precisión arbitraria: en PHP, PHP_INT_MAX es 9223372036854775807 (64 bits). Pasarlo causa overflow silencioso o conversión a float. En Python, 2 ** 100 se calcula exactamente. Para criptografía y computación científica esto es relevante; para backend CRUD, es un detalle que raramente importa.

Los strings en Python son inmutables y Unicode por defecto (desde Python 3). No hay strings de bytes y strings de texto mezclados como en Python 2; str siempre es texto Unicode, bytes es binario.

Colecciones: list, tuple, dict, set #

python 
numeros: list[int] = [3, 1, 4, 1, 5, 9]
numeros.append(2)
numeros[0] = 99
numeros.sort()
print(numeros)  # [1, 1, 2, 3, 4, 5, 9, 99]

coordenadas: tuple[float, float] = (40.4168, -3.7038)
latitud, longitud = coordenadas
print(latitud)  # 40.4168

usuario: dict[str, object] = {
    "nombre": "Ana",
    "edad": 30,
    "activo": True,
}
usuario["email"] = "ana@example.com"
nombre = usuario.get("telefono", "sin teléfono")  # default si no existe
print(usuario.keys())    # dict_keys(['nombre', 'edad', 'activo', 'email'])
print(usuario.values())  # dict_values(['Ana', 30, True, 'ana@example.com'])
print(usuario.items())   # pares clave-valor

etiquetas: set[str] = {"python", "backend", "fastapi"}
etiquetas.add("docker")
etiquetas.discard("backend")
print({"python", "go"} & etiquetas)  # intersección: {'python'}
print({"python", "go"} | etiquetas)  # unión

Los diccionarios en Python 3.7+ mantienen el orden de inserción (garantía del lenguaje, no solo del intérprete). En PHP, los arrays son arrays asociativos ordenados; la equivalencia es directa. En Go, los maps no tienen orden garantizado.

Mutabilidad e inmutabilidad #

La mutabilidad en Python determina dos cosas importantes: qué pasa cuando pasas un objeto a una función, y qué objetos pueden usarse como claves de diccionario.

python 
lista = [1, 2, 3]


def agregar(items: list[int], valor: int) -> None:
    items.append(valor)


agregar(lista, 4)
print(lista)  # [1, 2, 3, 4] — la lista original se modificó


texto = "hola"
texto[0] = "H"
# TypeError: 'str' object does not support item assignment

nuevo_texto = "H" + texto[1:]  # crear un string nuevo en su lugar
print(nuevo_texto)  # 'Hola'

Las claves de un diccionario deben ser hashables, es decir, inmutables:

python 
d: dict = {}
d[(1, 2)] = "tupla como clave"  # OK: tuplas son inmutables
d[[1, 2]] = "lista como clave"  # TypeError: cannot use 'list' as a dict key (unhashable type: 'list')
TipoMutableHashable (puede ser clave de dict)
int, float, boolNoSí
strNoSí
tupleNoSí (si todos sus elementos son hashables)
listSíNo
dictSíNo
setSíNo
frozensetNoSí

Errores típicos con tipos y mutabilidad

  • Creer que b = a copia. Con una lista o un diccionario, los dos nombres apuntan al mismo objeto y cambiar uno cambia «el otro». Copia con a.copy(), y con copy.deepcopy(a) si hay colecciones anidadas.
  • Construir una matriz con [[0] * 3] * 3. Son tres referencias a la misma fila: asignar matriz[0][0] = 1 cambia la primera columna entera. Usa una comprensión: [[0] * 3 for _ in range(3)].
  • Comparar valores con is. is mira si es el mismo objeto, no si vale lo mismo. Con enteros pequeños parece funcionar porque CPython los reutiliza, y falla con números grandes o con strings construidos en ejecución. is solo para None; para todo lo demás, ==.
  • Crear un Decimal desde un float. Decimal(0.1) hereda el error de redondeo del float; Decimal("0.1") es exacto.

Type hints #

Los type hints son anotaciones opcionales que documentan qué tipos espera y produce cada función. Python no los valida en runtime, pero mypy, Pyright y FastAPI sí los usan:

python 
from typing import Any


def saludar(nombre: str, veces: int = 1) -> str:
    return f"Hola, {nombre}! " * veces


def procesar(items: list[int]) -> dict[str, int]:
    return {"suma": sum(items), "maximo": max(items), "minimo": min(items)}


def buscar_usuario(identificador: int) -> str | None:
    if identificador == 1:
        return "Ana"
    return None


def log(valor: Any) -> None:
    print(repr(valor))

Desde Python 3.10, str | None es la sintaxis preferida en lugar de Optional[str] de typing. Para colecciones, list[int] funciona directamente desde Python 3.9 (antes hacía falta from typing import List).

Type hints y FastAPI: FastAPI lee los type hints de los parámetros de tus funciones en tiempo de ejecución para generar la validación automática y la documentación OpenAPI. En ese contexto, los type hints no son opcionales; son la API de FastAPI.

Cuándo aplicarlo #

En PHP el array lo hace todo; en Python elegir la colección es elegir qué operaciones serán baratas y qué errores serán imposibles.

  • list para una secuencia ordenada que crece o cambia: los resultados que vas acumulando, una cola de trabajo pequeña.
  • tuple para un registro fijo de pocos campos o una clave compuesta de diccionario. Si los campos merecen nombre, pasa a una dataclass o una NamedTuple: usuario[2] no le dice nada a quien lee.
  • dict para buscar por clave. No lo uses como objeto con campos fijos que viaja por toda la aplicación, como el array asociativo de PHP: ahí una dataclass o un TypedDict te dan autocompletado y errores de tipo.
  • set para pertenencia y para quitar duplicados: x in conjunto cuesta lo mismo con diez elementos que con un millón, mientras que en una lista recorre hasta encontrarlo. A cambio, no guarda orden.
  • Decimal, no float, para importes: 0.1 + 0.2 no da 0.3 y en dinero ese céntimo acaba en una factura.

Los type hints van siempre en las firmas de funciones que otros llaman. En variables locales, solo cuando el tipo no se deduce solo, como una lista que nace vacía: pendientes: list[str] = [].

Resumen #

Lo que te llevas

  • La variable no tiene tipo; el objeto sí. El tipado fuerte impide coerciones implícitas: 1 + "2" es un TypeError, no una conversión silenciosa.
  • int tiene precisión arbitraria en Python (sin overflow); float es IEEE 754 doble precisión como en todos los lenguajes.
  • Las cuatro colecciones fundamentales: list (mutable, ordenada), tuple (inmutable, hashable), dict (hash map ordenado desde 3.7), set (sin duplicados, operaciones de conjunto).
  • Los objetos mutables (list, dict, set) se pasan por referencia a las funciones; los inmutables (str, tuple, int) no pueden modificarse.
  • Los type hints documentan los tipos esperados y son la base de FastAPI, mypy y Pyright; Python no los valida en runtime por defecto.
