Control de flujo en Python

if/elif/else, while, for con iterables, break/continue/else en bucles, match/case de Python 3.10 y el operador walrus :=.

La lógica de un endpoint es casi toda control de flujo: validar, ramificar y recorrer resultados. En Python las piezas se parecen a las de PHP lo justo para confundir: el for no lleva índice, un else puede colgar de un bucle y match no es un switch. Aquí ves qué herramienta elegir en cada caso y por qué.

if/elif/else y truthiness #

La indentación con 4 espacios (PEP 8) es la sintaxis del bloque. No hay llaves, no hay end, no hay fi. El compilador rechaza mezclar espacios y tabuladores en el mismo fichero.

python 
edad = 25

if edad >= 18:
    print("Mayor de edad")
elif edad >= 13:
    print("Adolescente")
else:
    print("Menor")

Python no tiene switch hasta 3.10 (donde llegó match/case, que va mucho más allá de un switch). Las cadenas elif son el sustituto directo.

Truthiness: Python evalúa cualquier objeto como booleano. Los valores falsy son 0, 0.0, "", b"", [], {}, set(), None y False. Todo lo demás es truthy.

python 
if not []:
    print("lista vacía es falsy")  # se ejecuta

if "texto":
    print("string no vacío es truthy")  # se ejecuta

if 0:
    print("nunca se ejecuta")

nombre = ""
resultado = nombre or "Anónimo"  # "Anónimo" — or retorna el primer truthy
print(resultado)

Diferencia con PHP: PHP tiene reglas de truthiness más complejas y sorprendentes ("0" es falsy en PHP, truthy en Python). Las reglas de Python son más predecibles: solo los "vacíos" y None son falsy.

for sobre iterables #

El for de Python itera sobre cualquier objeto iterable: listas, strings, diccionarios, rangos, generadores y cualquier objeto que implemente el protocolo iterador.

python 
frutas = ["manzana", "pera", "naranja"]

for fruta in frutas:
    print(fruta)

for caracter in "Python":
    print(caracter)

config = {"host": "localhost", "port": 8000, "debug": True}

for clave, valor in config.items():
    print(f"{clave}: {valor}")

for indice, fruta in enumerate(frutas, start=1):
    print(f"{indice}. {fruta}")

for i in range(0, 10, 2):
    print(i)  # 0, 2, 4, 6, 8

El else en un bucle for es una característica rara pero útil: se ejecuta si el bucle terminó sin un break. Sirve para el patrón "buscar algo y actuar si no se encontró":

python 
numeros = [3, 7, 11, 8, 4]

for numero in numeros:
    if numero > 10:
        print(f"Encontrado: {numero}")
        break
else:
    print("No hay números mayores de 10")

while y break/continue #

python 
contador = 0

while contador < 5:
    print(contador)
    contador += 1

while True:
    entrada = input("Escribe 'salir' para terminar: ")

    if entrada == "salir":
        break

    print(f"Recibido: {entrada}")

for i in range(10):
    if i % 2 == 0:
        continue
    print(i)  # 1, 3, 5, 7, 9

while True con break es el patrón idiomático para bucles donde la condición de salida está en el medio del cuerpo: conexiones de red que esperan mensajes, menús interactivos, polling con condición compleja.

match/case (Python 3.10+) #

El structural pattern matching de Python 3.10 va más allá de un switch: permite descomponer estructuras, capturar variables y añadir guardas:

python 
comando = "borrar 42"

match comando.split():
    case ["listar"]:
        print("Listar todos")
    case ["buscar", termino]:
        print(f"Buscando: {termino}")
    case ["borrar", id_str] if id_str.isdigit():
        print(f"Borrando id {id_str}")
    case _:
        print("Comando desconocido")

También funciona con tipos y dataclasses:

python 
from dataclasses import dataclass


@dataclass
class Punto:
    x: float
    y: float


def describir(punto: Punto) -> str:
    match punto:
        case Punto(x=0, y=0):
            return "Origen"
        case Punto(x=0, y=y):
            return f"Eje Y en {y}"
        case Punto(x=x, y=0):
            return f"Eje X en {x}"
        case Punto(x=x, y=y):
            return f"Punto ({x}, {y})"

Comparación con Rust: el match de Rust es exhaustivo; el compilador fuerza que cubras todos los casos posibles. El match de Python no es exhaustivo: si ningún patrón coincide y no hay case _:, simplemente no hace nada. Eso es consistente con el modelo dinámico de Python pero pierde la seguridad en compilación de Rust.

Errores típicos al controlar el flujo

  • Usar un nombre suelto en un case como si fuera una constante. case ACTIVO: no compara: captura el valor en una variable llamada ACTIVO y casa siempre. Si no es el último case, Python lo rechaza con un SyntaxError; si lo es, se traga todo en silencio. Compara con nombres con punto (Estado.ACTIVO, de un Enum) o con literales.
  • Borrar de una lista mientras la recorres. El for avanza por índice y, al quitar un elemento, se salta el siguiente. Con un diccionario, directamente salta RuntimeError. Construye una colección nueva con una comprensión, o recorre una copia.
  • Usar la truthiness cuando el cero es un valor válido. if not cantidad: trata igual 0 que None, y un pedido de cero unidades acaba en la rama de «falta el dato». Si lo que quieres saber es si llegó, pregunta if cantidad is None:.

El operador walrus := #

El operador walrus (:=, PEP 572, Python 3.8+) asigna y evalúa en la misma expresión. Su nombre viene de los colmillos de la morsa.

python 
with open("fichero.bin", "rb") as f:
    while chunk := f.read(8192):
        procesar(chunk)

lineas = ["  hola  ", "", "  mundo  ", ""]
filtradas = [limpia for linea in lineas if (limpia := linea.strip())]
print(filtradas)  # ['hola', 'mundo']

Sin walrus, el primer ejemplo requiere duplicar la llamada a f.read():

python 
chunk = f.read(8192)
while chunk:
    procesar(chunk)
    chunk = f.read(8192)  # duplicado

El walrus es útil en tres situaciones concretas: bucles while que leen I/O, comprensiones donde el valor filtrado es el valor procesado, y condiciones donde calcular el resultado una vez y reutilizarlo evita trabajo repetido.

Cuándo no usar walrus: si no elimina duplicación real o si hace el código más oscuro, no lo uses. El Zen de Python: "Explicit is better than implicit." Un walrus innecesario es un truco, no una mejora.

Cuándo aplicarlo #

  • if/elif para dos o tres ramas y condiciones sobre rangos. Si se anidan, sal pronto con un return en cada caso que no sigue: el camino feliz queda al final y sin sangría.
  • match cuando ramificas por la forma de los datos: un comando partido en palabras, un JSON que llega con estructuras distintas o una dataclass. Para comparar un valor con cuatro constantes, un if/elif o un diccionario de funciones se lee mejor.
  • for sobre el iterable, con enumerate si necesitas el índice y zip si recorres dos a la vez. for i in range(len(lista)) es PHP traducido y casi siempre sobra.
  • while solo cuando no hay una colección que recorrer: polling, reintentos o leer hasta que se agote la entrada.
  • for…else para «busca y, si no aparece, haz esto». Si el equipo no lo conoce, una función con return dentro del bucle dice lo mismo sin sorpresas.
  • Walrus cuando elimina una llamada repetida de verdad, no para ahorrar una línea.

Resumen #

Lo que te llevas

  • La indentación con 4 espacios es la sintaxis del bloque, no una convención opcional. Python no tiene llaves ni palabras clave de cierre.
  • Las reglas de truthiness son predecibles: falsy son los vacíos (0, "", [], {}) y None; todo lo demás es truthy.
  • El for itera sobre cualquier iterable; enumerate() da índice y valor, .items() da clave y valor en dicts.
  • El else en for y while se ejecuta solo si no hubo break: útil para el patrón "busca y actúa si no encontraste".
  • match/case de Python 3.10 es structural pattern matching real: descompone estructuras y captura variables, no es solo un switch glorificado.
  • El walrus := asigna y evalúa en la misma expresión; útil para eliminar duplicación en bucles de I/O y comprensiones.
