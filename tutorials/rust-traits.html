¿Qué es un trait? #

Un trait en Rust define un conjunto de métodos que un tipo debe implementar. Es conceptualmente similar a una interface de PHP, con dos diferencias importantes:

  • Los traits pueden tener implementaciones por defecto, no solo firmas.
  • Puedes implementar un trait de la stdlib (o de otra crate) sobre tus propios tipos, siempre que al menos uno de los dos (trait o tipo) sea tuyo.
rust 
trait Describible {
    fn descripcion(&self) -> String;

    fn descripcion_corta(&self) -> String {
        let descripcion = self.descripcion();
        descripcion.chars().take(50).collect()
    }
}

descripcion es abstracto (cada tipo debe implementarlo). descripcion_corta tiene implementación por defecto que reutiliza descripcion, pero los tipos pueden sobrescribirla.

Rust no tiene herencia: no hay extends. El código compartido se expresa a través de implementaciones por defecto en traits y composición de structs. Los traits pueden requerir que implementen otros traits (supertrait), pero no heredan datos.

Definir e implementar traits #

rust 
struct Producto {
    nombre: String,
    precio: f64,
}

struct Usuario {
    nombre: String,
    email: String,
}

impl Describible for Producto {
    fn descripcion(&self) -> String {
        format!("{} — {:.2}€", self.nombre, self.precio)
    }
}

impl Describible for Usuario {
    fn descripcion(&self) -> String {
        format!("{} <{}>", self.nombre, self.email)
    }
}

La regla de la coherencia (orphan rule): solo puedes implementar un trait sobre un tipo si el trait o el tipo pertenece a tu crate. Esto evita conflictos de implementaciones duplicadas entre crates.

Puedes también implementar traits de la stdlib sobre tus tipos. Por ejemplo, implementar Display para poder usar tu tipo con println!:

rust 
use std::fmt;

impl fmt::Display for Producto {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{} ({:.2}€)", self.nombre, self.precio)
    }
}

fn main() {
    let prod = Producto { nombre: "Ratón".to_string(), precio: 29.99 };
    println!("{}", prod); // usa Display: Ratón (29.99€)
}

Generics con trait bounds #

Los generics permiten escribir funciones que operan sobre cualquier tipo, y los trait bounds restringen qué tipos son aceptables:

rust 
use std::fmt::Display;

fn imprimir_par<T: Display>(primero: T, segundo: T) {
    println!("{} y {}", primero, segundo);
}

fn mayor<T: PartialOrd>(a: T, b: T) -> T {
    if a > b { a } else { b }
}

Para múltiples bounds, usa +:

rust 
fn imprimir_debug<T: Display + std::fmt::Debug>(valor: T) {
    println!("{} / {:?}", valor, valor);
}

Cuando los bounds se complican, la sintaxis where los separa del nombre de la función para mayor legibilidad:

rust 
fn procesar<T, U>(t: T, u: U) -> String
where
    T: Display + Clone,
    U: Display + std::fmt::Debug,
{
    format!("{} {:?}", t, u)
}

Los generics con trait bounds son static dispatch: el compilador genera una versión de la función para cada tipo concreto que la usa. Resultado: rendimiento idéntico a escribir la función a mano para ese tipo, sin coste en runtime.

impl Trait en parámetros y retorno #

impl Trait en parámetros es una sintaxis más concisa que los generics para la mayoría de casos:

rust 
fn imprimir(item: impl Display) {
    println!("{}", item);
}

fn imprimir_todos(items: impl Iterator<Item = impl Display>) {
    for item in items {
        println!("{}", item);
    }
}

En el retorno, impl Trait permite retornar un tipo que implementa el trait sin especificarlo exactamente. Esto es especialmente útil para retornar iteradores (cuyo tipo real suele ser críptico):

rust 
fn numeros_pares(hasta: u32) -> impl Iterator<Item = u32> {
    (0..=hasta).filter(|n| n % 2 == 0)
}

fn main() {
    for n in numeros_pares(10) {
        print!("{} ", n); // 0 2 4 6 8 10
    }
}

Limitación de impl Trait en retorno: todas las rutas de la función deben retornar el mismo tipo concreto. No puedes retornar impl Trait desde un if donde una rama retorna un tipo y la otra un tipo distinto. En ese caso, usa Box<dyn Trait>.

dyn Trait: polimorfismo en runtime #

Los trait objects (dyn Trait) permiten polimorfismo en runtime: guardar en una colección valores de tipos distintos que comparten un trait.

rust 
fn describir_todos(items: &[Box<dyn Describible>]) {
    for item in items {
        println!("{}", item.descripcion());
    }
}

fn main() {
    let items: Vec<Box<dyn Describible>> = vec![
        Box::new(Producto { nombre: "Teclado".to_string(), precio: 79.0 }),
        Box::new(Usuario { nombre: "Ana".to_string(), email: "ana@ej.com".to_string() }),
    ];

    describir_todos(&items);
}

El coste de dyn Trait frente a los generics: una indirección de puntero extra (vtable) por llamada de método. Para la mayoría de aplicaciones web, este coste es insignificante. Para código de rendimiento crítico en bucles tight, prefiere generics.

Box<dyn Trait> vs impl Trait: impl Trait se resuelve en compilación (static dispatch, sin vtable). Box<dyn Trait> se resuelve en runtime (dynamic dispatch, con vtable). Elige impl Trait cuando el tipo es único y conocido en compilación; Box<dyn Trait> cuando necesitas una colección heterogénea.

Traits importantes de la stdlib #

La stdlib de Rust define traits que aparecen constantemente:

TraitPropósitoCómo se obtiene
DisplayFormateo para usuarios: {}Implementación manual
DebugFormateo para debuggers: {:?}#[derive(Debug)]
CloneClonar un valor explícitamente#[derive(Clone)]
CopyCopiar en lugar de mover (tipos simples)#[derive(Copy, Clone)]
PartialEq / EqComparación con ==#[derive(PartialEq, Eq)]
PartialOrd / OrdComparación de orden: <, >#[derive(PartialOrd, Ord)]
IteratorProtocolo de iteraciónImplementación manual de next()
From / IntoConversiones entre tiposImplementar From, Into es gratuito
DefaultValor por defecto del tipo#[derive(Default)]

El derive macro #[derive(...)] genera implementaciones automáticas para traits que siguen patrones estructurales predecibles:

rust 
#[derive(Debug, Clone, PartialEq)]
struct Punto {
    x: f64,
    y: f64,
}

fn main() {
    let p1 = Punto { x: 1.0, y: 2.0 };
    let p2 = p1.clone();
    println!("{:?}", p1);   // Punto { x: 1.0, y: 2.0 }
    println!("{}", p1 == p2); // true
}

Resumen #

Lo que te llevas

  • Los traits definen comportamiento compartido; pueden tener implementaciones por defecto. No hay herencia en Rust.
  • La orphan rule garantiza coherencia: solo implementas un trait sobre un tipo si alguno de los dos es tuyo.
  • Los generics con trait bounds son static dispatch: el compilador genera código especializado sin coste en runtime.
  • impl Trait en parámetros y retorno es la sintaxis concisa para la mayoría de casos con generics.
  • Box<dyn Trait> habilita polimorfismo en runtime para colecciones heterogéneas, con coste de una vtable por llamada.
  • #[derive(...)] genera automáticamente implementaciones de Debug, Clone, PartialEq y otros traits estructurales.
