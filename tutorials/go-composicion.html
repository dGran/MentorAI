Composición: embedding sin herencia

Go no tiene herencia. No hay extends. En su lugar tiene embedding: incrustar un tipo dentro de otro para que sus métodos sean accesibles directamente. Es composición a nivel de lenguaje, sin jerarquías de clases.

Go no tiene herencia

En PHP es habitual extender clases para reutilizar comportamiento. En Go no existe ese mecanismo. El lenguaje toma partido deliberadamente: la herencia crea acoplamientos frágiles; la composición construye sistemas más flexibles.

Si vienes de PHP, el cambio mental es: en vez de pensar "X es un Y" (herencia), piensas "X tiene un Y" (composición). Go refuerza esta idea con el embedding.

Embedding de structs

El embedding consiste en incluir un tipo dentro de otro struct sin darle un nombre de campo. Solo el tipo:

type Animal struct {
    Nombre string
    Peso   float64
}

type Perro struct {
    Animal        // embedding: sin nombre de campo, solo el tipo
    Raza  string
}

p := Perro{
    Animal: Animal{Nombre: "Rex", Peso: 30.5},
    Raza:   "Pastor Alemán",
}

fmt.Println(p.Nombre)        // acceso directo: "Rex"
fmt.Println(p.Animal.Nombre) // acceso explícito: también "Rex"
fmt.Println(p.Raza)          // "Pastor Alemán"

El tipo incrustado (Animal) sigue siendo accesible por su nombre como campo, pero sus campos también se "promueven" al tipo externo: puedes acceder a p.Nombre directamente.

Métodos promovidos

Lo más útil del embedding: los métodos del tipo incrustado también se promueven. El tipo externo los hereda sin declarar nada:

func (a *Animal) Describir() string {
    return fmt.Sprintf("%s (%.1f kg)", a.Nombre, a.Peso)
}

p := Perro{
    Animal: Animal{Nombre: "Rex", Peso: 30.5},
    Raza:   "Pastor Alemán",
}

fmt.Println(p.Describir())   // "Rex (30.5 kg)" — método promovido

Si el tipo externo define su propio método con el mismo nombre, ese método tiene prioridad (overriding sin jerarquía):

func (d *Perro) Describir() string {
    return fmt.Sprintf("%s, %s (%.1f kg)", d.Nombre, d.Raza, d.Peso)
}

fmt.Println(p.Describir())        // "Rex, Pastor Alemán (30.5 kg)"
fmt.Println(p.Animal.Describir()) // "Rex (30.5 kg)": método original sigue accesible

Comparación con PHP traits

El embedding de Go se parece más a los traits de PHP que a la herencia clásica: ambos permiten reutilizar comportamiento sin herencia. Pero hay diferencias:

PHP traits

trait Auditable {
    private \DateTime $createdAt;
    private \DateTime $updatedAt;

    public function touch(): void {
        $this->updatedAt = new \DateTime();
    }
}

class Producto {
    use Auditable;

    public function __construct(
        private string $nombre
    ) {
        $this->createdAt = new \DateTime();
        $this->updatedAt = new \DateTime();
    }
}

Go embedding

type Auditable struct {
    CreadoEn     time.Time
    ActualizadoEn time.Time
}

func (a *Auditable) Actualizar() {
    a.ActualizadoEn = time.Now()
}

type Producto struct {
    Auditable       // embedding
    Nombre string
}

p := Producto{
    Auditable: Auditable{
        CreadoEn:     time.Now(),
        ActualizadoEn: time.Now(),
    },
    Nombre: "Mesa",
}
p.Actualizar()   // método promovido

La diferencia clave: el embedding en Go usa un tipo real con su propia memoria. El trait PHP inyecta código en la clase. En Go, p.Auditable es un valor concreto al que puedes acceder directamente.

Embedding de interfaces

También puedes incrustar interfaces dentro de otras interfaces para componerlas:

type Lector interface {
    Leer() ([]byte, error)
}

type Escritor interface {
    Escribir([]byte) error
}

// Composición de interfaces
type LectorEscritor interface {
    Lector
    Escritor
}

Este patrón es exactamente lo que hace la stdlib: io.ReadWriter es io.Reader + io.Writer. Permite construir interfaces más ricas a partir de partes pequeñas.

También es útil incrustar una interfaz dentro de un struct cuando solo quieres implementar parte de ella (para tests):

type Notificador interface {
    Enviar(dest, msg string) error
    Estado() bool
}

// Stub de test que solo implementa Enviar
type notificadorStub struct {
    Notificador   // embedding: Estado() delega al zero value (nil panic si se llama)
    mensajes []string
}

func (s *notificadorStub) Enviar(dest, msg string) error {
    s.mensajes = append(s.mensajes, msg)
    return nil
}

Cuándo usar embedding

SituaciónRecomendación
Comportamiento compartido entre tipos (logging, auditoría, timestamps)Embedding de struct
Extender una interfaz con más métodosEmbedding de interfaces
Stubs parciales en testsEmbedding de interfaz en struct
Relación "es un" que en PHP harías con extendsReplantearlo como composición; si hay polimorfismo, usar interfaz
El embedding promueve métodos pero no es herencia real. No hay super, no hay jerarquía de tipos, no hay subclassing. Perro no es un subtipo de Animal: son dos tipos distintos. Esto es intencional: evita los problemas de la herencia profunda.

Resumen

  • Go no tiene herencia. El mecanismo de reutilización es el embedding: incrustar un tipo dentro de otro sin nombre de campo.
  • Los campos y métodos del tipo incrustado se promueven al tipo externo y son accesibles directamente.
  • Si el tipo externo define un método con el mismo nombre, tiene prioridad. El método original sigue accesible vía el nombre del tipo incrustado.
  • Las interfaces también pueden incrustar otras interfaces para componer comportamientos más ricos.
  • El embedding no crea jerarquía de tipos: Perro no es un Animal para el sistema de tipos de Go.
