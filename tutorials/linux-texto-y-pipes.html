Linux: texto, pipes y variables de entorno

El modelo stdio de Unix — stdin, stdout, stderr y pipes — es lo que hace que pequeños comandos se conviertan en pipelines poderosos. Cat, head, tail, sort, awk, sed y las variables de entorno.

La filosofía Unix: cada herramienta hace una sola cosa bien, y las pipes las conectan. Es lo que hace que cat access.log | grep "500" | awk '{print $1}' | sort | uniq -c | sort -rn | head -10 tenga sentido.

stdin, stdout, stderr#

Todo proceso en Linux tiene tres flujos de datos abiertos por defecto:

FlujoDescriptorPor defectoPara qué
stdin0TecladoEntrada del proceso
stdout1TerminalSalida normal
stderr2TerminalErrores y diagnósticos

Los pipes y la redirección son simplemente formas de conectar o redirigir estos flujos entre procesos y ficheros.

Pipes#

El pipe (|) conecta el stdout de un proceso con el stdin del siguiente. Ambos procesos corren en paralelo; el kernel gestiona el buffer entre ellos.

bash · pipelines reales
# Las 10 IPs con más errores 500:
cat /var/log/nginx/access.log | grep " 500 " | awk '{print $1}' | sort | uniq -c | sort -rn | head -10

# Procesos que más memoria consumen:
ps aux | sort -k4 -rn | head -10

# Contar líneas únicas en un log:
cat error.log | grep "Exception" | sort | uniq | wc -l

# URLs más solicitadas:
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -20

Redirección#

bash · operadores de redirección
comando > fichero.txt       # stdout → fichero (sobreescribe)
comando >> fichero.txt      # stdout → fichero (añade al final)
comando < fichero.txt       # stdin ← fichero
comando 2> errores.txt      # stderr → fichero
comando 2>> errores.txt     # stderr → fichero (añade)
comando > out.txt 2>&1      # stdout y stderr → mismo fichero
comando >& fichero.txt      # atajo: stdout y stderr juntos (bash)
comando 2>/dev/null         # descarta stderr
comando >/dev/null 2>&1     # descarta todo (stdout y stderr)

# tee: escribe en fichero Y sigue pasando por stdout
comando | tee fichero.txt          # guarda y muestra
comando | tee -a fichero.txt       # añade (no sobreescribe)
comando | tee fichero.txt | grep "error"   # guarda todo, filtra lo que ves

# Here-doc: stdin multilínea en el script
cat << EOF
Línea 1
Línea 2
EOF

2>&1: el orden importa

comando > out.txt 2>&1 funciona porque primero redirige stdout a out.txt y luego redirige stderr al mismo sitio que stdout (ya apunta a out.txt). Al revés (2>&1 > out.txt) el stderr sigue yendo a la terminal.

Ver texto#

bash · cat, head, tail, less
cat fichero.txt              # muestra todo el contenido
cat -n fichero.txt           # con números de línea
cat a.txt b.txt              # concatena dos ficheros

head fichero.txt             # primeras 10 líneas
head -n 50 fichero.txt       # primeras 50 líneas
head -c 1024 fichero.bin     # primeros 1024 bytes

tail fichero.txt             # últimas 10 líneas
tail -n 100 error.log        # últimas 100 líneas
tail -f /var/log/nginx/access.log     # -f sigue en tiempo real (follow)
tail -f access.log | grep "500"       # sigue y filtra errores 500

less fichero.txt             # paginador interactivo (q=salir, /=buscar, G=final)

Procesar texto#

bash · wc, sort, uniq, cut
# wc: contar
wc -l fichero.txt       # número de líneas
wc -w fichero.txt       # palabras
wc -c fichero.txt       # bytes
wc -l *.php             # líneas de cada .php + total

# sort: ordenar
sort fichero.txt                # orden alfabético
sort -r fichero.txt             # inverso
sort -n numeros.txt             # numérico
sort -rn numeros.txt            # numérico inverso (el mayor primero)
sort -k2 fichero.txt            # ordena por columna 2
sort -t: -k3 -n /etc/passwd     # separa por : y ordena por columna 3 (UID)
sort -u fichero.txt             # elimina duplicados mientras ordena

# uniq: eliminar o contar duplicados (requiere entrada ordenada)
sort fichero.txt | uniq         # líneas únicas
sort fichero.txt | uniq -c      # con conteo de repeticiones
sort fichero.txt | uniq -d      # solo las que aparecen más de una vez
sort fichero.txt | uniq -u      # solo las que aparecen exactamente una vez

# cut: extraer columnas
cut -d: -f1 /etc/passwd         # campo 1 separado por : (nombres de usuario)
cut -d: -f1,3 /etc/passwd       # campos 1 y 3 (nombre y UID)
cut -c1-10 fichero.txt          # caracteres 1 al 10 de cada línea

sed y awk#

bash · sed: editar streams
# sed 's/patrón/reemplazo/' (por defecto solo la primera ocurrencia por línea)
echo "hola mundo" | sed 's/hola/adiós/'          # adiós mundo
echo "aaa bbb aaa" | sed 's/aaa/xxx/g'           # xxx bbb xxx (g = global)
sed -i 's/localhost/production.db/g' config.php  # -i edita el fichero en sitio

# Borrar líneas:
sed '/^#/d' fichero.txt                # borra líneas que empiezan por #
sed '/^$/d' fichero.txt                # borra líneas vacías
sed '5d' fichero.txt                   # borra la línea 5

# Mostrar solo ciertas líneas:
sed -n '10,20p' fichero.txt            # líneas 10 a 20
sed -n '/ERROR/p' app.log             # líneas que contienen ERROR
bash · awk: procesar columnas
# awk divide cada línea en campos ($1, $2... $NF=último)
awk '{print $1}' access.log             # primera columna (la IP)
awk '{print $7}' access.log             # séptima columna (la URL)
awk '{print $1, $9}' access.log         # IP y código de estado

# Filtrar con condiciones:
awk '$9 == "500"' access.log            # solo las líneas con código 500
awk '$9 >= 500' access.log             # 5xx
awk 'NR > 10 && NR <= 20' fichero.txt  # líneas 11 a 20

# Separador personalizado:
awk -F: '{print $1}' /etc/passwd        # -F: separador es ':'
awk -F: '{print $1, $3}' /etc/passwd    # nombre y UID

# Cálculos:
awk '{sum += $NF} END {print sum}' numeros.txt    # suma de la última columna
awk 'END {print NR}' fichero.txt                  # número de líneas (como wc -l)

Variables de entorno#

bash
env                         # muestra todas las variables de entorno
printenv PATH               # valor de PATH
echo $HOME                  # directorio home
echo $USER                  # usuario actual
echo $PWD                   # directorio actual
echo $SHELL                 # shell en uso

# Definir variables (solo en el proceso actual):
MI_VAR="hola"
echo $MI_VAR

# Exportar (disponible para subprocesos):
export DATABASE_URL="mysql://user:pass@localhost/db"
export -p                   # muestra todas las exportadas

# Eliminar:
unset MI_VAR

# Ficheros de configuración del shell (se ejecutan al arrancar):
# ~/.bashrc      → sesiones interactivas no-login (la más usada)
# ~/.bash_profile → sesiones login (SSH)
# ~/.zshrc        → equivalente para zsh
# /etc/environment → variables globales del sistema (todos los usuarios)

# alias: atajos de comandos
alias ll='ls -lah'
alias ..='cd ..'
alias grep='grep --color=auto'
# Para persistirlos, añadirlos al ~/.bashrc

PATH: dónde busca el shell los ejecutables

PATH es una lista de directorios separados por :. Cuando escribes php, el shell los recorre en orden hasta encontrar el ejecutable. Añadir un directorio: export PATH="$HOME/.composer/vendor/bin:$PATH" (en ~/.bashrc para que sea permanente).

Cuándo aplicarlo#

Úsalo cuando…

  • Transformación de texto puntual o procesamiento de logs en tiempo real: pipes con awk y sed
  • La operación es un one-liner claro y no necesita mantenimiento posterior

No lo uses cuando…

  • La lógica encadena más de 2-3 pasos o necesita estructuras de datos: usa Python o PHP
  • El script va a vivir en un repositorio y otros lo van a mantener: la legibilidad importa más que la concisión

Resumen#

Lo que te llevas

  • El pipe (|) conecta stdout de un proceso con stdin del siguiente. Es la base de los pipelines Unix: herramientas pequeñas compuestas.
  • > sobreescribe, >> añade. 2>&1 redirige stderr al mismo sitio que stdout. 2>/dev/null descarta errores. tee bifurca la salida.
  • tail -f sigue logs en tiempo real. Combínalo con | grep para filtrar sobre la marcha.
  • sort | uniq -c | sort -rn | head es el pipeline para encontrar las N cosas más frecuentes en cualquier log.
  • awk '{print $7}' extrae columnas de logs; sed 's/viejo/nuevo/g' reemplaza texto en streams.
  • export VARIABLE=valor la disponibiliza para subprocesos. ~/.bashrc persiste alias y exports entre sesiones.
