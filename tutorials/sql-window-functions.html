Window functions: SQL de analítica avanzada

A diferencia de GROUP BY, las window functions calculan sobre un conjunto de filas sin colapsarlas. El resultado se añade como columna adicional en cada fila. Son la herramienta que convierte SQL básico en SQL profesional.

Antes de las window functions, calcular "el rango de este producto dentro de su categoría" o "la variación respecto al mes anterior" requería self-joins o subconsultas correlacionadas — lentas y difíciles de leer. Las window functions resuelven eso en una sola línea.

El problema que resuelven #

GROUP BY colapsa filas y pierdes el detalle. Pero muchas veces quieres el detalle y el resultado del cálculo sobre el grupo. Ejemplo: mostrar cada pedido con su importe y el total acumulado y el porcentaje que representa del total.

GROUP BY — pierdes el detalle

sql 
-- Una fila por cliente, no por pedido
SELECT cliente_id, SUM(importe) AS total
FROM pedidos
GROUP BY cliente_id;

Window function — conservas el detalle

sql 
-- Una fila por pedido + el total del cliente añadido
SELECT id, cliente_id, importe,
       SUM(importe) OVER (PARTITION BY cliente_id) AS total_cliente
FROM pedidos;

Anatomía de OVER() #

Toda window function lleva OVER(). Sin él, es una función de agregado normal. Con él, opera sobre una ventana de filas definida por tres cláusulas opcionales:

sql 
función() OVER (
    PARTITION BY columna        -- divide en grupos (opcional)
    ORDER BY columna ASC|DESC   -- ordena dentro de cada grupo (opcional)
    ROWS BETWEEN ... AND ...    -- define el marco de filas (opcional)
)
Cláusula Qué hace Sin ella
PARTITION BY Divide las filas en grupos independientes. La función calcula por separado en cada grupo. Toda la tabla es una sola ventana
ORDER BY Ordena las filas dentro de cada partición. Necesario para ranking y offset. Sin orden definido (indeterminado para ranking)
ROWS BETWEEN Define exactamente qué filas forman la ventana para cada fila: acumulado, deslizante, toda la partición. Con ORDER BY: acumulado desde el inicio de la partición hasta la fila actual

El ORDER BY de OVER no ordena el resultado final

El ORDER BY dentro de OVER() define el orden de evaluación de la función dentro de la partición, no el orden de las filas del resultado. Para ordenar el resultado necesitas un ORDER BY fuera, al final de la consulta.

Funciones de ranking #

Asignan una posición a cada fila dentro de su partición según el ORDER BY. La diferencia está en cómo tratan los empates:

sql 
SELECT
    nombre,
    categoria,
    ventas,
    ROW_NUMBER()  OVER (PARTITION BY categoria ORDER BY ventas DESC) AS fila,
    RANK()        OVER (PARTITION BY categoria ORDER BY ventas DESC) AS rango,
    DENSE_RANK()  OVER (PARTITION BY categoria ORDER BY ventas DESC) AS rango_denso
FROM productos
ORDER BY categoria, ventas DESC;

Para verlo claro con un ejemplo donde dos productos de "Libros" tienen las mismas ventas (100):

Producto Ventas ROW_NUMBER RANK DENSE_RANK
Libro A150111
Libro B100222
Libro C100322
Libro D80443
Función Empates Cuándo usarla
ROW_NUMBER() Sin empates, siempre único Paginación, eliminar duplicados, elegir exactamente N filas
RANK() Comparten posición, hay huecos Podios reales ("dos segundos, ningún tercero")
DENSE_RANK() Comparten posición, sin huecos Cuando los huecos son confusos para el usuario

LAG y LEAD #

LAG accede al valor de la fila N posiciones antes en la partición. LEAD accede N posiciones después. Son la herramienta estándar para calcular variaciones respecto al período anterior sin hacer un self-join.

sql 
-- LAG(expresión, offset, valor_por_defecto)
-- LEAD(expresión, offset, valor_por_defecto)

-- Variación de ventas mes a mes
SELECT
    mes,
    ventas,
    LAG(ventas, 1, 0)  OVER (ORDER BY mes) AS ventas_mes_anterior,
    ventas - LAG(ventas, 1, 0) OVER (ORDER BY mes) AS delta,
    ROUND(
        (ventas - LAG(ventas, 1, 0) OVER (ORDER BY mes)) * 100.0
        / NULLIF(LAG(ventas, 1, 0) OVER (ORDER BY mes), 0),
        1
    ) AS variacion_pct
FROM resumen_mensual
ORDER BY mes;

El tercer argumento (0 en el ejemplo) es el valor por defecto cuando no hay fila anterior —el primer mes—. NULLIF(..., 0) evita la división por cero si el mes anterior tuvo ventas cero.

Con PARTITION BY, LAG/LEAD respetan los límites de la partición: no saltan de un grupo al siguiente.

sql 
-- Variación por producto (cada producto tiene su propia secuencia)
SELECT
    producto_id,
    mes,
    ventas,
    LAG(ventas) OVER (PARTITION BY producto_id ORDER BY mes) AS ventas_mes_anterior
FROM ventas_mensuales
ORDER BY producto_id, mes;

Agregados como ventana #

Las funciones de agregado habituales (SUM, COUNT, AVG, MIN, MAX) también funcionan como window functions. El comportamiento depende de si hay ORDER BY:

sql 
SELECT
    fecha,
    importe,

    -- Con ORDER BY: acumulado hasta la fila actual (running total)
    SUM(importe) OVER (ORDER BY fecha) AS acumulado,

    -- Sin ORDER BY: el total de toda la tabla (misma cifra en todas las filas)
    SUM(importe) OVER () AS total_global,

    -- PARTITION BY: acumulado por categoría
    SUM(importe) OVER (PARTITION BY categoria ORDER BY fecha) AS acumulado_categoria,

    -- Porcentaje del total (combina ventana con y sin ORDER BY)
    ROUND(importe * 100.0 / SUM(importe) OVER (), 1) AS pct_del_total

FROM ventas_diarias
ORDER BY fecha;

Con ROWS BETWEEN puedes hacer una media móvil deslizante: los últimos N días en lugar del acumulado completo.

sql 
-- Media móvil de los últimos 7 días (la fila actual y las 6 anteriores)
SELECT
    fecha,
    ventas,
    ROUND(
        AVG(ventas) OVER (
            ORDER BY fecha
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        ),
        2
    ) AS media_7_dias
FROM ventas_diarias
ORDER BY fecha;

Top-N por grupo #

El caso más solicitado: los N registros más altos (o más bajos) dentro de cada grupo. Con GROUP BY no puedes: solo te da el máximo del grupo, no los N primeros con todos sus datos. La solución estándar es ROW_NUMBER() en una CTE seguido de un filtro.

sql 
-- Top 3 productos por ventas en cada categoría
WITH productos_rankeados AS (
    SELECT
        nombre,
        categoria,
        ventas,
        ROW_NUMBER() OVER (PARTITION BY categoria ORDER BY ventas DESC) AS posicion
    FROM productos
)
SELECT nombre, categoria, ventas, posicion
FROM productos_rankeados
WHERE posicion <= 3
ORDER BY categoria, posicion;

No puedes poner WHERE posicion <= 3 directamente en la consulta donde defines la window function, porque WHERE se evalúa antes que el SELECT (y por tanto antes que las window functions). La CTE resuelve eso: defines el ROW_NUMBER en la CTE, filtras en la consulta exterior.

¿ROW_NUMBER o RANK para top-N?

Si quieres exactamente N filas por grupo (aunque haya empates), usa ROW_NUMBER. Si quieres todos los empatados en la posición N (el podio real), usa RANK o DENSE_RANK — pueden devolver más de N filas por grupo cuando hay empates.

El mismo patrón sirve para "la última transacción por usuario", "el pedido más reciente por cliente", "el registro más nuevo por dispositivo":

sql 
-- El pedido más reciente de cada cliente (top-1 por grupo)
WITH pedidos_rankeados AS (
    SELECT
        cliente_id,
        id AS pedido_id,
        fecha,
        importe,
        ROW_NUMBER() OVER (PARTITION BY cliente_id ORDER BY fecha DESC) AS rn
    FROM pedidos
)
SELECT cliente_id, pedido_id, fecha, importe
FROM pedidos_rankeados
WHERE rn = 1;

Resumen #

Lo que te llevas

  • Window function: calcula sobre un conjunto de filas sin colapsarlas. La fila original permanece; el resultado se añade como columna extra.
  • OVER(PARTITION BY ... ORDER BY ...): PARTITION BY divide en grupos, ORDER BY ordena dentro de cada grupo.
  • ROW_NUMBER: siempre único. RANK: empates con huecos. DENSE_RANK: empates sin huecos.
  • LAG/LEAD: accede a la fila N posiciones antes/después. Ideal para variaciones respecto al período anterior sin self-join.
  • SUM/AVG con ORDER BY → acumulado. Sin ORDER BY → total de la partición. Con ROWS BETWEEN → ventana deslizante.
  • Top-N por grupo: ROW_NUMBER() en CTE + WHERE posicion <= N. No puedes filtrar por window function en la misma consulta donde la defines.
