Definir funciones

def dividir(dividendo: float, divisor: float) -> float:
    if divisor == 0:
        raise ValueError("El divisor no puede ser cero")
    return dividendo / divisor


def min_max(numeros: list[float]) -> tuple[float, float]:
    return min(numeros), max(numeros)


minimo, maximo = min_max([3.0, 1.0, 4.0, 1.0, 5.0, 9.0])


def crear_usuario(
    nombre: str,
    rol: str = "usuario",
    activo: bool = True,
) -> dict[str, object]:
    return {"nombre": nombre, "rol": rol, "activo": activo}


crear_usuario("Ana")
crear_usuario("Bob", rol="admin")
crear_usuario("Carol", activo=False)

Una función sin return explícito retorna None implícitamente. En PHP la equivalencia es exacta: una función sin return retorna null.

Trampa clásica: mutable como valor por defecto. Los valores por defecto se evalúan una sola vez al definir la función, no en cada llamada. Usar una lista como default comparte la misma lista entre todas las llamadas: 
def agregar(item: str, lista: list[str] = []) -> list[str]:
    lista.append(item)
    return lista

agregar("a")  # ['a']
agregar("b")  # ['a', 'b'] — ¡la misma lista mutada!

def agregar_correcto(item: str, lista: list[str] | None = None) -> list[str]:
    if lista is None:
        lista = []
    lista.append(item)
    return lista

*args, **kwargs y keyword-only

def sumar(*numeros: float) -> float:
    return sum(numeros)


sumar(1, 2, 3, 4)  # 10
sumar(1.5, 2.5)    # 4.0


def crear_config(**opciones: object) -> dict[str, object]:
    defaults: dict[str, object] = {"debug": False, "timeout": 30}
    return {**defaults, **opciones}


crear_config(debug=True, puerto=8080)


def conectar(host: str, *, puerto: int, timeout: int = 30) -> None:
    print(f"Conectando a {host}:{puerto} (timeout={timeout}s)")


conectar("localhost", puerto=5432)
conectar("localhost", 5432)  # TypeError: takes 1 positional argument

El * sin nombre obliga a que todos los parámetros siguientes sean keyword-only. Es una práctica recomendada en APIs públicas: si cambias el orden de los parámetros, ningún caller se rompe porque todos pasan los argumentos por nombre.

El / fuerza positional-only, útil para emular el comportamiento de funciones built-in que no aceptan keyword arguments como len() o range().

Funciones de primera clase

Las funciones son objetos de primera clase en Python: se pueden asignar a variables, pasar como argumentos y retornar desde otras funciones.

def duplicar(x: int) -> int:
    return x * 2


operacion = duplicar
print(operacion(5))  # 10

usuarios = [
    {"nombre": "Bob", "edad": 30},
    {"nombre": "Ana", "edad": 25},
    {"nombre": "Carol", "edad": 35},
]
por_edad = sorted(usuarios, key=lambda u: u["edad"])


from collections.abc import Callable


def multiplicador(factor: int) -> Callable[[int], int]:
    def aplicar(x: int) -> int:
        return x * factor
    return aplicar


doble = multiplicador(2)
triple = multiplicador(3)
print(doble(5))   # 10
print(triple(5))  # 15

El cierre (closure) de aplicar captura factor del scope de multiplicador. En PHP existe el mismo concepto con use ($factor) explícito; en Python la captura es implícita y por referencia.

lambda

Las lambdas son funciones anónimas de una sola expresión. Se usan principalmente como argumento de key= en funciones de ordenación y filtrado:

cuadrado = lambda x: x ** 2
print(cuadrado(4))  # 16

productos = [
    {"nombre": "Teclado", "precio": 79.99},
    {"nombre": "Ratón", "precio": 29.99},
    {"nombre": "Monitor", "precio": 299.99},
]
mas_caro = max(productos, key=lambda p: p["precio"])
print(mas_caro["nombre"])  # Monitor

precios_ordenados = sorted(productos, key=lambda p: p["precio"], reverse=True)

Cuándo no usar lambda: si la expresión necesita más de una operación simple, usa def. Una lambda con una expresión condicional larga es más difícil de leer que una función con nombre. El objetivo es claridad, no brevedad por sí sola.

Built-ins imprescindibles

datos = [3, 1, 4, 1, 5, 9, 2, 6]

len(datos)       # 8
min(datos)       # 1
max(datos)       # 9
sum(datos)       # 31
sorted(datos)    # [1, 1, 2, 3, 4, 5, 6, 9]
list(reversed(datos))  # [6, 2, 9, 5, 1, 4, 1, 3]

for indice, valor in enumerate(datos, start=1):
    print(f"{indice}. {valor}")

nombres = ["Ana", "Bob", "Carol"]
edades = [25, 30, 22]

for nombre, edad in zip(nombres, edades):
    print(f"{nombre}: {edad}")

all(x > 0 for x in datos)   # True — todos positivos
any(x > 8 for x in datos)   # True — hay un 9

isinstance(42, int)                # True
isinstance("hola", (str, bytes))   # True — acepta tupla de tipos
isinstance(True, int)              # True — bool es subclase de int

for i in range(1_000_000):
    if i > 5:
        break  # range es lazy, no crea la lista en memoria
zip en Python 3.10+: acepta el parámetro strict=True, que lanza ValueError si los iterables tienen longitudes distintas. Sin él, zip para al agotarse el más corto, un bug silencioso que aparece cuando los datos no tienen el tamaño esperado.

Resumen

  • Los valores por defecto mutables (listas, dicts) se comparten entre llamadas. El patrón correcto es usar None como default y crear el objeto dentro de la función.
  • * en la firma fuerza keyword-only en los parámetros siguientes; es la práctica recomendada para APIs públicas estables.
  • Las funciones son objetos de primera clase: se pasan como argumentos, se retornan desde funciones y capturan el scope que las rodea (closures).
  • lambda es para expresiones simples de una línea; para lógica más compleja, def da nombres y es más legible.
  • enumerate, zip, any y all son built-ins que eliminan bucles manuales con índices; range es lazy y no consume memoria.
