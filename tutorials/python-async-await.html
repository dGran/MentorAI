asyncio: concurrencia sin hilos

El event loop y las corrutinas

El event loop es un bucle que monitoriza operaciones de I/O pendientes y reanuda la corrutina que estaba esperando cuando la operación termina. Todo ocurre en un único hilo del sistema operativo.

La diferencia clave con los hilos es el tipo de multitarea. Los hilos usan multitarea preemptiva: el sistema operativo interrumpe un hilo cuando quiere y cede el procesador a otro. Las corrutinas usan multitarea cooperativa: una corrutina cede el control explícitamente con await, y el event loop decide qué continuar.

import asyncio


async def corrutina_a() -> None:
    print("A: inicio")
    await asyncio.sleep(1)   # el loop puede ejecutar otras corrutinas aquí
    print("A: fin")


async def corrutina_b() -> None:
    print("B: inicio")
    await asyncio.sleep(0.5)
    print("B: fin")


async def main() -> None:
    await asyncio.gather(corrutina_a(), corrutina_b())


asyncio.run(main())
# A: inicio
# B: inicio
# B: fin    (B termina primero porque duerme menos)
# A: fin

Aunque corrutina_a se lanza primero, corrutina_b termina antes porque tiene un sleep más corto. Ambas avanzan de forma concurrente dentro del mismo hilo. Sin gather, si hicieras await corrutina_a() y luego await corrutina_b() de forma secuencial, tardarías 1.5 s; con gather tardas solo 1 s.

async/await en la práctica

async def define una función corrutina. Llamarla no la ejecuta: devuelve un objeto corrutina. Solo al hacer await sobre ella (o pasarla a asyncio.run()) comienza la ejecución.

import asyncio
import httpx


async def obtener_repositorios(usuario: str) -> list[dict]:
    async with httpx.AsyncClient() as cliente:
        respuesta = await cliente.get(
            f"https://api.github.com/users/{usuario}/repos",
            headers={"Accept": "application/vnd.github.v3+json"},
        )
        respuesta.raise_for_status()
        return respuesta.json()


async def main() -> None:
    repos = await obtener_repositorios("tiangolo")
    print(f"Encontrados {len(repos)} repositorios")


asyncio.run(main())

asyncio.run() crea el event loop, ejecuta la corrutina hasta que termina y luego destruye el loop. Es el punto de entrada de cualquier programa async y debe llamarse una sola vez, desde código síncrono.

Dentro de una corrutina, await solo puede aplicarse a objetos awaitable: otras corrutinas, asyncio.Task, asyncio.Future o cualquier objeto que implemente __await__. Usar await fuera de una función async def es un error de sintaxis.

gather y TaskGroup

asyncio.gather() lanza varias corrutinas de forma concurrente y espera a que todas terminen. Devuelve los resultados en el mismo orden en que se pasaron las corrutinas, independientemente del orden de finalización.

import asyncio
import httpx


async def obtener_precio(producto_id: int, cliente: httpx.AsyncClient) -> dict:
    respuesta = await cliente.get(
        f"https://api.tienda.com/productos/{producto_id}/precio"
    )
    respuesta.raise_for_status()
    return respuesta.json()


async def main() -> None:
    ids = [1, 2, 3, 4, 5]

    async with httpx.AsyncClient() as cliente:
        precios = await asyncio.gather(
            *[obtener_precio(producto_id, cliente) for producto_id in ids]
        )

    print(f"Obtenidos {len(precios)} precios")


asyncio.run(main())

Por defecto, si una corrutina lanza una excepción, gather la propaga. Con return_exceptions=True, los errores se devuelven como valores en la lista en lugar de propagarse, lo que permite tratar cada resultado individualmente.

TaskGroup (Python 3.11+) introduce concurrencia estructurada: si cualquier tarea del grupo falla, el grupo cancela automáticamente todas las demás y acumula los errores en un ExceptionGroup. Es más robusto para producción:

import asyncio
import httpx


async def descargar(url: str, cliente: httpx.AsyncClient) -> bytes:
    respuesta = await cliente.get(url)
    respuesta.raise_for_status()
    return respuesta.content


async def main() -> None:
    urls = [
        "https://api.a.com/datos",
        "https://api.b.com/datos",
        "https://api.c.com/datos",
    ]

    async with httpx.AsyncClient() as cliente:
        async with asyncio.TaskGroup() as grupo:
            tareas = [grupo.create_task(descargar(url, cliente)) for url in urls]

    resultados = [tarea.result() for tarea in tareas]
    print(f"Descargados {len(resultados)} recursos")


asyncio.run(main())

La diferencia práctica: con gather y return_exceptions=False, el primer fallo propaga la excepción pero las otras corrutinas continúan ejecutándose en segundo plano sin supervisión. Con TaskGroup, el fallo de cualquier tarea cancela todas las demás inmediatamente, sin tareas huérfanas.

Timeouts y cancelación

Llamar a una API externa sin timeout es un riesgo: si no responde, la corrutina queda suspendida indefinidamente. asyncio.timeout() (Python 3.11+) es el gestor de contexto moderno para limitar la duración de cualquier operación awaitable:

import asyncio
import httpx


async def llamar_api_externa(url: str) -> dict:
    async with httpx.AsyncClient() as cliente:
        respuesta = await cliente.get(url)
        return respuesta.json()


async def main() -> None:
    try:
        async with asyncio.timeout(2.0):
            datos = await llamar_api_externa("https://api.lenta.com/datos")
    except asyncio.TimeoutError:
        print("La API no respondió en 2 segundos")
        datos = {}

    print(datos)


asyncio.run(main())

Para versiones anteriores a 3.11, el equivalente es asyncio.wait_for(corrutina, timeout=segundos):

import asyncio


async def main() -> None:
    try:
        datos = await asyncio.wait_for(
            llamar_api_externa("https://api.lenta.com/datos"),
            timeout=2.0,
        )
    except asyncio.TimeoutError:
        datos = {}

    print(datos)

Cuando un timeout expira, asyncio cancela internamente la tarea lanzando CancelledError. Si tienes recursos que limpiar (conexiones, ficheros), atrapa CancelledError dentro de la corrutina, haz la limpieza y vuelve a lanzarlo para no silenciar la cancelación:

import asyncio


async def tarea_con_recursos() -> None:
    conexion = await abrir_conexion()

    try:
        await procesar(conexion)
    except asyncio.CancelledError:
        await conexion.close()
        raise

Cuándo elegir async, hilos o multiproceso

Async no es la solución universal a todos los problemas de rendimiento. La elección depende de dónde está el cuello de botella:

Modelo Cuándo usarlo Ejemplos de librerías
async/await I/O bound con librerías async nativas httpx, aiofiles, asyncpg, redis-py (async)
threading I/O bound con librerías síncronas que liberan el GIL durante I/O requests, psycopg2, boto3
multiprocessing CPU bound; cada proceso tiene su propio intérprete y GIL numpy, pandas, cálculo intensivo
El GIL y los hilos: el GIL de Python impide que dos hilos ejecuten bytecode Python en paralelo, por eso threading no ayuda con código CPU-bound. Pero durante operaciones de I/O (red, disco), el GIL se libera, y ahí varios hilos sí avanzan en paralelo. Async hace lo mismo sin el coste de cambio de contexto de los hilos del SO.

Si necesitas ejecutar código síncrono bloqueante desde una corrutina sin paralizar el event loop, delégalo a un pool de hilos con run_in_executor():

import asyncio
from concurrent.futures import ThreadPoolExecutor


def leer_fichero_grande(ruta: str) -> bytes:
    with open(ruta, "rb") as fichero:
        return fichero.read()


async def main() -> None:
    loop = asyncio.get_running_loop()

    with ThreadPoolExecutor() as pool:
        contenido = await loop.run_in_executor(
            pool,
            leer_fichero_grande,
            "/ruta/al/fichero.dat",
        )

    print(f"Leídos {len(contenido)} bytes")


asyncio.run(main())

Llamar directamente a una función bloqueante desde una corrutina sin run_in_executor paraliza todo el event loop: ninguna otra corrutina puede avanzar hasta que esa llamada síncrona termine.

Resumen

  • El event loop ejecuta corrutinas en un solo hilo; await es el punto de pausa cooperativa donde el loop puede reanudar otra corrutina pendiente.
  • asyncio.run() crea el event loop y lo destruye al terminar: es el único punto de entrada de cualquier aplicación async y debe llamarse una sola vez desde código síncrono.
  • asyncio.gather() lanza corrutinas concurrentes y devuelve sus resultados en orden; TaskGroup (3.11+) añade cancelación automática de todas las tareas si alguna falla, evitando tareas huérfanas.
  • asyncio.timeout() (3.11+) limita la duración de cualquier operación awaitable; asyncio.wait_for() cumple la misma función en versiones anteriores.
  • Async no acelera código CPU-bound; para eso usa ProcessPoolExecutor. Una librería síncrona bloqueante dentro de una corrutina congela el event loop: delégala con run_in_executor.
  • Elige threading cuando debes usar librerías síncronas con I/O; elige multiprocessing para cálculo intensivo; elige async cuando construyes servicios de alta concurrencia con librerías async nativas.
