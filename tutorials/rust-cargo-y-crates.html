Cargo: build, test, doc, publish

Cargo integra en una sola herramienta lo que en PHP requiere Composer + make + phpunit + phpDocumentor separados. Es el build system, gestor de dependencias, runner de tests, generador de documentación y herramienta de publicación de Rust.

ComandoEquivalente PHPQué hace
cargo buildphp artisan buildCompila el proyecto
cargo runphp artisan serveCompila y ejecuta
cargo test./vendor/bin/phpunitEjecuta todos los tests
cargo add serdecomposer require serdeAñade una dependencia
cargo updatecomposer updateActualiza dependencias respetando semver
cargo doc --openPHPDocGenera y abre documentación HTML
cargo publishcomposer publishPublica el crate en Crates.io
cargo fmtphp-cs-fixer fixFormatea el código
cargo clippyPHPStan/PsalmAnálisis estático y linting

El Cargo.lock funciona igual que el composer.lock: fija las versiones exactas de todas las dependencias transitivas. Debe commitearse en proyectos de aplicación (para reproducibilidad) y excluirse en librerías (para que los usuarios tengan flexibilidad en las versiones).

Crates.io: el registro de paquetes

Crates.io es el registro público de crates de Rust, equivalente a Packagist para PHP. Tiene más de 140.000 crates publicados.

cargo add serde
cargo add serde --features derive
cargo add tokio --features full
cargo add sqlx --features postgres,runtime-tokio-rustls

cargo add (disponible desde Rust 1.62) actualiza el Cargo.toml automáticamente. Antes había que editar el fichero a mano.

Las versiones siguen semver estricto. La notación de versiones en Cargo.toml:

[dependencies]
serde = "1.0"         # ^1.0: >=1.0.0, <2.0.0 (compatible)
tokio = "~1.28"       # ~1.28: >=1.28.0, <1.29.0 (patch solo)
uuid = "=1.3.0"       # versión exacta
rand = "*"            # cualquier versión (no recomendado)

Para dependencias de desarrollo (tests, benchmarks) que no se incluyen en el binario de producción:

[dev-dependencies]
criterion = "0.5"
mockall = "0.12"

Features: compilación condicional

Las features permiten habilitar funcionalidades opcionales de una crate. Reducen el tiempo de compilación y el tamaño del binario al incluir solo lo necesario.

[dependencies]
tokio = { version = "1", features = ["full"] }
serde = { version = "1", features = ["derive"] }
sqlx = { version = "0.7", features = ["postgres", "runtime-tokio-rustls", "macros"] }
reqwest = { version = "0.11", features = ["json"] }

Sin features = ["full"], Tokio solo incluye el código base sin el I/O async, timers, canales, etc. Con "full", incluye todo. Para producción, es mejor especificar solo las features que usas para reducir la compilación.

Puedes definir features propias en tu crate para exponer funcionalidades opcionales:

[features]
default = []
postgres = ["dep:sqlx"]
redis = ["dep:fred"]
metricas = ["dep:prometheus"]

[dependencies]
sqlx = { version = "0.7", optional = true }
fred = { version = "7", optional = true }
prometheus = { version = "0.13", optional = true }

El usuario de la librería activa solo las features que necesita: mi-crate = { version = "1", features = ["postgres", "metricas"] }.

Workspaces: monorepo Rust

Un workspace agrupa varios crates en el mismo repositorio compartiendo un único Cargo.lock y directorio target/. Equivalente a un monorepo con workspaces de npm o a múltiples paquetes de Composer en el mismo repositorio.

mi-servicio/
├── Cargo.toml          # workspace root
├── Cargo.lock
├── crates/
│   ├── api/            # crate del servidor HTTP
│   │   └── Cargo.toml
│   ├── dominio/        # crate de lógica de negocio
│   │   └── Cargo.toml
│   └── infraestructura/ # crate de acceso a datos
│       └── Cargo.toml
└── target/

El Cargo.toml del workspace root:

[workspace]
members = [
    "crates/api",
    "crates/dominio",
    "crates/infraestructura",
]

[workspace.dependencies]
tokio = { version = "1", features = ["full"] }
serde = { version = "1", features = ["derive"] }

La sección [workspace.dependencies] centraliza las versiones de dependencias compartidas. Los crates individuales las referencian sin repetir la versión:

[dependencies]
tokio.workspace = true
serde.workspace = true

Todos los crates del workspace comparten el mismo Cargo.lock: las versiones son consistentes en todo el monorepo.

Resumen

  • Cargo integra build, test, doc y gestión de dependencias en una herramienta. Es el equivalente completo de Composer + phpunit + php-cs-fixer + PHPStan juntos.
  • Crates.io es el registro de paquetes; cargo add añade dependencias y actualiza Cargo.toml automáticamente.
  • Las features habilitan funcionalidades opcionales: tokio = { features = ["full"] }. Usar solo las features necesarias reduce tiempo de compilación y tamaño del binario.
  • Los workspaces agrupan múltiples crates en un monorepo con Cargo.lock compartido y versiones centralizadas en [workspace.dependencies].
  • El stack de backend Rust está consolidado: tokio + axum + serde + sqlx + tracing cubre la mayoría de servicios web.
