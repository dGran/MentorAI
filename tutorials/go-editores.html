gopls: el corazón del tooling

gopls (pronunciado "go please") es el language server oficial de Go. Es el mismo binario que usa GoLand, VS Code y cualquier editor con soporte LSP. Proporciona autocompletado, navegación al código fuente, refactoring, diagnóstico de errores en tiempo real y documentación inline.

Que ambos editores compartan el mismo language server tiene una implicación práctica: la calidad del tooling es la misma. La diferencia real entre editores es la integración, la UX y cuánto hay que configurar.

GoLand

GoLand es el IDE de JetBrains para Go. Si ya usas PhpStorm, la transición es casi inmediata: mismo layout, mismos atajos de teclado, misma filosofía. Están basados en la misma plataforma IntelliJ.

Ventajas sobre VS Code

  • Cero configuración inicial — detecta el proyecto Go y configura gopls automáticamente.
  • Integración con Docker nativa — puede ejecutar y depurar el código directamente en el contenedor sin plugins extra.
  • Refactoring avanzado — renombrar un tipo o extraer una función propaga el cambio con más fiabilidad que VS Code.
  • Misma experiencia que PhpStorm — si ya tienes los atajos de JetBrains en el músculo, no hay que reaprender nada.

Configurar el Go remoto en el contenedor

Con el contenedor corriendo, en GoLand:

  1. Settings → Go → GOROOT → Add SDK → From Docker
  2. Selecciona el contenedor app de tu compose
  3. GoLand usará el Go del contenedor para indexar y analizar
GoLand es de pago pero tiene 30 días de prueba gratuita y licencias gratuitas para estudiantes y proyectos open source. Si ya tienes una suscripción JetBrains All Products Pack (común en empresas), GoLand está incluida.

VS Code + extensión Go

La extensión oficial de Go para VS Code (publicada por el equipo de Go) instala gopls y configura el editor automáticamente. Es gratuita y la opción más popular en la comunidad.

Instalación

# Instala la extensión desde la terminal de VS Code
code --install-extension golang.go

Al abrir un proyecto Go por primera vez, VS Code pedirá instalar las herramientas necesarias (gopls, dlv, golangci-lint). Acepta todo.

Configuración recomendada (.vscode/settings.json)

{
  "go.formatTool": "goimports",
  "editor.formatOnSave": true,
  "go.lintTool": "golangci-lint",
  "go.lintOnSave": "workspace",
  "go.testOnSave": false,
  "[go]": {
    "editor.codeActionsOnSave": {
      "source.organizeImports": "explicit"
    }
  }
}

Remote Containers / Dev Containers

La extensión Dev Containers de VS Code permite abrir el proyecto directamente dentro del contenedor Docker. El editor se conecta al contenedor y gopls se ejecuta ahí, usando el Go del contenedor. Es la integración más limpia para trabajo dockerizado:

# .devcontainer/devcontainer.json
{
  "name": "Go Dev",
  "dockerComposeFile": "../compose.yaml",
  "service": "app",
  "workspaceFolder": "/app",
  "extensions": ["golang.go"],
  "settings": {
    "go.formatTool": "goimports",
    "editor.formatOnSave": true
  }
}

gofmt y goimports

Go resolvió las guerras de estilo de una vez: gofmt es el formateador oficial y no tiene opciones. O tu código está formateado según gofmt, o no está formateado. Punto. El ecosistema (CI, revisiones de código, editores) asume que todo el código Go pasa por gofmt.

goimports hace lo mismo que gofmt y además gestiona los imports: añade los que faltan y elimina los que no se usan (el compilador rechaza imports no usados, así que esto es obligatorio).

# Formatear un fichero
gofmt -w main.go

# Formatear todo el proyecto
gofmt -w .

# goimports también gestiona imports
goimports -w .

# Ver qué cambiaría sin aplicarlo
gofmt -d main.go

Con el editor configurado con "editor.formatOnSave": true nunca necesitas ejecutarlos manualmente.

Depurar con delve

delve (o dlv) es el debugger de Go. Funciona con breakpoints, inspección de variables, step-in/step-out y expresiones en tiempo de pausa, igual que el debugger de PhpStorm.

# Instalar delve (dentro del contenedor)
go install github.com/go-delve/delve/cmd/dlv@latest

# Ejecutar el programa en modo debug
dlv debug ./cmd/server/

# Dentro del prompt de dlv:
# b main.go:25     -> poner breakpoint en línea 25
# c                -> continuar hasta el breakpoint
# p variable       -> imprimir el valor de variable
# n                -> siguiente línea
# s                -> entrar en la función
# q                -> salir

Tanto GoLand como VS Code tienen integración gráfica con delve: puedes poner breakpoints con un clic y ver las variables en un panel lateral, igual que en PhpStorm con Xdebug.

Apuntar el editor al contenedor

La situación habitual: el código está en el host, el Go está en el contenedor. Tienes tres opciones:

OpciónCómo funcionaComplejidad
Go localInstalar Go en el host solo para el editor (misma versión que el contenedor)Baja
GoLand + Docker SDKGoLand se conecta al contenedor para indexarMedia
VS Code Dev ContainersEl editor se ejecuta dentro del contenedorMedia

La opción más sencilla para empezar es instalar Go en el host con la misma versión que el contenedor, solo para que el editor tenga el toolchain disponible. No se usa para ejecutar el código (eso siempre ocurre dentro del contenedor), solo para el language server.

# Ubuntu/Debian: instalar Go localmente (solo para el editor)
wget https://go.dev/dl/go1.23.linux-amd64.tar.gz
sudo tar -C /usr/local -xzf go1.23.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.zshrc

Resumen

  • gopls es el language server compartido por todos los editores; la calidad del tooling es la misma en todos.
  • GoLand es la transición natural desde PhpStorm: cero configuración, integración Docker nativa, mismos atajos.
  • VS Code con la extensión Go es gratuito y la opción más popular; Dev Containers integra el editor directamente en el contenedor.
  • gofmt no tiene opciones: todo el código Go en el mundo tiene el mismo formato. Configura el editor para formatear al guardar.
  • goimports hace lo mismo que gofmt y además gestiona los imports automáticamente.
  • delve es el debugger; tanto GoLand como VS Code tienen integración gráfica con él.
