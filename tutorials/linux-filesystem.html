Linux: el árbol de directorios, inodos y discos

Antes de ejecutar comandos, conviene entender sobre qué terreno pisas. Cómo está organizado el sistema de ficheros, qué significa que "todo sea un fichero", qué es un inodo y cómo gestionar el espacio en disco.

Linux hereda la filosofía Unix. Antes de aprender comandos, entender esa filosofía cambia cómo lees el sistema: deja de ser una caja negra y empieza a tener sentido.

Todo es un fichero#

La idea central de Unix/Linux es que casi todo el sistema se expone como un fichero. No solo los documentos y scripts: los discos, los dispositivos, los procesos, las conexiones de red y la configuración del kernel son ficheros o se comportan como tales.

RecursoRuta en el filesystemPara qué sirve
Disco duro/dev/sda, /dev/nvme0n1Leer/escribir sectores directamente
Proceso (PID 1234)/proc/1234/Ver memoria, ficheros abiertos, estado
Kernel tunable/proc/sys/net/ipv4/ip_forwardecho 1 > ruta activa el routing
Terminal actual/dev/ttyLeer/escribir en la consola
Memoria del sistema/proc/meminfoRAM total, libre, buffers, caché

La consecuencia práctica: las mismas herramientas que usas para ficheros de texto (cat, grep, tail) funcionan en buena parte de estos "ficheros especiales". cat /proc/meminfo muestra el estado de la memoria; tail -f /var/log/syslog sigue el log del sistema en tiempo real.

El árbol FHS#

El Filesystem Hierarchy Standard (FHS) define dónde va cada cosa en Linux. El árbol arranca en / (raíz) y todo cuelga de ahí. No hay letras de unidad como en Windows.

bash · árbol simplificado
/
├── bin/        # Binarios esenciales del sistema (ls, cp, bash...)
├── sbin/       # Binarios de administración (fdisk, iptables...)
├── etc/        # Configuración del sistema (ficheros de texto)
├── home/       # Directorios personales de los usuarios (/home/david)
├── root/       # Directorio personal del usuario root
├── var/        # Datos variables: logs, colas, bases de datos locales
│   ├── log/    # Logs del sistema y aplicaciones
│   └── www/    # Web roots (en algunas distros)
├── tmp/        # Temporal; se borra al reiniciar (en la mayoría)
├── usr/        # Programas y datos de usuario (el "segundo árbol")
│   ├── bin/    # Binarios de usuario (git, php, python...)
│   ├── lib/    # Librerías
│   └── share/  # Datos compartidos independientes de arquitectura
├── lib/        # Librerías esenciales del sistema
├── proc/       # Sistema de ficheros virtual: estado del kernel y procesos
├── sys/        # Sistema de ficheros virtual: dispositivos y kernel
├── dev/        # Dispositivos (discos, terminales, /dev/null, /dev/random)
├── mnt/        # Punto de montaje temporal para discos externos
├── media/      # Montaje automático (USB, CD...)
├── opt/        # Software de terceros instalado fuera del gestor de paquetes
├── srv/        # Datos servidos (HTTP, FTP...)
└── boot/       # Kernel e initramfs (lo que arranca el sistema)
DirectorioQué encontrarás allí como desarrollador
/etcConfiguración de nginx, PHP-FPM, MySQL, SSH, cron… Todo en texto plano.
/var/logLogs de nginx (access.log, error.log), PHP, MySQL, syslog.
/tmpFicheros temporales. Nunca guardes nada importante aquí.
/procLee /proc/cpuinfo, /proc/meminfo, /proc/<pid>/cmdline.
/dev/nullEl "agujero negro": todo lo que escribes desaparece. Útil para silenciar salidas.

/etc siempre en texto plano

Una de las mejores decisiones de Unix: la configuración del sistema son ficheros de texto legibles. cat /etc/nginx/nginx.conf, grep -r "listen" /etc/nginx/, git diff /etc/nginx/. Todo funciona.

Tipos de fichero#

En Linux no todo lo que aparece como "fichero" en un listado es lo mismo. ls -l muestra el tipo en el primer carácter de los permisos:

bash
-rw-r--r--  fichero regular (texto, binario, imagen...)
drwxr-xr-x  directorio
lrwxrwxrwx  enlace simbólico (symlink)
brw-rw----  dispositivo de bloque (disco, partición)
crw-rw-rw-  dispositivo de carácter (terminal, /dev/null)
prw-r--r--  pipe con nombre (FIFO)
srwxrwxrwx  socket Unix
TipoEjemplos realesCuándo te lo encuentras
Regular (-)Scripts, binarios, logs, configsTodo el tiempo
Directorio (d)/etc, /var/logTodo el tiempo
Symlink (l)/usr/bin/php → php8.2Versiones de PHP, alternativas
Bloque (b)/dev/sda, /dev/nvme0n1Al gestionar discos
Socket (s)/var/run/php/php-fpm.sockPHP-FPM, MySQL, Redis

Inodos#

Un inodo (index node) es la estructura de datos que el filesystem mantiene por cada fichero: guarda los metadatos (permisos, propietario, tamaño, timestamps, bloques de datos en disco) pero no el nombre del fichero. El nombre vive en el directorio que apunta al inodo.

1Directorio/home/david/app
2Inodo 48291permisos, owner, size, timestamps, bloques
3Bloques de datosel contenido real del fichero

El nombre es solo un alias que apunta a un inodo. Un inodo puede tener varios nombres (hard links).

bash · ver inodos
ls -li archivo.txt          # -i muestra el número de inodo
stat archivo.txt            # todos los metadatos del inodo
df -i /                     # inodos usados/libres en cada partición

Se pueden agotar los inodos sin llenar el disco

Cada filesystem tiene un número fijo de inodos (reservado al formatearlo). Si creas millones de ficheros pequeños (logs, caché, sesiones PHP) puedes quedarte sin inodos aunque quede espacio libre. df -i lo muestra; es el primer diagnóstico cuando el sistema dice "no space left" pero df -h muestra espacio libre.

Discos y filesystems#

En Linux un disco no se "conecta" automáticamente al árbol: hay que montarlo en un punto de montaje (un directorio vacío). El kernel mapea ese directorio al filesystem del disco.

bash · dispositivos y montaje
lsblk                       # árbol de discos y particiones
lsblk -f                    # añade filesystem, UUID y punto de montaje

# Ejemplo de salida:
# NAME        FSTYPE  SIZE  MOUNTPOINT
# sda                  50G
# ├─sda1      ext4     48G  /
# └─sda2      swap      2G  [SWAP]

cat /proc/mounts            # lo que está montado ahora mismo
mount | grep "^/dev"        # equivalente, más legible

# Montar manualmente (necesita root):
mount /dev/sdb1 /mnt/datos
umount /mnt/datos           # desmontar antes de extraer

# /etc/fstab: montaje automático al arrancar
cat /etc/fstab

xfsServidores de alta carga, RHEL/CentOSMuy eficiente con ficheros grandes

Gestionar el espacio#

bash · df y du
# df: espacio por filesystem (Disk Free)
df -h                       # -h = human readable (GB, MB)
df -h /var/log              # solo el filesystem donde vive esa ruta
df -i                       # inodos en lugar de bloques

# du: espacio ocupado por directorios (Disk Usage)
du -sh /var/log             # total del directorio (-s summary, -h human)
du -sh /var/log/*           # por subdirectorio
du -h /var/log | sort -rh | head -20   # los 20 directorios más grandes

# Buscar ficheros grandes rápidamente:
find /var -size +100M -type f          # ficheros mayores de 100 MB
find /tmp -mtime +7 -type f            # ficheros no tocados en 7 días

El disco "lleno" más común en servidores PHP

Los candidatos habituales son /var/log (logs de nginx/PHP sin rotar), /tmp (sesiones PHP acumuladas) y el directorio de uploads sin política de retención. du -sh /var/log/* | sort -rh | head suele señalar al culpable en segundos.

Resumen#

Lo que te llevas

  • "Todo es un fichero": dispositivos, procesos y configuración del kernel se exponen como ficheros y responden a las mismas herramientas.
  • El árbol FHS define dónde va cada cosa: /etc = configs, /var/log = logs, /tmp = temporal, /proc = kernel virtual, /dev = dispositivos.
  • El tipo de fichero se ve en el primer carácter de ls -l: - regular, d directorio, l symlink, s socket.
  • Un inodo guarda los metadatos del fichero; el nombre es solo un alias en el directorio. Los inodos se pueden agotar independientemente del espacio en disco.
  • lsblk -f muestra discos y particiones; df -h el espacio por filesystem; du -sh directorio el espacio que ocupa un árbol.
