El intérprete interactivo

Python incluye un REPL (Read-Eval-Print Loop) que permite explorar el lenguaje línea a línea. A diferencia de PHP, donde todo el código se ejecuta a través del servidor web, Python puede ejecutarse directamente en el terminal.

>>> 1 + 1
2
>>> "hola".upper()
'HOLA'
>>> type(42)
<class 'int'>
>>> [x ** 2 for x in range(5)]
[0, 1, 4, 9, 16]
>>> help(str.split)
>>> exit()

Dos funciones que conviene conocer desde el principio: help(objeto) imprime la documentación del objeto, y dir(objeto) lista todos sus atributos y métodos. Son la referencia integrada del lenguaje.

IPython y Jupyter: el REPL estándar de Python es básico. IPython ofrece autocompletado, historial persistente y visualización de tipos. Jupyter Notebook permite mezclar código, salida y texto en un documento interactivo. Para data science, Jupyter es el entorno estándar.

Scripts .py

Un fichero .py es un módulo Python que se puede ejecutar directamente. La convención if __name__ == "__main__": distingue entre ejecutar un fichero directamente e importarlo como módulo:

#!/usr/bin/env python3


def calcular_descuento(precio: float, porcentaje: float) -> float:
    return precio * (1 - porcentaje / 100)


def formatear_precio(precio: float) -> str:
    return f"{precio:.2f}€"


if __name__ == "__main__":
    precio_original = 100.0
    precio_final = calcular_descuento(precio_original, 20)
    print(f"Precio final: {formatear_precio(precio_final)}")

Cuando Python ejecuta python3 script.py, la variable especial __name__ vale "__main__". Cuando otro módulo importa este fichero, __name__ vale "script". Esto permite que el código bajo el if solo se ejecute cuando el fichero es el punto de entrada principal.

En PHP no existe este concepto: cualquier código de nivel superior se ejecuta en el momento de include o require, lo que obliga a envolver todo en funciones o usar guardas específicas de framework.

El shebang #!/usr/bin/env python3 en la primera línea permite ejecutar el script directamente tras darle permisos de ejecución (chmod +x script.py). En Windows se ignora.

Virtual environments

Un virtual environment es un directorio que contiene una copia del intérprete Python y un espacio aislado de paquetes. El problema que resuelve es el mismo que composer.json por proyecto en PHP: el proyecto A necesita requests==2.x y el proyecto B necesita requests==3.x, y ambas versiones no pueden coexistir en la instalación global.

python3 -m venv .venv
source .venv/bin/activate
pip install fastapi httpx
python3 script.py
deactivate

Con uv, el gestor moderno, el flujo es más limpio:

uv venv
uv add fastapi httpx
uv run python3 script.py

uv run activa el entorno virtual implícitamente para ese comando. No hace falta source .venv/bin/activate ni acordarse de desactivar.

El fichero pyproject.toml es el equivalente a composer.json: declara las dependencias del proyecto. El fichero uv.lock es el equivalente a composer.lock: fija versiones exactas para reproducibilidad:

[project]
name = "mi-api"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "fastapi>=0.111",
    "uvicorn[standard]>=0.29",
    "httpx>=0.27",
]

[dependency-groups]
dev = [
    "pytest>=8.0",
    "ruff>=0.4",
]

Primer programa útil

Un script que consulta la API pública de GitHub y muestra los repositorios más recientes de un usuario. Usa httpx, la alternativa moderna y async-compatible a requests:

import httpx


def obtener_repositorios(usuario: str, limite: int = 5) -> list[dict]:
    url = f"https://api.github.com/users/{usuario}/repos"
    params = {"per_page": limite, "sort": "updated"}

    with httpx.Client(timeout=10.0) as cliente:
        respuesta = cliente.get(url, params=params)
        respuesta.raise_for_status()
        return respuesta.json()


def mostrar_repositorios(repositorios: list[dict]) -> None:
    for repo in repositorios:
        nombre = repo["name"]
        estrellas = repo["stargazers_count"]
        descripcion = repo.get("description") or "Sin descripción"
        print(f"  ★ {estrellas:>5}  {nombre}: {descripcion}")


if __name__ == "__main__":
    usuario = "torvalds"
    print(f"Repositorios de {usuario}:\n")

    repositorios = obtener_repositorios(usuario)
    mostrar_repositorios(repositorios)

Algunos detalles que vale la pena señalar:

  • Type hints en las firmas: list[dict] dice que devuelve una lista de diccionarios. El editor puede inferir que repo es un dict y ofrecer autocompletado.
  • with httpx.Client() as cliente:: el context manager garantiza que la conexión se cierra aunque ocurra una excepción. Equivalente al finally de PHP pero sin el boilerplate.
  • raise_for_status(): lanza una excepción si el status HTTP es 4xx o 5xx. Sin esta línea, un error de la API pasa silenciosamente.
  • repo.get("description") or "Sin descripción": .get() devuelve None si la clave no existe; el or proporciona el fallback.
  • f"{estrellas:>5}": formatea el número con alineación a la derecha en un campo de 5 caracteres, para que la columna quede alineada.

Resumen

  • El REPL de Python es una herramienta de exploración real: help() y dir() dan acceso a la documentación sin salir del terminal.
  • if __name__ == "__main__": es la forma idiomática de separar código de ejecución directa de código importable como módulo.
  • Los virtual environments aíslan dependencias por proyecto; uv es el gestor moderno que los crea y gestiona automáticamente sin activación manual.
  • pyproject.toml + uv.lock son el equivalente a composer.json + composer.lock: dependencias declaradas y versiones fijadas.
  • El primer programa real usa type hints, context managers y la stdlib estándar desde el primer día, sin simplificar artificialmente.
