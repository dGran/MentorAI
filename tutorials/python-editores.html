Pylance en VS Code

Pylance es la extensión de VS Code que envuelve Pyright, el type checker estático de Microsoft. Proporciona completado basado en tipos, inferencia, documentación al vuelo y errores en tiempo real sin ejecutar el código. La diferencia con el soporte Python genérico es la misma que entre tener un LSP completo y tener solo syntax highlighting.

Extensiones a instalar: ms-python.python (base) y ms-python.pylance (análisis). Ruff se instala por separado.

Configuración recomendada en .vscode/settings.json:

{
    "python.analysis.typeCheckingMode": "basic",
    "python.analysis.autoImportCompletions": true,
    "python.analysis.inlayHints.functionReturnTypes": true,
    "[python]": {
        "editor.defaultFormatter": "charliermarsh.ruff",
        "editor.formatOnSave": true,
        "editor.codeActionsOnSave": {
            "source.fixAll.ruff": "explicit",
            "source.organizeImports.ruff": "explicit"
        }
    }
}

typeCheckingMode acepta cuatro valores: "off" (solo completado), "basic" (errores obvios), "standard" (más estricto) y "strict" (máximo rigor, equivalente a mypy strict). Para empezar, "basic" es el punto de equilibrio: detecta problemas reales sin ser tan estricto que abrume con advertencias en código no anotado.

Pylance vs mypy: Pylance (Pyright) hace el análisis de tipos en el editor, en tiempo real. mypy hace lo mismo en CI o en pre-commit. Para un proyecto serio, ambos se complementan: Pylance da feedback inmediato mientras escribes, mypy da el veredicto definitivo en el pipeline.

PyCharm

Para quien viene de PhpStorm, PyCharm Professional es la transición más natural: mismo IDE, mismos atajos de teclado, misma filosofía de integración profunda con el lenguaje. La curva de aprendizaje del entorno es prácticamente cero.

CaracterísticaCommunity (gratis)Professional (de pago)
Edición Python, tests, refactoringSíSí
Soporte Django / FastAPINoSí
Intérprete remoto (Docker/SSH)NoSí
Cliente HTTP integradoNoSí
Herramientas de base de datosNoSí

El intérprete remoto de PyCharm Professional permite conectar al Python del contenedor Docker directamente: Settings → Project → Python Interpreter → Add → Docker Compose. El IDE ejecuta el código y los tests dentro del contenedor, con el mismo entorno que producción.

Ventajas de PyCharm frente a VS Code para Python: refactoring más robusto (rename de símbolos a través de módulos, extract method con análisis de tipos), el cliente HTTP integrado similar al de PhpStorm y las herramientas de base de datos con navegación de esquemas.

Ruff: linter y formatter

Ruff está escrito en Rust y es 10-100× más rápido que flake8+black combinados. Más importante: reemplaza a toda la toolchain clásica en un solo binario.

Herramienta reemplazadaFunción
flake8Linting (errores de estilo y bugs simples)
blackFormateo de código
isortOrdenar imports
pyupgradeActualizar sintaxis a versiones modernas de Python
flake8-bugbearDetección de bugs sutiles

Configuración en pyproject.toml:

[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM"]

[tool.ruff.format]
quote-style = "double"
indent-style = "space"

Los rule sets más útiles: E (pycodestyle), F (pyflakes, detecta variables no usadas e imports fantasma), I (isort), UP (pyupgrade: sugiere X | Y en lugar de Union[X, Y]), B (bugbear: mutable defaults, comparaciones con is en lugar de ==), SIM (simplificaciones de código).

ruff check .
ruff format .
ruff check --fix .

Dev Containers y acceso al contenedor

VS Code Dev Containers resuelve el problema fundamental: el código está en el host pero el intérprete está en el contenedor. En lugar de apuntar el editor al Python del host (que no tiene las dependencias del proyecto), Dev Containers abre VS Code desde dentro del contenedor.

.devcontainer/devcontainer.json:

{
    "name": "Python API",
    "dockerComposeFile": "../compose.yml",
    "service": "app",
    "workspaceFolder": "/app",
    "customizations": {
        "vscode": {
            "extensions": [
                "ms-python.python",
                "ms-python.pylance",
                "charliermarsh.ruff"
            ],
            "settings": {
                "python.analysis.typeCheckingMode": "basic"
            }
        }
    },
    "postCreateCommand": "uv sync"
}

Con este fichero, VS Code detecta el contenedor disponible, ofrece reabrirlo en el contenedor y desde ese momento el intérprete, los imports, los tests y el linter trabajan sobre el Python del contenedor. No hay desfase entre lo que el editor ve y lo que ejecuta.

PyCharm + Docker: PyCharm Professional configura el intérprete remoto desde Settings → Project → Python Interpreter → Add → On Docker Compose. Seleccionas el servicio app y PyCharm ejecuta el código directamente en el contenedor, sin necesidad de Dev Containers.

Resumen

  • Pylance (Pyright) en VS Code ofrece type checking en tiempo real, completado basado en tipos y errores antes de ejecutar; typeCheckingMode: "basic" es el punto de equilibrio para empezar.
  • PyCharm Professional es la transición más natural desde PhpStorm: mismo IDE, intérprete Docker integrado y cliente HTTP.
  • Ruff reemplaza flake8 + black + isort + pyupgrade en un solo binario escrito en Rust; la configuración va en pyproject.toml.
  • Dev Containers (VS Code) y el intérprete remoto de Docker (PyCharm) eliminan el desfase entre el entorno del editor y el del contenedor.
