Pattern matching en Rust

El match exhaustivo de Rust: desestructuración, guards, if let, while let, y cómo reemplaza toda una familia de if/else.

match exhaustivo

El match de Rust es la construcción de control de flujo más potente del lenguaje. A diferencia del switch de PHP, es exhaustivo: el compilador exige que se cubran todos los casos posibles o el código no compila.

enum EstadoPedido {
    Pendiente,
    Procesando,
    Enviado { numero_tracking: String },
    Entregado,
    Cancelado(String),
}

fn describir_estado(estado: &EstadoPedido) -> String {
    match estado {
        EstadoPedido::Pendiente => String::from("Esperando procesamiento"),
        EstadoPedido::Procesando => String::from("En preparación"),
        EstadoPedido::Enviado { numero_tracking } => {
            format!("En camino — tracking: {}", numero_tracking)
        }
        EstadoPedido::Entregado => String::from("Entregado con éxito"),
        EstadoPedido::Cancelado(motivo) => format!("Cancelado: {}", motivo),
    }
}

Si añades una nueva variante al enum (Devuelto, por ejemplo), el compilador marcará cada match sobre ese enum que no la cubra. Esto es invaluable en proyectos grandes: añadir un estado nuevo no puede pasar desapercibido.

El _ actúa como catch-all para los casos que no quieres manejar individualmente:

match codigo_http {
    200 => manejar_ok(),
    404 => manejar_no_encontrado(),
    _ => manejar_otro(),
}

El | combina varios patrones en un solo brazo:

match c {
    'a' | 'e' | 'i' | 'o' | 'u' => println!("vocal"),
    'a'..='z' => println!("consonante"),
    _ => println!("otro"),
}

Desestructuración de structs y enums

El match puede desestructurar structs directamente:

struct Punto {
    x: i32,
    y: i32,
}

fn clasificar_punto(punto: &Punto) {
    match punto {
        Punto { x: 0, y: 0 } => println!("origen"),
        Punto { x: 0, y } => println!("sobre el eje Y: {}", y),
        Punto { x, y: 0 } => println!("sobre el eje X: {}", x),
        Punto { x, y } => println!("en ({}, {})", x, y),
    }
}

El operador .. ignora los campos que no te interesan:

struct Usuario {
    id: u32,
    nombre: String,
    email: String,
    activo: bool,
}

fn main() {
    let usuario = Usuario {
        id: 1,
        nombre: String::from("Ana"),
        email: String::from("ana@ejemplo.com"),
        activo: true,
    };

    let Usuario { nombre, activo, .. } = usuario;
    println!("{} — activo: {}", nombre, activo);
}

Guards: condiciones adicionales

Los guards añaden condiciones extra a un patrón con la palabra clave if después del patrón:

fn clasificar_numero(n: i32) -> &'static str {
    match n {
        x if x < 0 => "negativo",
        0 => "cero",
        x if x % 2 == 0 => "par positivo",
        _ => "impar positivo",
    }
}

Los guards son útiles cuando el patrón por sí solo no puede expresar la condición. El compilador sigue verificando exhaustividad: si los guards no cubren todos los casos de una variante, el _ final debe existir.

enum Mensaje {
    Mover { x: i32, y: i32 },
    Escribir(String),
    Activar,
}

fn procesar(msg: Mensaje) {
    match msg {
        Mensaje::Mover { x, y } if x == y => println!("movimiento diagonal a {}", x),
        Mensaje::Mover { x, y } => println!("mover a ({}, {})", x, y),
        Mensaje::Escribir(texto) if texto.is_empty() => println!("texto vacío"),
        Mensaje::Escribir(texto) => println!("escribir: {}", texto),
        Mensaje::Activar => println!("activado"),
    }
}

if let

if let es azúcar sintáctico para un match cuando solo te importa un patrón y quieres ignorar el resto. Es más legible que un match de un solo caso con _ => {}:

let config = Some(("localhost", 5432));

if let Some((host, puerto)) = config {
    println!("Conectando a {}:{}", host, puerto);
}

let resultado: Result<i32, &str> = Ok(42);

if let Ok(valor) = resultado {
    println!("Éxito: {}", valor);
} else {
    println!("Error");
}

Puedes encadenar if let con else if let para manejar varios casos distintos sin la estructura completa de un match:

fn main() {
    let valor: Option<i32> = Some(7);

    if let Some(n) = valor {
        println!("Tenemos: {}", n);
    } else {
        println!("No hay valor");
    }
}

while let

while let itera mientras el patrón encaja. El caso más típico es consumir elementos de una estructura hasta que se agote:

fn main() {
    let mut pila: Vec<i32> = vec![1, 2, 3, 4, 5];

    while let Some(tope) = pila.pop() {
        println!("Procesando: {}", tope);
    }

    println!("Pila vacía");
}

También es útil con canales de mensajes: iterar mientras llegan mensajes y parar cuando el canal se cierra:

use std::sync::mpsc;

fn main() {
    let (tx, rx) = mpsc::channel();
    tx.send(1).unwrap();
    tx.send(2).unwrap();
    drop(tx); // cierra el canal

    while let Ok(mensaje) = rx.recv() {
        println!("Recibido: {}", mensaje);
    }
}

Patrones en let y parámetros

Los patrones no son exclusivos del match: cualquier let es un patrón, y los parámetros de funciones también lo son.

fn main() {
    let (x, y, z) = (1, 2, 3);
    println!("{} {} {}", x, y, z);

    let (primero, .., ultimo) = (1, 2, 3, 4, 5);
    println!("{} y {}", primero, ultimo);
}

struct Punto { x: f64, y: f64 }

fn distancia_al_origen(&Punto { x, y }: &Punto) -> f64 {
    (x * x + y * y).sqrt()
}

fn main() {
    let punto = Punto { x: 3.0, y: 4.0 };
    println!("Distancia: {}", distancia_al_origen(&punto)); // 5.0
}

Desestructurar en el parámetro de función es útil cuando el caller siempre tiene la estructura entera pero la función solo necesita algunos campos.

Resumen

  • El match es exhaustivo: el compilador exige cubrir todos los casos posibles. Añadir una variante a un enum marca todos los match incompletos.
  • La desestructuración en match extrae campos de structs y enums con tipo verificado, sin casting ni instanceof.
  • Los guards (if condicion después del patrón) añaden condiciones que no pueden expresarse solo con el patrón.
  • if let es la forma concisa de manejar un solo caso de un match; más legible que match con un brazo activo y _ => {}.
  • while let itera mientras el patrón encaja; natural para consumir Option, Result o canales de mensajes.
  • Los patrones funcionan en let, en parámetros de función y en cualquier lugar que enlace variables.
