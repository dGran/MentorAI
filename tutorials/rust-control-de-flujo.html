Control de flujo en Rust

if/else como expresión, loop con valor de retorno, while, for con iteradores y ranges, y el match básico.

if como expresión

En PHP, if es una sentencia: controla el flujo pero no produce un valor. En Rust, if es una expresión: produce un valor que puedes asignar directamente a una variable.

fn main() {
    let temperatura = 22;

    let descripcion = if temperatura > 30 {
        "calor"
    } else if temperatura > 15 {
        "agradable"
    } else {
        "frío"
    };

    println!("Hace {}", descripcion);
}

Rust no tiene operador ternario (? :). El if como expresión es el sustituto directo, pero más legible: cada rama puede ser un bloque de varias líneas.

Los tipos deben coincidir: todas las ramas del if deben producir el mismo tipo. Si una rama retorna "calor" (&str) y otra retorna 42 (i32), el compilador lo rechaza. Esto es consistente: la variable no puede tener tipos distintos según la condición.

El if clásico sin asignación también funciona igual que en PHP:

if condicion {
    hacer_algo();
}

loop con valor de retorno

Rust tiene loop para bucles infinitos. La diferencia con while true de PHP es que loop puede retornar un valor con break:

fn main() {
    let mut intentos = 0;

    let resultado = loop {
        intentos += 1;

        if intentos == 3 {
            break intentos * 10; // retorna 30
        }
    };

    println!("Resultado tras {} intentos: {}", intentos, resultado);
}

La expresión después de break es el valor que produce el bucle. Esto permite patrones como "reintentar hasta éxito y capturar el resultado" sin variables intermedias.

Para bucles anidados, puedes etiquetar el bucle externo y hacer break desde el interno con la etiqueta:

'externo: loop {
    loop {
        break 'externo; // sale del bucle etiquetado 'externo
    }
}

while y while let

El while clásico funciona como en cualquier otro lenguaje:

fn main() {
    let mut n = 1;

    while n < 100 {
        n *= 2;
    }

    println!("Primera potencia de 2 >= 100: {}", n);
}

while let combina while con pattern matching: itera mientras el patrón encaja. Es especialmente útil para consumir valores de una pila o cola:

fn main() {
    let mut pila = vec![1, 2, 3, 4, 5];

    while let Some(tope) = pila.pop() {
        println!("{}", tope);
    }
    // Imprime: 5, 4, 3, 2, 1
    // Termina cuando pop() retorna None (pila vacía)
}

Vec::pop() retorna Option<T>: Some(valor) si hay elementos, None si está vacía. while let Some(tope) continúa el bucle mientras hay elementos y los desestructura directamente en tope.

for con iteradores y ranges

Rust no tiene el for clásico de C (for (int i = 0; i < n; i++)). Todo for en Rust itera sobre un iterador:

for i in 0..5 {
    println!("{}", i); // 0, 1, 2, 3, 4
}

for i in 0..=5 {
    println!("{}", i); // 0, 1, 2, 3, 4, 5
}

0..5 es un range excluyente (no incluye el 5). 0..=5 es un range incluyente (incluye el 5). Para iterar colecciones:

let frutas = vec!["manzana", "pera", "naranja"];

for fruta in &frutas {
    println!("{}", fruta);
}

for (indice, fruta) in frutas.iter().enumerate() {
    println!("{}: {}", indice, fruta);
}

El & en &frutas presta la colección al bucle sin moverla: el Vec sigue siendo válido después del for. Sin &, el for consumiría la colección y no podrías usarla después.

.enumerate() envuelve cada elemento en una tupla (índice, valor). La desestructuración directa en (indice, fruta) es parte del patrón for.

Iterar en reversa: usa (0..5).rev() o coleccion.iter().rev(). No hay índice decreciente en Rust; la reversa es un adaptador del iterador.

match básico

match en Rust es como switch en PHP pero con dos diferencias fundamentales: es exhaustivo (el compilador exige cubrir todos los casos posibles) y es una expresión (produce un valor).

fn clasificar(numero: i32) -> &'static str {
    match numero {
        1 => "uno",
        2 | 3 => "dos o tres",
        4..=9 => "entre cuatro y nueve",
        _ => "otro",
    }
}

El _ es el patrón catch-all, equivalente al default del switch de PHP. Si eliminas el _ y no cubres todos los i32 posibles, el compilador rechaza el código con error[E0004]: non-exhaustive patterns.

El | en 2 | 3 significa "o": el patrón encaja si el valor es 2 o 3. Los rangos también funcionan como patrones.

fn main() {
    let codigo_http = 404;

    let mensaje = match codigo_http {
        200 => "OK",
        301 | 302 => "Redirección",
        400 => "Bad Request",
        401 => "Unauthorized",
        404 => "Not Found",
        500..=599 => "Error del servidor",
        _ => "Código desconocido",
    };

    println!("{}: {}", codigo_http, mensaje);
}
match vs switch: PHP no exige que el switch cubra todos los casos, y el fall-through entre cases es implícito (requiere break). En Rust, el match exige exhaustividad y no hay fall-through: cada brazo termina en su punto.

Resumen

  • if en Rust es una expresión: puede asignarse a una variable. No existe operador ternario; el if lo reemplaza.
  • loop crea un bucle infinito que puede retornar un valor con break expresion; las etiquetas de bucle permiten salir de bucles anidados.
  • while let combina iteración con pattern matching: itera mientras el patrón encaja, muy útil para consumir Option.
  • Todo for en Rust itera sobre un iterador; los ranges 0..n y 0..=n son el sustituto del for clásico de C.
  • match es exhaustivo: el compilador exige cubrir todos los casos posibles. El _ actúa como catch-all.
