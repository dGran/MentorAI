Qué es un context manager y por qué with #

Un context manager es un objeto que encapsula la lógica de configuración y limpieza de un recurso. El bloque with garantiza que la limpieza ocurre siempre, incluso si se lanza una excepción:

python 
f = open("datos.txt", "r")
try:
    contenido = f.read()
finally:
    f.close()

with open("datos.txt", "r") as f:
    contenido = f.read()

Ambos fragmentos son equivalentes. El segundo es más corto, pero lo importante es que with no es magia: cuando Python entra en el bloque llama a __enter__, y cuando sale (con o sin excepción) llama a __exit__. Si __enter__ devuelve algo, ese valor queda disponible con as.

Cualquier objeto que implemente __enter__ y __exit__ es un context manager válido. Los ficheros (open), conexiones de red, locks de threading y mocks de unittest lo son. Puedes construir los tuyos propios con la misma interfaz.

Implementar con __enter__ y __exit__ #

__enter__ prepara el recurso y devuelve el valor que aparecerá tras as. __exit__ recibe tres argumentos sobre la excepción (tipo, valor y traceback), que son None cuando no hubo excepción. Devolver True suprime la excepción; devolver False o None la propaga.

python 
import sqlite3


class ConexionBD:
    def __init__(self, ruta: str) -> None:
        self._ruta = ruta
        self._conexion: sqlite3.Connection | None = None

    def __enter__(self) -> sqlite3.Connection:
        self._conexion = sqlite3.connect(self._ruta)
        return self._conexion

    def __exit__(self, tipo_exc, valor_exc, traceback) -> bool:
        if self._conexion is None:
            return False

        if tipo_exc is not None:
            self._conexion.rollback()
        else:
            self._conexion.commit()

        self._conexion.close()
        return False


with ConexionBD("app.db") as conn:
    conn.execute("INSERT INTO pedidos VALUES (?, ?)", (42, "pendiente"))

Si el código dentro del bloque with lanza una excepción, tipo_exc contiene la clase de esa excepción y __exit__ hace rollback antes de que se propague. Si todo va bien, hace commit. En ningún caso hay que acordarse de cerrar la conexión.

Devuelve False, no None. Python trata ambos igual (no suprimir la excepción), pero devolver False documenta la intención. Devolver True silencia la excepción y puede ocultar errores inesperados; úsalo solo cuando suprimir sea un comportamiento deliberado y esperado.

contextlib.contextmanager #

Escribir una clase entera para un context manager simple es verboso. contextlib.contextmanager convierte un generador con un único yield en un context manager funcional:

python 
from contextlib import contextmanager
import sqlite3


@contextmanager
def conexion_bd(ruta: str):
    conexion = sqlite3.connect(ruta)

    try:
        yield conexion
        conexion.commit()
    except Exception as excepcion:
        conexion.rollback()
        raise excepcion
    finally:
        conexion.close()


with conexion_bd("app.db") as conn:
    conn.execute("INSERT INTO pedidos VALUES (?, ?)", (42, "pendiente"))

El código antes del yield equivale a __enter__. El valor del yield es el que recibe as. El código después del yield, dentro del bloque try/except/finally, equivale a __exit__.

Si el bloque with lanza una excepción, Python la relanza dentro del generador en el punto del yield, activando el except. El bloque finally se ejecuta siempre, haya o no excepción.

¿Clase o generador? El generador con @contextmanager es suficiente para la mayoría de casos. Usa una clase cuando el context manager necesita mantener estado complejo entre apertura y cierre, o cuando quieres que sea verificable como tipo en anotaciones.

Casos reales #

Locks de threading. threading.Lock ya implementa el protocolo de context manager. Usarlo con with garantiza que el lock se libera aunque la sección crítica lance una excepción:

python 
import threading

_lock = threading.Lock()
_contador = 0


def incrementar() -> None:
    global _contador

    with _lock:
        _contador += 1

Mocks en tests. unittest.mock.patch como context manager parchea un símbolo únicamente durante el bloque y lo restaura al salir, sin necesidad de decoradores en el método de test:

python 
from unittest.mock import patch, MagicMock


def test_obtener_precio():
    mock_respuesta = MagicMock()
    mock_respuesta.json.return_value = {"precio": 29.99}
    mock_respuesta.status_code = 200

    with patch("servicios.precios.httpx.get", return_value=mock_respuesta):
        precio = obtener_precio("producto-42")

    assert precio == 29.99

Directorio temporal. tempfile.TemporaryDirectory crea un directorio y lo elimina con todo su contenido al salir del bloque, sin cleanup manual:

python 
import tempfile
from pathlib import Path


with tempfile.TemporaryDirectory() as directorio:
    ruta_config = Path(directorio) / "config.ini"
    ruta_config.write_text("[app]\ndebug = true\n")

    resultado = cargar_configuracion(str(ruta_config))

assert resultado["debug"] is True

Suprimir excepciones esperadas. contextlib.suppress silencia excepciones específicas, eliminando el patrón try/except/pass:

python 
from contextlib import suppress
import json


def cargar_config(ruta: str) -> dict:
    with suppress(FileNotFoundError, json.JSONDecodeError):
        with open(ruta) as fichero:
            return json.load(fichero)

    return {}

Si el fichero no existe o el JSON está malformado, cargar_config devuelve un diccionario vacío en lugar de propagar la excepción. Úsalo solo cuando suprimir esa excepción concreta sea el comportamiento correcto por diseño, no para ignorar errores inesperados.

Resumen #

Lo que te llevas

  • with garantiza que el cleanup se ejecuta aunque se lance una excepción: es la herramienta correcta para gestionar recursos que necesitan abrirse y cerrarse.
  • __enter__ prepara el recurso y expone su valor con as; __exit__ recibe la información de la excepción y libera el recurso siempre.
  • @contextmanager convierte un generador con un único yield en un context manager sin necesidad de clase; el código antes del yield es la apertura, el finally es el cierre.
  • Devolver True en __exit__ suprime la excepción; devolver False o None la propaga. La supresión debe ser explícita e intencional.
  • threading.Lock, unittest.mock.patch, tempfile.TemporaryDirectory y contextlib.suppress son context managers de la stdlib que cubren la mayoría de casos cotidianos sin necesidad de implementar los tuyos.
