Linux: scripting bash

Un script bash es un fichero de texto con comandos que el shell ejecuta en orden. Con variables, condicionales, bucles y funciones puedes automatizar cualquier tarea repetitiva del servidor.

No hace falta ser experto en bash para sacarle valor. Con lo que cabe en esta lección puedes escribir scripts de deploy, backup y mantenimiento que ahorran tiempo todos los días.

Tu primer script#

bash · hola.sh
#!/usr/bin/env bash
# La primera línea (shebang) indica qué intérprete usar.
# env bash busca bash en el PATH; más portable que #!/bin/bash.

echo "Hola, mundo"
echo "Fecha: $(date)"        # $() = sustitución de comando
bash · hacer ejecutable y correr
chmod +x hola.sh        # dar permiso de ejecución
./hola.sh               # ejecutar (el ./ es necesario si no está en el PATH)
bash hola.sh            # alternativa: pasarlo explícitamente a bash

Añade set -euo pipefail al inicio

set -e aborta el script si cualquier comando falla. set -u trata variables sin definir como errores. set -o pipefail hace que un pipeline falle si falla cualquier comando intermedio. Sin esto, un script puede continuar silenciosamente tras un error.

Variables#

bash
NOMBRE="david"              # sin espacios alrededor del =
echo $NOMBRE                # usar la variable
echo "${NOMBRE}_backup"     # llaves para evitar ambigüedad: david_backup

# Sustitución de comando:
FECHA=$(date +%Y-%m-%d)     # guarda la salida de un comando
LINEAS=$(wc -l < fichero.txt)

# Variables especiales:
$0    # nombre del script
$1, $2...  # argumentos posicionales
$#    # número de argumentos
$@    # todos los argumentos (como lista)
$?    # exit code del último comando
$$    # PID del proceso actual
$!    # PID del último proceso en background

# Valor por defecto si la variable no está definida:
ENTORNO=${ENTORNO:-production}    # usa "production" si $ENTORNO está vacía

# Leer del usuario:
read -p "Introduce el nombre: " NOMBRE
read -sp "Contraseña: " PASS     # -s oculta lo que se escribe

Condicionales#

bash · if/elif/else
#!/usr/bin/env bash
set -euo pipefail

USUARIO=$1

if [[ -z "$USUARIO" ]]; then
    echo "Error: falta el argumento usuario" >&2
    exit 1
elif [[ "$USUARIO" == "root" ]]; then
    echo "No uses root directamente"
else
    echo "Hola, ${USUARIO}"
fi
bash · condiciones más usadas
# Strings:
[[ -z "$VAR" ]]        # está vacía
[[ -n "$VAR" ]]        # no está vacía
[[ "$A" == "$B" ]]     # iguales
[[ "$A" != "$B" ]]     # distintas
[[ "$A" =~ ^[0-9]+$ ]] # coincide regex (solo en [[ ]])

# Números:
[[ $N -eq 0 ]]   # igual a 0
[[ $N -ne 0 ]]   # distinto de 0
[[ $N -lt 10 ]]  # menor que 10
[[ $N -gt 0 ]]   # mayor que 0

# Ficheros y directorios:
[[ -f "$RUTA" ]]    # existe y es fichero regular
[[ -d "$RUTA" ]]    # existe y es directorio
[[ -e "$RUTA" ]]    # existe (cualquier tipo)
[[ -r "$RUTA" ]]    # es legible
[[ -x "$RUTA" ]]    # es ejecutable
[[ -s "$RUTA" ]]    # existe y no está vacío

# Combinar:
[[ -f "$RUTA" && -r "$RUTA" ]]   # AND
[[ -z "$A" || -z "$B" ]]         # OR

Bucles#

bash · for, while, until
# for sobre lista:
for servidor in web1 web2 web3; do
    echo "Desplegando en ${servidor}..."
    ssh "${servidor}" 'sudo systemctl restart php-fpm'
done

# for sobre glob:
for fichero in /var/log/*.log; do
    echo "Procesando ${fichero}"
done

# for numérico:
for i in {1..10}; do echo "Iteración $i"; done
for ((i=0; i<10; i++)); do echo "$i"; done

# for sobre la salida de un comando:
for usuario in $(cut -d: -f1 /etc/passwd); do
    echo "$usuario"
done

# while:
INTENTOS=0
while [[ $INTENTOS -lt 3 ]]; do
    if curl -sf http://localhost/health; then
        echo "Servidor listo"
        break
    fi
    INTENTOS=$((INTENTOS + 1))
    sleep 5
done

# Leer líneas de un fichero:
while IFS= read -r linea; do
    echo "Procesando: ${linea}"
done < listado.txt

Funciones#

bash
log() {
    echo "[$(date +%H:%M:%S)] $*"
}

require_arg() {
    local nombre_param=$1
    local valor=$2
    if [[ -z "$valor" ]]; then
        echo "Error: falta el argumento ${nombre_param}" >&2
        exit 1
    fi
}

desplegar() {
    local entorno=$1
    local version=$2
    log "Desplegando versión ${version} en ${entorno}"
    # ...comandos de deploy...
}

# Llamar a la función:
log "Inicio del script"
require_arg "entorno" "$1"
desplegar "$1" "$2"

local para variables de función

Sin local, las variables de una función son globales y pueden contaminar el resto del script. Declara siempre con local dentro de funciones.

Exit codes y errores#

bash
# 0 = éxito; cualquier otro valor = error
exit 0          # termina con éxito
exit 1          # error genérico
exit 2          # uso incorrecto del comando
$?              # exit code del último comando ejecutado

# Verificar resultado:
if ! comando; then
    echo "El comando falló" >&2
    exit 1
fi

# Trap: ejecutar código al salir (limpieza)
TEMPDIR=$(mktemp -d)
trap 'rm -rf "$TEMPDIR"' EXIT    # siempre limpia, aunque el script falle

# Capturar SIGINT (Ctrl+C):
trap 'echo "Interrumpido"; exit 130' INT

Script completo de ejemplo#

bash · backup.sh
#!/usr/bin/env bash
set -euo pipefail

readonly BACKUP_DIR="/var/backups/miapp"
readonly KEEP_DAYS=7

log() { echo "[$(date '+%Y-%m-%d %H:%M:%S')] $*"; }

require_root() {
    if [[ $EUID -ne 0 ]]; then
        echo "Este script requiere root" >&2
        exit 1
    fi
}

crear_backup() {
    local fecha
    fecha=$(date +%Y-%m-%d)
    local destino="${BACKUP_DIR}/${fecha}.tar.gz"

    log "Creando backup en ${destino}"
    tar -czf "$destino" /var/www/miapp

    log "Backup completado: $(du -sh "$destino" | cut -f1)"
}

limpiar_viejos() {
    log "Eliminando backups de más de ${KEEP_DAYS} días"
    find "$BACKUP_DIR" -name "*.tar.gz" -mtime +"${KEEP_DAYS}" -delete
}

require_root
mkdir -p "$BACKUP_DIR"
crear_backup
limpiar_viejos
log "Proceso completado"

Cuándo aplicarlo#

Úsalo cuando…

  • Glue code entre herramientas del sistema: copiar, mover, comprimir, llamar a comandos externos
  • Automatización de tareas repetitivas en cualquier Unix sin instalar dependencias
  • El script es corto (menos de 50 líneas) y su lógica es lineal

No lo uses cuando…

  • La lógica es compleja o el manejo de errores es sofisticado: usa Python o PHP
  • El script supera las 50-100 líneas o necesitas tests unitarios: la mantenibilidad lo exige

Resumen#

Lo que te llevas

  • Todo script empieza con #!/usr/bin/env bash y set -euo pipefail. Sin esto el script puede continuar silenciosamente tras un error.
  • Usa [[ ]] (doble corchete) para condiciones: soporta &&, || y regex. Evita el [ ] antiguo.
  • $? es el exit code del último comando. 0 = éxito. Comprueba con if ! comando; then.
  • trap 'limpieza' EXIT garantiza que el código de limpieza se ejecuta aunque el script falle.
  • Declara las variables de función con local. Escribe los mensajes de error en stderr (>&2).
