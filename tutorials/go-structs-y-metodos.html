Structs y métodos en Go

Go no tiene clases. Tiene structs: tipos que agrupan campos, y métodos que se asocian a esos tipos. La distinción entre value receiver y pointer receiver es lo que determina si un método puede modificar el struct o solo leerlo.

Definir y crear structs

Un struct es un tipo que agrupa campos. Es el equivalente funcional de una clase PHP pero sin herencia ni encapsulación por palabras clave.

PHP

class Producto {
    public function __construct(
        private string $nombre,
        private float $precio,
        private int $stock,
    ) {}
}

$p = new Producto("Mesa", 299.99, 5);

Go

type Producto struct {
    Nombre string
    Precio float64
    Stock  int
}

p := Producto{
    Nombre: "Mesa",
    Precio: 299.99,
    Stock:  5,
}

Hay tres formas de crear un struct:

// 1. Literal con nombres de campo (recomendado: explícito y resistente a cambios)
p1 := Producto{Nombre: "Mesa", Precio: 299.99, Stock: 5}

// 2. Literal posicional (frágil: depende del orden de los campos)
p2 := Producto{"Mesa", 299.99, 5}

// 3. new: devuelve un puntero al struct con zero values
p3 := new(Producto)    // *Producto con Nombre="", Precio=0, Stock=0
p3.Nombre = "Mesa"

Campos y acceso

Los campos de un struct son accesibles con el operador punto. La visibilidad (público/privado) sigue la regla de mayúsculas de Go:

type Producto struct {
    Nombre    string    // exportado: accesible desde fuera del paquete
    Precio    float64   // exportado
    stock     int       // no exportado: privado al paquete
    categoria string    // no exportado
}

p := Producto{Nombre: "Mesa", Precio: 299.99}
fmt.Println(p.Nombre)    // "Mesa"
fmt.Println(p.Precio)    // 299.99
// fmt.Println(p.stock)  // error si estás fuera del paquete

Los structs en Go se copian por valor por defecto. Asignar un struct a otra variable crea una copia independiente:

a := Producto{Nombre: "Mesa", Precio: 299.99}
b := a           // copia
b.Precio = 399.99

fmt.Println(a.Precio)   // 299.99 (no cambia)
fmt.Println(b.Precio)   // 399.99

Métodos

Los métodos en Go son funciones con un receiver: el tipo al que pertenecen. El receiver va entre func y el nombre del método:

type Producto struct {
    Nombre string
    Precio float64
    Stock  int
}

// Método con value receiver
func (p Producto) PrecioConIVA() float64 {
    return p.Precio * 1.21
}

// Método con value receiver
func (p Producto) EstaDisponible() bool {
    return p.Stock > 0
}

p := Producto{Nombre: "Mesa", Precio: 299.99, Stock: 5}
fmt.Printf("%.2f€\n", p.PrecioConIVA())   // 362.99€
fmt.Println(p.EstaDisponible())            // true

Value receiver vs pointer receiver

Aquí está la distinción clave que todo dev PHP tiene que interiorizar:

Value receiver (p Producto)

func (p Producto) PrecioConIVA() float64 {
    return p.Precio * 1.21
    // p es una COPIA del struct
    // cualquier cambio a p aquí NO afecta al original
}

Recibe una copia. Solo puede leer. Los cambios al receiver no afectan al original.

Pointer receiver (*p Producto)

func (p *Producto) AplicarDescuento(pct float64) {
    p.Precio = p.Precio * (1 - pct/100)
    // p es un PUNTERO al struct original
    // los cambios a p.Precio afectan al original
}

Recibe un puntero. Puede leer y modificar. Los cambios al receiver sí afectan al original.

p := Producto{Nombre: "Mesa", Precio: 299.99}

p.AplicarDescuento(10)   // el compilador pasa &p automáticamente
fmt.Println(p.Precio)    // 269.99 (modificado)

El compilador es inteligente: si llamas a un método con pointer receiver sobre un valor (no un puntero), Go toma la dirección automáticamente. Pero hay un caso en el que no puede hacerlo: valores temporales no direccionables.

Regla práctica:

  • Usa pointer receiver si el método modifica el struct, o si el struct es grande (evitas copiar).
  • Usa value receiver si el método solo lee y el struct es pequeño.
  • Si un método de un tipo usa pointer receiver, lo habitual es que todos los métodos del tipo usen pointer receiver, para consistencia.

El patrón constructor en Go

Go no tiene constructores como PHP, pero la convención es una función New o NewTipo que valida y devuelve el struct (generalmente un puntero):

type Producto struct {
    nombre string
    precio float64
    stock  int
}

func NewProducto(nombre string, precio float64, stock int) (*Producto, error) {
    if precio <= 0 {
        return nil, fmt.Errorf("el precio debe ser positivo, got %f", precio)
    }

    if stock < 0 {
        return nil, fmt.Errorf("el stock no puede ser negativo")
    }

    return &Producto{nombre: nombre, precio: precio, stock: stock}, nil
}

// Getters para campos privados
func (p *Producto) Nombre() string  { return p.nombre }
func (p *Producto) Precio() float64 { return p.precio }

Structs anidados

Los structs pueden contener otros structs como campos, o usar el embedding para promover sus métodos (esto se desarrolla en la lección de composición):

type Direccion struct {
    Calle   string
    Ciudad  string
    CP      string
}

type Cliente struct {
    Nombre    string
    Email     string
    Direccion Direccion   // struct anidado
}

c := Cliente{
    Nombre: "Ana García",
    Email:  "ana@ejemplo.com",
    Direccion: Direccion{
        Calle:  "Calle Mayor 1",
        Ciudad: "Madrid",
        CP:     "28001",
    },
}

fmt.Println(c.Direccion.Ciudad)   // "Madrid"

Resumen

  • Los structs agrupan campos con nombre y tipo. Son el equivalente funcional de las clases PHP, sin herencia.
  • Visibilidad por mayúsculas: campos en mayúscula = públicos; en minúscula = privados al paquete.
  • Los métodos llevan un receiver entre func y su nombre: func (p Producto) método().
  • Value receiver recibe una copia (solo lectura del original); pointer receiver recibe la dirección (puede modificar el original).
  • Regla: usa pointer receiver si el método modifica el struct o el struct es grande.
  • El patrón constructor es una función NewTipo() que valida y devuelve un puntero al struct.
