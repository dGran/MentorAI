cargo new: crea el proyecto #

Cargo es la herramienta de build, gestión de dependencias y publicación de Rust. Es equivalente a Composer en PHP o go mod en Go, pero integra también el build system completo. Para crear un proyecto nuevo:

bash 
cargo new hola-mundo
cd hola-mundo

Cargo genera esta estructura:

bash 
hola-mundo/
├── Cargo.toml
├── .gitignore
└── src/
    └── main.rs

El .gitignore incluye /target por defecto. El directorio target/ es donde Cargo deposita los artefactos compilados y puede pesar varios gigabytes en proyectos grandes.

Para crear una librería en lugar de un binario, usa cargo new --lib nombre. Las librerías tienen src/lib.rs como punto de entrada en lugar de src/main.rs.

Cargo.toml #

El Cargo.toml generado por defecto:

rust 
[package]
name = "hola-mundo"
version = "0.1.0"
edition = "2021"

[dependencies]

Los campos más relevantes:

  • name: el nombre del crate. En binarios, es también el nombre del ejecutable generado.
  • version: sigue semver estricto.
  • edition: la edición del lenguaje. Usa siempre 2021. Las ediciones no rompen compatibilidad entre crates: un crate en edición 2021 puede depender de uno en edición 2018 sin problema.

Para añadir dependencias, edita la sección [dependencies] o usa cargo add:

bash 
cargo add serde --features derive

Esto añade la línea al Cargo.toml y actualiza el Cargo.lock con las versiones exactas resueltas. El Cargo.lock es equivalente al composer.lock de PHP: fija las versiones exactas para reproducibilidad.

Anatomía de main.rs #

El src/main.rs generado:

rust 
fn main() {
    println!("Hello, world!");
}

Punto a punto:

  • fn main(): el punto de entrada del programa. Sin paréntesis de tipo de retorno porque retorna () (unit, el tipo vacío de Rust). Si necesitas retornar un código de error, puedes declararlo como fn main() -> Result<(), Box<dyn Error>>.
  • println!: es una macro, no una función. El ! al final lo indica. Las macros en Rust se expanden en tiempo de compilación. println! acepta un string de formato similar a printf: println!("{} tiene {} años", nombre, edad).
  • El punto y coma: en Rust, las sentencias terminan con ;. Las expresiones sin ; son el valor de retorno del bloque. Esta distinción es fundamental y la veremos en profundidad al hablar de funciones.

Rust no tiene return implícito en main: la función main no retorna nada por defecto. El programa termina al llegar al final de main con código de salida 0. Para salir con un código distinto, usa std::process::exit(1).

cargo build, run y check #

Rust distingue tres comandos que la mayoría confunde al principio:

ComandoQué haceCuándo usarlo
cargo checkCompila sin generar binario. Solo verifica tipos y errores.Durante el desarrollo. Es 3-5x más rápido que build.
cargo buildCompila y genera el binario en target/debug/.Cuando necesitas ejecutar el binario manualmente.
cargo runCompila y ejecuta inmediatamente.El comando habitual durante el desarrollo.
cargo build --releaseCompila con optimizaciones completas en target/release/.Para producción o benchmarks.

La compilación en modo debug incluye información de depuración y comprobaciones de overflow aritméticos. En modo release, estas comprobaciones desaparecen y el compilador aplica todas las optimizaciones LLVM. El binario en release puede ser entre 2x y 10x más rápido que en debug.

bash 
cargo run
# Compiling hola-mundo v0.1.0 (/app)
#  Finished dev [unoptimized + debuginfo] target(s) in 0.42s
#   Running `target/debug/hola-mundo`
# Hello, world!

El primer error del compilador #

El compilador de Rust tiene los mensajes de error más claros de cualquier lenguaje compilado. Para experimentarlo, introduce un error a propósito:

rust 
fn main() {
    let x = 5;
    println!("{}", y);
}
bash 
error[E0425]: cannot find value `y` in this scope
 --> src/main.rs:3:20
  |
3 |     println!("{}", y);
  |                    ^ not found in this scope

El compilador indica el código de error (E0425), el fichero y línea exactos, y señala con ^ el token problemático. Para muchos errores, también propone la corrección.

Prueba con una variable no usada:

rust 
fn main() {
    let x = 5;
}
bash 
warning: unused variable: `x`
 --> src/main.rs:2:9
  |
2 |     let x = 5;
  |         ^ help: if this is intentional, prefix it with an underscore: `_x`

Rust trata las variables no usadas como warning, no error, pero el compilador ya te dice exactamente cómo suprimirlo: prefija con _ si es intencional.

Cuando el error sea confuso: ejecuta rustc --explain E0425 (o el código del error que aparezca). El compilador muestra una explicación detallada con ejemplos del error y cómo corregirlo.

cargo doc --open #

Cargo puede generar y abrir la documentación de todas tus dependencias en el navegador:

bash 
cargo doc --open

Esto compila la documentación en formato HTML de tu crate y todas sus dependencias, y abre el resultado en el navegador. La documentación de la stdlib de Rust también está disponible offline en el mismo formato.

La convención de Rust es documentar con /// (doc comments) antes de cada función pública. Estos comentarios soportan Markdown y aparecen en la documentación generada:

rust 
/// Calcula el factorial de `n`.
///
/// # Panics
///
/// Entra en pánico si `n` es mayor que 20.
pub fn factorial(n: u64) -> u64 {
    (1..=n).product()
}

Resumen #

Lo que te llevas

  • cargo new crea la estructura completa del proyecto: Cargo.toml, src/main.rs y .gitignore con target/ excluido.
  • El Cargo.toml declara nombre, versión y edition; el Cargo.lock fija las versiones exactas de dependencias.
  • cargo check es el comando más rápido durante el desarrollo: solo verifica errores sin generar binario.
  • cargo build --release activa todas las optimizaciones; el binario puede ser 2-10x más rápido que el de debug.
  • El compilador de Rust tiene los mensajes de error más claros del ecosistema: línea exacta, señalamiento del token y sugerencia de corrección.
  • cargo doc --open genera y abre offline la documentación de todas las dependencias del proyecto.
