Entorno Rust con Docker

Montar un entorno de desarrollo Rust completamente dockerizado: imagen oficial, volumen para las fuentes, caché de dependencias de Cargo y acceso desde el editor del host.

Por qué dockerizar el entorno

Rust instala con rustup y los toolchains cambian entre proyectos (stable, nightly, versiones concretas). Con Docker, el toolchain vive en la imagen y cada proyecto lleva el suyo sin conflictos. Mismo principio que el curso de Go: el host solo necesita Docker y un editor.

Estructura del proyecto

mi-proyecto/
├── src/
│   └── main.rs
├── Cargo.toml
├── Dockerfile.dev
└── compose.yml

Cargo gestiona las dependencias en Cargo.toml (equivalente a composer.json) y genera Cargo.lock con versiones exactas.

El Dockerfile de desarrollo

FROM rust:1.79-slim

WORKDIR /app

RUN apt-get update && apt-get install -y \
    pkg-config \
    libssl-dev \
    && rm -rf /var/lib/apt/lists/*

ENV CARGO_HOME=/cargo-cache
ENV PATH="$CARGO_HOME/bin:$PATH"

CMD ["cargo", "watch", "-x", "run"]

La imagen oficial rust:1.79-slim incluye rustc, cargo y rustup. La variable CARGO_HOME mueve el caché fuera del contenedor (lo explicamos abajo).

Para desarrollo activo, cargo-watch recarga al guardar igual que nodemon:

RUN cargo install cargo-watch

Docker Compose

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile.dev
    volumes:
      - .:/app
      - cargo-cache:/cargo-cache
    ports:
      - "3000:3000"
    environment:
      - RUST_LOG=debug

volumes:
  cargo-cache:

El volumen .:/app monta el código fuente del host dentro del contenedor, igual que en PHP/Go. Los cambios en el editor son inmediatos para cargo-watch.

Caché de dependencias

Este es el punto más importante para no perder tiempo. Cargo descarga y compila dependencias la primera vez; si el volumen cargo-cache no existe, cada docker compose up recompila todo desde cero (puede tardar varios minutos).

El volumen nombrado cargo-cache persiste el directorio CARGO_HOME entre arranques. También conviene cachear el directorio target/:

volumes:
  - .:/app
  - cargo-cache:/cargo-cache
  - target-cache:/app/target   # compila incremental entre sesiones
Sin este caché, una sesión nueva descarga e compila todas las dependencias de cero. Con él, solo recompila lo que cambió.

Flujo de trabajo diario

# Primera vez o tras cambiar Dockerfile
docker compose build

# Arrancar el entorno
docker compose up

# Entrar al contenedor para comandos cargo
docker compose exec app bash

# Añadir una dependencia
docker compose exec app cargo add tokio --features full

# Ejecutar tests
docker compose exec app cargo test

# Ver logs del compilador en vivo (cargo-watch lo hace solo)
# Guardar cualquier .rs → cargo recompila y relanza
cargo add es el equivalente a composer require: añade la crate al Cargo.toml y actualiza el lock. Disponible desde Rust 1.62.

Resumen

  • La imagen oficial rust:VERSION-slim incluye todo el toolchain; no hace falta instalar nada en el host.
  • El volumen del código (.:/app) da acceso inmediato desde el editor del host.
  • El volumen cargo-cache sobre CARGO_HOME es crítico: sin él, cada sesión recompila todas las dependencias.
  • cargo-watch -x run relanza el servidor al guardar, igual que nodemon en Node.
  • El directorio target/ en un volumen propio acelera la compilación incremental entre sesiones.
