HTTP sin framework: net/http

En PHP necesitas Apache, Nginx o el servidor embebido de PHP para servir HTTP. En Go, net/http es production-ready y va incluido en la stdlib. Un servidor que maneja peticiones concurrentes desde el primer go run, sin instalar nada.

En PHP, el servidor web y el lenguaje son piezas separadas: Nginx recibe, PHP-FPM ejecuta y Laravel o Symfony enrutan. En Go todo eso es tu binario, y la stdlib trae lo necesario para levantar una API seria. Entender net/http por dentro es lo que te deja decidir con criterio si necesitas un framework o no.

Servidor básico #

El servidor HTTP más simple posible en Go: 10 líneas, cero dependencias:

go 
package main

import (
    "fmt"
    "net/http"
)

func main() {
    http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintln(w, "Hola, mundo")
    })

    http.ListenAndServe(":8080", nil)
}

Cada petición es manejada por una goroutine separada, de forma transparente. El servidor es concurrente por defecto: no necesitas configurar nada.

La interfaz http.Handler #

Toda la maquinaria de net/http gira en torno a una interfaz de un solo método:

go 
type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}

Cualquier tipo con ese método puede ser un handler HTTP. Esto es la implementación de interfaces implícitas aplicada al servidor web. HandlerFunc es un adaptador que convierte una función ordinaria en un Handler:

go 
// http.HandlerFunc es simplemente:
type HandlerFunc func(ResponseWriter, *Request)
func (f HandlerFunc) ServeHTTP(w ResponseWriter, r *Request) { f(w, r) }

// Por eso http.HandleFunc acepta funciones directamente:
http.HandleFunc("/productos", listarProductos)

Los objetos más útiles del handler:

go 
func miHandler(w http.ResponseWriter, r *http.Request) {
    // Request: datos de la petición
    fmt.Println(r.Method)          // GET, POST, etc.
    fmt.Println(r.URL.Path)        // /productos/42
    fmt.Println(r.Header.Get("Authorization"))
    r.ParseForm()
    fmt.Println(r.FormValue("nombre"))

    // ResponseWriter: construir la respuesta
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusCreated)   // 201 (siempre antes de Write)
    w.Write([]byte(`{"id": 42}`))
}

ServeMux: el router de Go 1.22+ #

Go 1.22 mejoró significativamente el ServeMux incorporando rutas con patrones de método y parámetros de path:

go 
mux := http.NewServeMux()

// Método + ruta: "GET /productos" — solo responde a GET
mux.HandleFunc("GET /productos", listarProductos)
mux.HandleFunc("POST /productos", crearProducto)

// Parámetros de path con {nombre}: accesible con r.PathValue
mux.HandleFunc("GET /productos/{id}", func(w http.ResponseWriter, r *http.Request) {
    id := r.PathValue("id")
    fmt.Fprintf(w, "producto: %s", id)
})

// Comodín al final
mux.HandleFunc("/archivos/", servirArchivos)

http.ListenAndServe(":8080", mux)

Middleware #

El patrón de middleware en Go es elegante: una función que recibe un Handler y devuelve otro Handler. Los middlewares se encadenan envolviendo los handlers:

go 
func logger(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()

        next.ServeHTTP(w, r)   // llama al handler envuelto

        fmt.Printf("%s %s — %v\n", r.Method, r.URL.Path, time.Since(start))
    })
}

func autenticar(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        token := r.Header.Get("Authorization")

        if !esTokenValido(token) {
            http.Error(w, "no autorizado", http.StatusUnauthorized)
            return
        }

        next.ServeHTTP(w, r)
    })
}

// Encadenar middlewares:
handler := logger(autenticar(mux))
http.ListenAndServe(":8080", handler)

Timeouts de servidor #

El servidor por defecto de http.ListenAndServe no tiene timeouts: un cliente lento puede bloquear una goroutine indefinidamente. En producción, siempre configura timeouts:

go 
servidor := &http.Server{
    Addr:         ":8080",
    Handler:      handler,
    ReadTimeout:  5 * time.Second,   // leer la petición completa
    WriteTimeout: 10 * time.Second,  // escribir la respuesta
    IdleTimeout:  120 * time.Second, // conexiones keep-alive inactivas
}

servidor.ListenAndServe()

Apagado graceful (espera a que las peticiones activas terminen):

go 
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
defer stop()

go servidor.ListenAndServe()

<-ctx.Done()   // espera Ctrl+C o SIGTERM

shutdownCtx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()

servidor.Shutdown(shutdownCtx)

El cliente HTTP #

El cliente HTTP también va en la stdlib, con soporte nativo para contextos y timeouts:

go 
// Nunca uses http.DefaultClient en producción: no tiene timeout
// Define siempre tu propio cliente:
cliente := &http.Client{Timeout: 10 * time.Second}

ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()

req, err := http.NewRequestWithContext(ctx, http.MethodGet, "https://api.ejemplo.com/datos", nil)

if err != nil {
    return fmt.Errorf("crear petición: %w", err)
}

req.Header.Set("Authorization", "Bearer "+token)

resp, err := cliente.Do(req)

if err != nil {
    return fmt.Errorf("petición fallida: %w", err)
}

defer resp.Body.Close()

if resp.StatusCode != http.StatusOK {
    return fmt.Errorf("respuesta inesperada: %d", resp.StatusCode)
}

// Leer el cuerpo
cuerpo, err := io.ReadAll(resp.Body)

Errores típicos al pasar de PHP a net/http

  • Guardar estado de la petición en variables globales. En PHP cada petición empieza de cero; aquí los handlers corren a la vez en el mismo proceso. Un mapa global escrito desde un handler es una race condition. Lo que es de la petición vive en variables locales o en r.Context().
  • Llamar a w.Header().Set después de escribir. El primer Write o WriteHeader envía las cabeceras; lo que pongas después se ignora en silencio. Orden: cabeceras, código de estado y cuerpo.
  • No cerrar resp.Body en el cliente. Sin defer resp.Body.Close(), la conexión no vuelve al pool y bajo carga te quedas sin sockets. Ciérralo aunque el código de estado sea un error.
  • Ignorar el error de ListenAndServe. Si el puerto está ocupado, devuelve el error al instante y el programa termina sin decir por qué. Compruébalo, ignorando solo http.ErrServerClosed, que es el apagado normal.

Cuándo aplicarlo #

Basta con net/http cuando…

  • Haces una API REST o un servicio interno: desde Go 1.22 el ServeMux enruta por método y parámetros de path
  • Quieres pocas dependencias y saber qué pasa en cada petición
  • Tu middleware es lo habitual: logs, autenticación, recuperación de pánicos, CORS

Plantéate otra pieza cuando…

  • Necesitas validación de entrada, binding o documentación OpenAPI generada: un router ligero como chi o un generador de código te ahorra repetición
  • El equipo ya trabaja con un framework y su ecosistema de middleware
  • Tienes que servir TLS con certificados automáticos o hacer balanceo: un proxy delante (Nginx, Caddy, el balanceador de tu plataforma) sigue teniendo sentido

El criterio: empieza con la stdlib y añade una librería solo cuando repitas el mismo código en varios handlers. Como los routers populares de Go usan la interfaz http.Handler, cambiar después no obliga a reescribir los handlers. Lo que no es opcional, uses lo que uses, son los timeouts del servidor y del cliente.

Resumen #

Lo que te llevas

  • net/http es un servidor HTTP production-ready incluido en la stdlib. Cada petición se maneja en su propia goroutine automáticamente.
  • La interfaz central es http.Handler con el método ServeHTTP(w, r). HandlerFunc adapta funciones a esa interfaz.
  • Go 1.22+: ServeMux soporta métodos ("GET /ruta") y parámetros de path ({id}), accesibles con r.PathValue.
  • El patrón de middleware es una función func(Handler) Handler que envuelve el handler original.
  • Configura siempre ReadTimeout, WriteTimeout e IdleTimeout en el servidor. Usa Shutdown para apagado graceful.
  • Define tu propio http.Client con timeout; nunca uses http.DefaultClient en producción.
