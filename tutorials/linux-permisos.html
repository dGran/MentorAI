Linux: permisos y propiedad

El modelo rwx de Linux define quién puede leer, escribir y ejecutar cada fichero. Entenderlo evita los dos errores más comunes en servidores: dejar todo con 777 o quedarse bloqueado sin saber por qué.

Los permisos de Linux parecen crípticos al principio, pero el sistema es sencillo y elegante. Una vez lo internalizas, leer rwxr-xr-x es tan inmediato como leer texto.

El modelo de permisos#

Cada fichero tiene tres conjuntos de permisos y cada conjunto tiene tres bits:

bash · anatomía de los permisos
 -  rwx  r-x  r--
 │   │    │    └── others (resto del mundo): solo lectura
 │   │    └── group (grupo propietario): lectura y ejecución
 │   └── user/owner (propietario): lectura, escritura y ejecución
 └── tipo de fichero (- fichero, d directorio, l symlink...)
BitEn ficheroEn directorio
r (read, 4)Leer el contenidoListar con ls
w (write, 2)Modificar o borrar el contenidoCrear, renombrar y borrar ficheros dentro
x (execute, 1)Ejecutar como programaEntrar con cd y acceder a su contenido
-Sin permiso

x en directorios es especial

Para acceder a un fichero dentro de un directorio necesitas x en ese directorio aunque tengas r en el fichero. r sin x en un directorio permite listar los nombres pero no acceder a los ficheros. En la práctica, casi siempre van juntos (rx).

Leer los permisos#

bash · ejemplos reales
-rw-r--r-- david www-data  config.php   # owner rw, group r, others r
-rwxr-xr-x root  root      /bin/ls      # owner rwx, group rx, others rx
drwxr-x--- david www-data  storage/     # directorio; others sin acceso
-rw------- root  root      /etc/shadow  # solo root puede leer

Cambiar permisos: chmod#

chmod acepta dos formas: octal (más rápido) y simbólico (más legible para cambios parciales).

bash · notación octal
# Cada dígito octal = suma de bits activos (r=4, w=2, x=1)
# 7 = 4+2+1 = rwx
# 6 = 4+2   = rw-
# 5 = 4+1   = r-x
# 4 = 4     = r--
# 0 = 0     = ---

chmod 644 config.php     # rw-r--r-- (ficheros de configuración)
chmod 755 script.sh      # rwxr-xr-x (scripts ejecutables, directorios)
chmod 600 .env           # rw------- (solo el propietario; ficheros secretos)
chmod 700 ~/.ssh         # rwx------ (directorio SSH privado)
chmod -R 755 public/     # -R recursivo: aplica a todo el árbol
bash · notación simbólica
# [u=user/g=group/o=others/a=all] [+/-/=] [r/w/x]
chmod +x script.sh        # añade x a todos (owner, group, others)
chmod u+x script.sh       # añade x solo al owner
chmod g-w fichero.txt     # quita w al grupo
chmod o= fichero.txt      # quita todos los permisos a others
chmod u=rw,g=r,o= .env    # asigna exactamente (= reemplaza)

Permisos típicos para un servidor web PHP

Los ficheros PHP son leídos por php-fpm (corre como www-data): 644 (rw-r--r--) para ficheros, 755 (rwxr-xr-x) para directorios. El directorio de uploads necesita escritura del grupo: 775. Nunca 777: cualquier usuario del sistema podría escribir.

Cambiar propietario: chown#

bash
chown david fichero.txt           # cambia solo el propietario
chown david:www-data fichero.txt  # propietario y grupo
chown :www-data fichero.txt       # solo el grupo (equivalente a chgrp)
chown -R www-data:www-data /var/www/html   # recursivo

# Caso típico: después de desplegar código como root, ajustar para php-fpm:
chown -R www-data:www-data /var/www/miapp
find /var/www/miapp -type f -exec chmod 644 {} \;
find /var/www/miapp -type d -exec chmod 755 {} \;

Permisos por defecto: umask#

Cuando creas un fichero o directorio, los permisos iniciales no son 666/777 directamente: el kernel aplica una máscara (umask) que quita bits. La umask habitual es 022.

bash
# Con umask 022:
# fichero: 666 - 022 = 644 (rw-r--r--)
# directorio: 777 - 022 = 755 (rwxr-xr-x)

umask            # muestra la umask actual
umask 022        # la cambia para la sesión actual
umask 027        # más restrictiva: group sin w, others sin nada (rw-r-----)

# La umask por defecto se configura en /etc/profile o ~/.bashrc

Bits especiales#

BitOctalEfecto en ficherosEfecto en directorios
setuid (s en user)4xxxSe ejecuta con los permisos del propietario del fichero, no del que lo lanza. Ejemplo: /usr/bin/passwd (necesita tocar /etc/shadow).Sin efecto en Linux.
setgid (s en group)2xxxSe ejecuta con los permisos del grupo del fichero.Los ficheros creados dentro heredan el grupo del directorio (útil para carpetas compartidas).
sticky (t en others)1xxxSin efecto moderno.Solo el propietario puede borrar sus ficheros aunque others tenga w. Clásico en /tmp.
bash · bits especiales en la práctica
ls -la /usr/bin/passwd     # -rwsr-xr-x (s = setuid activo)
ls -la /tmp                # drwxrwxrwt (t = sticky activo)

# Carpeta compartida con setgid (los nuevos ficheros heredan el grupo):
mkdir /var/uploads
chown :www-data /var/uploads
chmod 2775 /var/uploads    # 2 = setgid; 775 = rwxrwxr-x

Cuándo aplicarlo#

Úsalo cuando…

  • Archivo contiene credenciales o claves API: usa permisos 600 (solo el propietario puede leer)
  • Directorio accesible por el servidor web o proceso de deploy: usa 755
  • Varios usuarios del equipo necesitan acceso al mismo recurso: crea un grupo (ej. deploy) y asigna los permisos al grupo

No lo uses cuando…

  • Nunca uses 777 en producción: cualquier proceso del sistema puede leer, escribir y ejecutar el fichero
  • No des permisos de escritura globales: abre la puerta a modificaciones no autorizadas

Resumen#

Lo que te llevas

  • Los permisos son tres tríos rwx: owner, group, others. Cada bit tiene valor numérico: r=4, w=2, x=1.
  • chmod 644 para ficheros de texto, 755 para directorios y ejecutables, 600 para secretos. Nunca 777.
  • La notación simbólica (chmod +x, chmod g-w) es más legible para cambios parciales; la octal es más rápida para asignar desde cero.
  • chown -R www-data:www-data /var/www es el ajuste habitual tras desplegar código.
  • La umask (022 por defecto) define los permisos iniciales al crear ficheros: 666-022=644, 777-022=755.
  • El sticky bit en /tmp protege los ficheros de cada usuario aunque todos tengan permisos de escritura en el directorio.
