Qué son los decoradores

Un decorador es una función que recibe una función y devuelve otra función (o el mismo objeto modificado). La sintaxis @decorador es azúcar sintáctico de función = decorador(función):

def mi_decorador(funcion):
    def wrapper(*args, **kwargs):
        print("Antes de la función")
        resultado = funcion(*args, **kwargs)
        print("Después de la función")
        return resultado
    return wrapper


@mi_decorador
def saludar(nombre: str) -> str:
    return f"Hola, {nombre}!"


saludar("Ana")
# Antes de la función
# Después de la función

La línea @mi_decorador equivale exactamente a escribir saludar = mi_decorador(saludar) después de definir la función. Esto ocurre en tiempo de definición, no en tiempo de llamada.

Ya usas decoradores sin saberlo: @app.get("/users") en FastAPI, @pytest.fixture, @dataclass, @property. Todos son funciones que transforman lo que se les pasa.

Decorador básico y functools.wraps

import functools
import time


def medir_tiempo(funcion):
    @functools.wraps(funcion)
    def wrapper(*args, **kwargs):
        inicio = time.perf_counter()
        resultado = funcion(*args, **kwargs)
        duracion = time.perf_counter() - inicio
        print(f"{funcion.__name__} tardó {duracion:.4f}s")
        return resultado
    return wrapper


@medir_tiempo
def procesar_datos(n: int) -> list[int]:
    return [i ** 2 for i in range(n)]


print(procesar_datos.__name__)  # 'procesar_datos' (gracias a @wraps)
print(procesar_datos.__doc__)   # el docstring original

@functools.wraps(funcion) es crítico: copia __name__, __doc__, __annotations__ y otros atributos de la función original al wrapper. Sin él, procesar_datos.__name__ devolvería 'wrapper', rompiendo debugging, logging e introspección.

Decoradores con argumentos

Un decorador con argumentos necesita tres niveles de anidación: el nivel exterior recibe los argumentos del decorador, el intermedio recibe la función, el interior la llama:

import functools
import time


def reintentar(max_intentos: int = 3, pausa: float = 1.0):
    def decorador(funcion):
        @functools.wraps(funcion)
        def wrapper(*args, **kwargs):
            ultimo_error: Exception | None = None

            for intento in range(max_intentos):
                try:
                    return funcion(*args, **kwargs)
                except Exception as error:
                    ultimo_error = error

                    if intento < max_intentos - 1:
                        time.sleep(pausa)

            raise ultimo_error

        return wrapper
    return decorador


@reintentar(max_intentos=5, pausa=0.5)
def llamar_api(url: str) -> dict:
    import httpx
    respuesta = httpx.get(url, timeout=5.0)
    respuesta.raise_for_status()
    return respuesta.json()

La estructura es: reintentar(max_intentos=5) devuelve decorador, que se aplica a llamar_api y devuelve wrapper. Desde el punto de vista del caller, llamar_api se llama igual que antes pero con reintentos automáticos.

Clases como decoradores

Una clase puede actuar como decorador si implementa __call__. Es útil cuando el decorador necesita mantener estado entre llamadas:

import functools


class LimitarLlamadas:
    def __init__(self, limite: int) -> None:
        self._limite = limite
        self._contador = 0

    def __call__(self, funcion):
        @functools.wraps(funcion)
        def wrapper(*args, **kwargs):
            self._contador += 1

            if self._contador > self._limite:
                raise RuntimeError(
                    f"{funcion.__name__} excedió el límite de {self._limite} llamadas"
                )
            return funcion(*args, **kwargs)
        return wrapper


@LimitarLlamadas(limite=3)
def operacion_cara() -> str:
    return "resultado"


operacion_cara()  # OK
operacion_cara()  # OK
operacion_cara()  # OK
operacion_cara()  # RuntimeError

La clase es útil cuando necesitas que el decorador recuerde algo entre llamadas (contador, caché, tiempo de última ejecución). Para decoradores stateless, una función anidada es más simple.

Decoradores que ya conoces

Los decoradores que usarás diariamente en un proyecto FastAPI:

from fastapi import FastAPI, Depends
import pytest
from dataclasses import dataclass
from functools import cache


app = FastAPI()


@app.get("/usuarios/{usuario_id}")
async def obtener_usuario(usuario_id: int):
    return {"id": usuario_id}


@pytest.fixture
def cliente_http():
    import httpx
    return httpx.Client(base_url="http://localhost:8000")


@dataclass
class Punto:
    x: float
    y: float


class Temperatura:
    def __init__(self, celsius: float) -> None:
        self._celsius = celsius

    @property
    def fahrenheit(self) -> float:
        return self._celsius * 9 / 5 + 32

    @classmethod
    def desde_fahrenheit(cls, fahrenheit: float) -> "Temperatura":
        return cls((fahrenheit - 32) * 5 / 9)


@cache
def fibonacci(n: int) -> int:
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
@cache de functools: memoiza los resultados de la función por los argumentos. La primera llamada con un conjunto de argumentos ejecuta la función; las siguientes la devuelven del cache. Para fibonacci(40), la diferencia es de segundos a microsegundos.

Resumen

  • @decorador es azúcar sintáctico de función = decorador(función); ocurre en tiempo de definición, no de llamada.
  • @functools.wraps(funcion) es obligatorio en cualquier decorador que escribas: preserva el nombre, docstring y anotaciones de la función original.
  • Los decoradores con argumentos necesitan tres niveles: función que recibe los args → función que recibe la función → función wrapper.
  • Las clases como decoradores son útiles cuando necesitas estado entre llamadas (contador, caché, timestamps).
  • @app.get, @pytest.fixture, @dataclass, @property, @cache: todos son decoradores aplicando el mismo patrón.
